Mower 一条龙入门说明

本说明更新于 2026-10-10，按首次运行顺序介绍部署、连接、排班和任务配置。已有用户可从左侧目录查找对应功能。

先让设备连接和普通轮休稳定，再逐项添加自动化。遇到校验失败或任务等待时，先读具体原因，不以反复启动代替修正配置。

  1. 部署并确认版本：源码部署或从项目 Releases 获取完整包，确认平台依赖。
  2. 绑定设备与选择性能档位：检测实例、明确选择，再测试连接；性能通常保留自动。
  3. 导入或编写排班：核对设施、干员、替班、宿舍与校验结果。
  4. 配置基建与日常：只开启需要的任务，先观察一轮下班和回班。
  5. 配置 MAA 与作战：区分刷理智周计划与独立大型任务。
  6. 安排养成与专精：同步练度和库存，再准备材料及训练路线。
  7. 导出完整备份：保存配置和持久化业务数据，迁移或重要修改前重新导出。

出现问题时，按日志与 AI 排错步骤整理证据，再通过反馈入口求助。

安装、软件更新与资源更新

优先按部署方式选择安装步骤

macOS 和 Linux 虽有独立包，仍建议优先使用源码部署。Windows、Linux、macOS 的环境、前端构建及启动命令统一放在项目主页 README；本地打包和 Docker 的 Markdown 链接也在 README 中。

首次使用独立包

  1. 从项目主页的 Releases获取适合系统、架构的完整包，核对发布说明与 SHA256SUMS。
  2. Windows 解压完整目录后运行主程序；Linux 解压后检查宿主系统库；macOS 将应用移出 DMG，放到可写位置再运行。
  3. 当前后续发行提供 Windows x64、Linux x64/ARM64 和 macOS ARM64 独立包，不再构建 macOS x64 包；Intel Mac 使用源码部署。Android 的程序更新 ZIP 供已有宿主导入，不是 APK。
  4. Windows 与 macOS 包没有平台发行签名。确认下载来源后按系统提示处理；Linux 缺少 GTK/WebKit2 时按启动提示安装依赖。

不再使用独立 Mower 下载器。手动下载入口仍是主项目 Releases，内置更新所用发布索引由程序管理。

已有安装：使用内置更新

  1. 打开 Mower 设置 → 软件更新，核对当前版本、部署方式及渠道，再检查更新。
  2. 正式版、公测版和开发版的可用目标随平台与部署方式变化，以页面结果为准。源码开发版跟随所选分支；独立包没有可用目标时不要跨平台强装。
  3. 更新会重启同一安装目录下的运行实例并恢复原运行状态；后台静默重启控制是否重新打开窗口。
  4. 独立包可在“手动应用”上传匹配的 Release 包；源码部署使用在线源码更新或源码版本管理，不上传独立包。强制源码更新会覆盖本地修改，先自行保存。

三类更新分别处理

内容入口与生效方式
Mower 程序Mower 设置 → 软件更新，安装后重启相关实例。
Mower 识别等资源Mower 设置 → 资源更新；同一安装共享，在任务间歇加载，通常无需重启程序。
MAA 本体与资源MAA 设置中分别更新；MAA 正在执行任务或测试连接时，等待其释放后操作。

下载失败先检查“网络与下载代理”并运行下载测试。文件下载代理、GitHub API 与 Git 的网络路径不同；提供具体失败步骤和日志。

设备连接与性能适配

先选预设，再选实例

  1. 进入 Mower 设置的设备连接区域，选择与当前系统和模拟器对应的预设。
  2. 按字段帮助填写必要路径，使用“检测实例”或页面支持的“启动并检测”。多个实例时明确选择目标，不使用另一台在线设备代替。
  3. 核对检测到的身份、实例及游戏包，执行连接测试。实例选择先保存，ADB 地址和游戏包在验证通过后保存；连接失败不会撤销已选实例。
  4. 检查游戏区服、横屏尺寸与连接状态。路径和端口以当前预设检测结果为准，不照抄旧教程的固定端口、多开编号或 shell 文件夹。

检测、只读测试与启动的区别

“测试连接（只读）”不会启动或重启模拟器。只有具备启停能力的预设提供相应操作；实例绑定和能力提示决定当前能执行什么。连接失败时先按状态提示区分未运行、离线、未就绪和身份不符，再选择修复动作。

截图、触控与实体设备

优先使用预设支持的截图和触控组合。MuMu IPC 截图与触控存在配套要求；切换方案前核对说明，不把所有识别或连接错误都改成 ADB+Gzip。

其他模拟器或实体设备在高级设置中明确填写目标 serial，再测试连接。实体设备默认检查横屏 1920×1080；页面提供的临时整备只对本次运行授权，结束后按恢复规则还原。macOS 源码部署需按 README 准备 ADB，Linux 使用配置的路径或系统 adb。

性能档位如何选择

“设备性能适配”位于 Mower 设置的设备连接区域。首次运行通常保留“自动”。自动档根据选人操作后的画面反馈和连续失败情况调整，桌面端从极高开始，Android 从中开始；Android 也可手动选高或极高，自动档可按反馈升档。手动选定的档位不会因为重载配置改回中档。

档位选人策略
极高连续点击重排，适合能及时响应输入的设备。
高缩短清空和翻页等待，操作完成后统一校验。
中等待稳定画面后继续操作。
低多确认一帧，优先处理响应较慢的情况。

连接测试显示的 CPU 核数和内存总量仅是目标设备的资源信息，不据此推荐档位，也不是帧率测试；信息读取失败不等于连接失败。截图间隔、选人采样间隔和页面切换超时独立设置，切换档位不会替你修改这些数值。先保留默认值，有明确日志依据再调整。

桌面端游戏内性能测试

  1. 停止 Mower 自动任务，等待 MAA 测试、更新及其他设备操作结束。核对并保存设备设置，先测试连接。
  2. 点击“游戏内性能测试”。程序按所选实例的启动能力连接设备、启动游戏并进入基建，再进入宿舍一；不支持自动启动的设备需先手动启动。登录验证、协议确认或尚未确认的既有换人操作，需手动处理后重试。
  3. 测试从极高档开始。每次先清空暂选、复位列表并连续滑动三次，再选人、重排并核验实际名单。每档须连续三次完整选人通过；一次选人失败立即降一档重新计数，低档失败不给出建议。导航、准备或设备故障直接中止，先排查具体错误。
  4. 进度下方可查看本次游戏画面并点击放大。测试期间不要操作游戏，可随时点击“取消测试”；取消后等待退出选人页。测试没有总时限，不用等待固定倒计时。
  5. 完成后核对“实测建议”，点击“采用建议”才保存该档位。结果只适用于本次设备和截图、采样及页面切换时间参数；修改这些设置后重新测试。

测试会操作游戏并临时选人，结束或取消时放弃暂选，不确认换人。若设备断开或程序退出导致清理未完成，按提示在游戏中返回并放弃换人，再开始自动任务。测试不修改排班和独立时间参数；采用建议后使用手动档位，需要自动调整时再选回“自动”。

滑动、选人或重排失败时

先核对绑定实例、截图与触控后端，再记录失败档位、轮次、实际画面及日志。当前选人翻页会在滑动终点按住期间截图并校验页面，不能仅凭翻页失败判断为识别慢；不要同时改截图后端、档位和多个时间参数。导航失败先修复登录或页面状态，误选或重排失败则保留实际名单，供排查时对照。

导入排班与启动校验

导入后逐项核对

  1. 排班页面支持排班 JSON、排班图片，以及从备份 ZIP 中只读取排班。导入别人的表后，先替换未持有或不适用的干员。
  2. 核对设施类型、等级、产物与岗位数。办公室、训练室、回收站的本地显示及导航顺序须与游戏布局一致；这项顺序不随排班导出。
  3. 核对主表及全部副表中的主班、每列绑组与替班，检查副表任务及触发条件。
  4. 点击“验证排班”。预算不足或超时表示校验未完成，不能当作通过；修改后重新验证。

持有和训练位检查

有森空岛干员名单时，校验覆盖主表、副表及换人任务；缺少干员会尝试同步。无法同步时，旧缓存不直接证明账号未持有。只有库存、尚无干员名单时保留原有验证行为。

训练室第二个位置是训练位，基础技能须达到 7 级且至少有一项技能尚未专三。已同步数据中不满足条件会阻止验证及启动；检查同时覆盖该位置各绑组的替班和副表换人任务。协助位不受这两项训练位检查。

  1. 基础技能不足 7 级：先在游戏中升级至 7 级；所有技能均已专三：更换训练对象，或按用途放到协助位。
  2. 到“养成规划”页面手动点击“刷新”，同步最新干员数据，再回到排班页面重新验证。技能字段缺失或缓存无效时也使用这一入口。
  3. 提示未持有干员时核对账号与排班，获取或替换干员后同样刷新再验证；提示资源缺少森空岛 ID 时才更新资源包。更新资源不能代替练度同步。

发现持有或训练条件问题时，检查会尝试同步一次；同步失败仍报告缓存中已知的训练条件错误。尚无干员名单时跳过相应检查，不代表已经具备开训条件。

通过校验后仍要观察一轮

静态校验确认配置是否可行，运行时还要考虑实际心情、占床、任务预约和训练保护。先确认普通下班、替班接岗、主班入宿与回班连续正常，再开启复杂副表或专项安排。

排班表编写理论：岗位、替班与恢复容量

排班表定义岗位身份和可用替换关系。Mower 根据心情、实际驻员和任务状态动态调度，不按固定时刻轮换整张表。编写时同时回答：谁工作、谁接岗、哪些人协同换班、到哪里恢复。

先确定主班与绑组

每个主班只占一个配置岗位。需要保留技能配合、一起上下班的成员填写同一组名；无需联动的成员可以不绑组。组名不表示轮休先后，跨设施绑组也不会增加替班或床位。

每个组至少有一名决定上下班的普通固定工作主班：非宿舍、非零心情工作、非多绑组、非候补。普通及低优固定工作主班都可满足这一要求；全候补组或全零心情工作组不能靠多写 Free 通过校验。宿舍跟随成员、候补及共享成员的个人事件不代替整组上下班。

三人制造站的完整替班示例

岗位主班组替班
制造站 1甲制造一组丁
制造站 2乙制造一组戊
制造站 3丙制造一组己

甲至己是示意称呼，实际填写持有且适合设施的干员。甲乙丙下班需要丁戊己同时可用，且三名主班均有合法恢复位置。三个岗位都只填丁不能完成整组替换；与另一组共用替班时，还要检查两个休息窗口能否错开。

替班列表是候选集合，不是按顺序轮换的时间表。候选正在其他岗位工作、被任务预约或受训练保护时，填写了名字也不表示当前可用。

宿舍固定岗位、Free 与绑组

主表每间宿舍填写完整五个位置，具名驻员后连续填写 Free，至少保留一个直接填写的 Free。当前不强制每间固定两名宿管；恢复速度由实际技能决定。Free 与菲亚梅塔不能绑组，菲亚梅塔替换名单表示充能对象。

宿舍具名成员的替换组下班时恢复容量
非主班干员候选接替固定宿舍岗位。仍是固定岗位，不额外产生普通 Free。
同组工作主班工作主班进入该固定宿舍岗位恢复，可与宿舍主班双向互替。已使用固定恢复位者不再重复申请动态床；该位置不对任意休息者开放。
Free宿舍成员随组离岗待命，临时开放恢复容量。形成绑组 Free 额度；只在相应组状态允许时生效，不是永久普通空床。

例如甲在办公室、乙在固定宿舍，两人同组且互填替换，换班时乙接办公室、甲进入固定恢复位；甲不再额外占一张 Free。若甲改由非主班丙替班、乙的替换改为 Free，则乙随组离岗待命，开放的是绑组额度；乙待命时不恢复心情。工作主班之间互替、跨组互替、自身替班仍不允许。

绑组 Free 额度不能任意借用

普通 Free 与绑组 Free 按可用数量校验，不锁定某个床号。前四层中需要恢复的工作主班可使用普通额度或符合自身绑组关系的额度，不能借用其他组的额度；高优替班使用普通额度。候补、普通替班、空闲干员可使用两类额度。分配优先使用合法绑组额度，为外组申请者保留普通额度。

判断容量时看实际驻员、已排队的入住预约和同轮成功安排，不能仅数当前画面空床或表格中的 Free。静态校验只计算普通额度与本组配置额度，不借用另一在休组临时开放的容量。宿管回班收回额度时可跨床换位，容量不足再按规则安排离宿；恢复已完成不会自动取消受保护床位。

一个岗位参与多个绑组

在同一个岗位点击组旁“+”，为每个绑组分别填写非空、不重复的组名和替班。不要把同一主班重复填进多个岗位；每个关联组仍须有只绑该组、符合普通固定工作主班条件的成员决定上下班。

主班组该组替班候选
甲（同一岗位第一列）A己、庚
甲（同一岗位新增列）B庚、辛
乙（只绑 A）A丁
丙（只绑 B）B戊

A、B 同时休息时，甲的替班须取两列共同可用候选，此例只有庚；丁、戊也必须可用且不能重复占岗。没有共同候选时，新申请休息的组等待。共享主班恢复只占一张床，零心情工作成员不申请恢复床。

每组保留独立状态。一个组回班不提前释放另一个在休组仍需的共享替班；最后一个依赖组回班后再恢复共享主班。共享宿舍成员和临时 Free 同样遵守依赖关系。共享成员或候补个人失床不召回整个组。

分床顺序与已占床保护

分床顺序为：宿舍高优先级干员 → 普通主班 → 宿舍低优先级主班 → 宿舍高优先级替班 → 休息候补 → 普通替班 → 空闲干员。同级按距各自心情上限的缺口排序，缺口较大者优先。

分床排序不等于可以挤走任何低优住员。前四层已占用的恢复床受保护，即使预计恢复完成、截止时间已过或处于救急，也不由普通恢复申请直接接管。同级不互抢。

前四层申请者可接管候补、普通替班和空闲床位。候补可接管普通替班和空闲床位；普通替班可接管空闲床位，但这两类申请者都须有有效实测心情且不超过自身上限的 80%。普通满心情清退、个人上限强制离宿、正常回班和明确排班任务另按各自条件执行。

已有单回目标不因心情变化主动重排；合法的新高优目标可替换较低层级目标，同级不抢。宿舍优先级排序决定有效床位的选用顺序，不增加容量。副表改变房间顺序不会单独把所有住员重新搬床。

候补可以待命，但不替代必需床位

“宿舍休息候补干员”对符合条件的工作主班生效。需要有符合规则的正常恢复主班提供待命依据；有床则恢复，无床可离岗待命，待命不恢复心情。用尽、强制回满、固定宿舍和零心情工作配置保留各自规则，不直接按普通候补处理。

下班分床前，候补低于个人急救线会升为低优并必须取得床位；恢复途中越过急救线也不降回候补，实际回到工作岗位后才清除本轮提升。因此静态配置容量通过，运行时仍可能因升优成员需要额外床位而暂缓下班。

心情上下限与工休估算

全体设置提供默认范围，令夕及其组内规则可覆盖，指定干员设置优先级最高。上下限在 0 至 24 点内且下限小于上限；用尽以适用下限为目标，回满以适用上限为目标，不一定是 0 和 24。

下班参考线 = 下限 +（上限 − 下限）× 心情阈值 工作时间 ≈（回班心情 − 下班心情）÷ 每小时消耗 恢复时间 ≈（回班心情 − 下班心情）÷ 每小时恢复

无自定义上下限时，下班参考线还按程序规则取整。阈值只是参考，实际下班还要求整组替班、合法床位与任务时间均可行。提高阈值通常更早申请休息，也增加周转压力。

估算工休时使用实际组合的消耗与恢复速度，再留出换人、排队、跑单和充能余量。普通组不一定等所有人回满才回班；强制回满和组内心情差设置会改变回班时间。达到个人上限离宿也不等于立即回岗。

主表稳定后再增加副表

副表按条件覆盖主表，可以同时生效。后面的生效副表继续覆盖前面的结果；主表页面的校验检查可能同时成立的组合，不能只检查当前编辑页。

Current 继承前面合并结果的整个岗位，包括主班、组与替班，不是保留游戏当前驻员。要修改替班，明确填写主班及完整绑定，不能在 Current 后局部覆盖。主表不使用 Current，Free 仅用于宿舍。

普通副表的回满、用尽及优先级名单使用“增”“减”列，先增后减；留空表示继承，后面的副表仍可重新加入。救急表使用独立名单。副表可调整 Free，但最终每间宿舍仍至少一个直接 Free，恢复容量也必须可行。

副表不能改变主表生产设施类型与岗位数。产物或订单目标不同还需开启对应高级开关。退出副表按最终合并表重新安排，不强制所有在休主班立即回岗。

从零写表的检查顺序

  1. 按游戏布局填设施与主班，先建立简单、完整的普通轮休。
  2. 为每个组保留合格的普通固定工作主班，并为每个岗位准备不冲突的替班。
  3. 区分固定恢复位、普通 Free 和绑组额度；再核对保护住员、预约和候补升优后的容量。
  4. 需要共享时逐组填写候选，检查同时休息的交集和最后依赖组回班行为。
  5. 同步干员练度，校验持有、训练位及主副表组合；观察完整下班与回班后再增加专项功能。

基建与日常设置

邮件、签到与线索

按需要配置公招、游戏邮件、好友和线索等日常任务，活动领取以当前设置与活动开放情况为准。通知邮箱填写发件地址、SMTP 与授权信息，先测试连接；它同时用于需要邮件的反馈流程。

跑单、无人机与产物

核对贸易站、跑单干员、无人机目标与时间设置。跑单和普通轮休共用实际岗位与预约约束；不要把准备时间或漏单报警时间直接当作原任务发生时间。

“自动切换产物与订单”默认关闭。关闭后仍可普通换班、收取产物和葛朗台跑单，但副表不能指定不同生产目标，相关切换条件与选项隐藏。需要切换时明确开启并检查损耗和无人机设置。

宿舍不养闲人与自动救急

“宿舍不养闲人”只控制普通满心情清退任务。关闭后仍可安排恢复、补空床及合法接管；个人上限和令夕上限的强制离宿仍生效。不能靠这个开关取消保床规则。

自动救急默认关闭，入口在 Mower 设置 → 基建设置，独立编辑救急排班。初始化观测满足接管条件且普通轮休无法安排时才使用救急表；正常与救急的设施类型、等级和产物须一致。期间正常副表冻结，跑单、宿管和菲亚梅塔按救急表配置，不自动继承未填写专项任务。

菲亚梅塔充能

按编辑器帮助填写充能目标及相关选项。菲亚梅塔不参与普通宿舍绑组或单回目标选择；充能记录、心情读数与正常换班分别处理。

MAA、作战与大型任务

安装完整 MAA 并测试

  1. 在 MAA 设置配置与系统、架构匹配的完整 MAA 目录。页面支持下载 MAA、检查或安装本体更新及资源更新。
  2. 核对 MAA 的 ADB 路径、目标设备与连接参数，执行测试连接；不要只复制 DLL 或用旧 Mower 下载器替换组件。
  3. Android 的目录及设备能力由宿主管理；桌面平台以当前页面帮助为准。

刷理智周计划

按星期配置执行方式、关卡、药品与理智限制。选择 MAA 时先验证 MAA 连接；选择 Mower 时使用对应支持范围。没有刷图时先检查当天方案、时间窗口与库存条件。

大型任务独立配置

肉鸽、保全、生息演算或隐秘战线按各自入口和独立开关运行。不需要为了大型任务开启空刷理智计划；也不能只打开周计划就假定大型任务已启用。

任务结束后恢复游戏主题在 MAA 设置中配置，需 MAA 核心与资源满足页面版本要求，并选择账号已解锁的主题。手动停止、异常退出或下一调度时间不足时不保证执行。

养成、专精与加工

先同步练度和库存

“养成规划”页面统一管理等级、精英化、基础技能、专精和模组目标，展示材料、龙门币及经验需求。绑定账号后点击“刷新”同步练度，再排序目标；游戏中升级、获取干员或完成专精后，也需刷新，不能只依赖旧缓存。库存扫描与干员练度同步是不同步骤。

自动化范围与训练冲突

“全自动专精”控制自动专精和养成材料自动合成。精英化、基础技能升级、模组开启与升级仍需在游戏手动完成，再同步数据。开训要求精英二、基础技能 7 级和对应材料，并核对训练位、协助路线及训练保护。

自动专精的被训练干员不能同时占用非训练室排班；出现冲突时按计划原因解除冲突，等待下一次库存扫描重新评估。训练位的基础技能和全技能专三校验也检查主副表替班和任务，见排班校验。

合成按统一计划顺序和本地库存预算备料，保留正在训练阶段的需求；刷新较晚的云端库存不能当作本地刚完成合成尚未发生。缺料、安排失败和训练中是不同状态，查看计划实际返回的原因。

AI 助手的专精重试工具会重置全部失败计划，不按传入干员筛选。只想处理一项时，先核对页面实际支持的操作范围。

备份、迁移与多开

导出完整实例备份

  1. 在 Mower 设置 → 配置导出与导入导出 ZIP。包含 config 原文件、主副排班及持久化 tmp 数据，例如专精计划、路线、历史和库存。
  2. 备份不含 state.json、资源包、更新文件、日志、其他实例及浏览器偏好。单独导出排班不能代替完整备份。
  3. 迁移时停止自动任务并等待更新结束，选择备份导入。覆盖前会生成恢复 ZIP；失败时按页面提示处理，成功后刷新配置，不自动开始任务。
  4. 当前管理端口、令牌及本机网络等设置保留，旧调度缓存清空。换电脑后重新核对设备、ADB 和 MAA 路径。

备份包含凭据，妥善保管。不要只复制旧教程的根目录 conf.yml、plan.json 或 temp 文件夹，也不要公开上传完整备份。

区分任务停止、进程退出与窗口关闭

多开管理器分别管理实例名称、数据目录、端口与绑定设备。配置和运行数据按实例隔离，同一安装的程序及资源更新按共享范围生效。

“进程操作”只处理当前实例；重启续接保留已保存队列，普通重启重新安排运行缓存。结束进程会停止该实例；关闭窗口可能仍保留后台运行，具体由托盘和多开管理器的关闭设置决定。手动操作游戏前先停止自动任务。

日志、排错与 AI 助手

先定位任务和时间

  1. 确认当前实例、发生时间及具体任务，区分设备连接、软件更新、排班和 MAA 日志。
  2. 保留完整错误上下文、实际画面及对应报错归档。排班等待先读缺少的替班、恢复容量或保护条件。
  3. 需要清理数据时先备份，再从运行日志页的“数据库管理”选择对应类别；不要全选或直接删除 data.db。

配置模型后从左侧打开助手

模型配置放在 Mower 设置 → AI 助手与模型服务。DeepSeek 使用一个服务选项，可选 deepseek-flash、deepseek-v4-pro 预设，或填写官方模型 ID；本地及在线接口分别填写实际地址、模型和密钥。本地接口须兼容 OpenAI Chat Completions，在线接口须使用 HTTPS；工具调用还需服务和模型支持。

点击左侧“Mower AI 助手”直接打开对话。桌面窗口可拖动标题栏调整位置，收起保留草稿和当前会话；新对话会清空会话。Enter 发送，Shift+Enter 换行，回复期间可继续写草稿。

助手可查询 FAQ、日志与数据库，分析漏单和报错、管理专精计划，并按明确要求发送反馈。选择具体归档可分析对应错误；漏单分析需具体记录或完整本地时间范围，报警时间不一定等于原任务时间。

以工具实际返回为准。AI 推测不证明根因，也不表示排班已自动修改；发送给模型的内容可能含精简日志，不提供密码、访问令牌或 API 密钥。

常见问题

连接失败，要直接换端口吗？

先核对预设、实例和具体状态，再使用对应检测或修复动作。只读测试不会启动模拟器，不猜默认端口，也不改连另一台在线设备。见设备连接。

有空床或已到心情线，为什么不下班？

空床不等于可用额度，填写替班也不等于完整替班可用。检查组的普通工作主班、共享候选交集、普通及本组容量、受保护住员、候补升优、预约和训练保护。见排班理论。

训练位导致验证失败，如何修复？

核对训练室第二个位置及其替班、副表任务。基础技能不足时在游戏中升至 7 级，全技能专三时更换训练对象；随后到“养成规划”手动点击“刷新”，再验证排班。协助位不受这两项训练位检查。具体步骤见持有和训练位检查。

CPU、内存较高，为什么没有推荐极高档？

资源读数仅展示信息。自动档依据实际操作反馈，桌面端游戏内测试依据连续滑动后的选人及重排结果，低档仍失败时不推荐档位。Android 支持高和极高，但暂不提供该游戏内测试。入口及操作见性能适配。

不刷图或大型任务没运行，要开空周计划吗？

周计划与大型任务独立。分别检查执行方式、当天配置、时间窗口、库存条件和独立开关，见作战配置。

白屏、数组错误或报表缺记录怎么办？

白屏区分系统窗口依赖与页面加载；数组错误结合完整堆栈和画面；报表先核对实例、时间范围及记录是否存在。保留证据后查归档或请求 AI 分析，不直接归因为杀毒、布局错误或数据库损坏。

反馈表与邮件反馈

先查阅Mower 反馈表。游客不一定有填写权限，需要登录及相应编辑权限；程序不自动写入腾讯文档。

  1. 说明 Mower 版本、系统及架构、设备或模拟器和目标实例。
  2. 给出复现步骤、期望结果与实际现象，附完整本地时间范围、相关日志或报错归档。
  3. 在内置反馈窗口或向 AI 明确提出发送请求，通过已配置邮箱发送。只整理描述不会发送；邮件成功也不表示已登记到表格。
  4. Bug 反馈需可用日志和对应时间范围。去除密码、授权码、令牌及密钥，不公开完整配置。
