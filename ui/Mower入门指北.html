Mower 一条龙入门说明

本说明介绍 Mower 的当前功能与界面，更新时间：2026-10-09。实际软件版本和可用操作以你所用平台的页面提示为准。

先完成设备连接和排班核对，再逐项打开需要的自动化。软件更新、资源更新、刷理智周计划和大型任务各有自己的入口与开关。

  1. 安装或更新：首次安装使用官方发布包，已有程序在“软件更新”检查版本。
  2. 绑定设备：选择平台预设，检测并选定目标实例，核对连接状态。
  3. 导入或编辑排班：核对设施、主班、绑组、替班、宿舍和副表，完成校验。
  4. 选择基建与日常任务：按需要开启线索、跑单、邮件和签到等功能。
  5. 配置作战：周计划选择 MAA 或 Mower 执行方式；大型任务独立设置。
  6. 配置养成与专精：先同步练度和库存，再核对目标、路线与自动合成。
  7. 启动并观察：先确认一轮换班和所选任务正常，出现异常查看对应日志或归档。
  8. 导出备份：保存当前实例的配置及持久化数据，迁移前再导出一次。

问题与建议可查阅 Mower 反馈表。

安装、软件更新与资源更新

首次安装

macOS 和 Linux 虽提供独立包，仍建议优先使用源码部署，安装步骤见 README。选择独立包时，按下列步骤安装。

  1. 从 MowerRelease 官方发布仓库选择对应系统和架构的独立包，并核对发布说明及 SHA256SUMS。
  2. Windows 解压完整包后启动其中的程序；macOS 使用对应架构的 DMG；Linux 使用对应架构的完整压缩包。
  3. Windows 和 macOS 包未签名，首次运行可能出现系统安全提示。核对来源后按官方说明处理；Linux 如提示缺少 GTK/WebKit2，按提示安装宿主依赖。
  4. 打开界面后先查看 Mower 设置 → 软件更新中的当前版本和渠道。

不再使用旧版独立 Mower 下载器，也不按旧教程直接覆盖未知增量包。

已有安装：内置软件更新

  1. 进入 Mower 设置 → 软件更新，选择正式版、公测版或开发版渠道。
  2. 检查目标版本和更新说明，再按页面提示安装。也可按需开启“自动检查更新”“自动更新”。
  3. 更新会重启同一安装目录下的运行实例并恢复原运行状态；“更新后后台静默重启”控制是否重新打开窗口。
  4. 独立包可在“手动应用”上传 Release 安装包；支持 OTA 的平台可用与当前版本匹配的差异包。版本不匹配或差异校验失败时使用完整包。

源码部署与平台差异

源码部署使用“软件更新”的在线源码更新及“源码版本管理”。本地源码有修改时，先自行保存需要的改动，再判断是否接受强制更新；不要向源码部署上传 Release 独立包。源码安装和平台依赖详见 README，不沿用旧文档中指定的环境名、手工拼装 macOS MAA 或固定安装路径。

资源与网络

Mower 设置 → 资源更新管理 Mower 识别等资源，支持检查、自动更新和手动上传资源包。共享安装下各实例在任务间歇加载资源，通常无需重启。MAA 本体和 MAA 资源在 MAA 设置中单独更新。

下载失败时，在“网络与下载代理”检查全局网络代理和 GitHub 下载站点，并使用页面的下载测试。软件更新日志、资源更新日志和设备连接日志应分别查看。

设备连接与恢复

选择预设与目标实例

  1. 在 Mower 设置的设备连接区域选择当前系统对应的预设。Windows、macOS、Linux 的支持范围和操作不同。
  2. 使用页面提供的“检测实例”或“启动并检测”。如果检测到多个实例，先明确选择目标。
  3. 需要补充路径时，按当前字段的问号说明填写安装、管理器或配置路径。不要统一填旧 shell 文件夹、多开编号0或某个默认端口。
  4. 查看状态、修复提示及所选实例。检测到的实例身份先保存，ADB 地址和游戏包通过验证后保存；测试失败不撤销已经选择的实例。

未指定自定义 ADB 路径时优先使用 Mower 自带的 ADB。需要手动连接时，在高级设置选择“其他模拟器”或“实体设备”，填写明确目标 serial，再测试连接。

区分检测、测试与启动

  • 测试连接（只读）：只检查当前连接，不启动或重启模拟器及其管理器。
  • 启动并检测：支持该动作的预设核验所选实例，停止时先启动再检查。多实例环境仍需明确目标。
  • 启动并测试连接：按当前连接与恢复设置处理选定实例，不自动切换到其他在线实例。
  • BlueStacks Air 需要在应用中手动开启 ADB 及启停；AVD、redroid、Genymotion 等以页面的本次启动确认和退出提示为准。

截图、触控与实体设备

标准画面为横屏1920×1080 RGB。截图与触控在“连接与恢复”调整；MuMu IPC 只适用于 Windows MuMu 12，截图与触控配套；雷电截图增强只适用于 Windows 雷电9或14。其他后端按页面支持情况选择，不统一切成 ADB+Gzip。

实体设备默认只检查画面尺寸。页面提供“临时整备”时，授权仅对本次运行有效，结束、取消或失败时按尺寸恢复规则还原；先手动横屏，Mower 不修改旋转、密度或导航栏。Android 应用内的设备连接由应用管理，桌面预设说明不适用。

启动保护时间、连接超时和重试次数均有边界。遇到离线或启动失败，按当前目标的状态提示修复，不反复增加等待时间或改连其他设备。

排班、主副表与宿舍

导入与核对

  1. 排班页面可导入排班 JSON、排班图片，或从配置 ZIP 读取 config/plan.json。完整配置迁移使用“配置导出与导入”。
  2. 核对基建设施的位置、类型、等级与岗位数；办公室和训练室显示位置在 Mower 设置 → 基建设置中选择。
  3. 检查主表、副表、触发条件、显式换人任务，以及对应的主班、绑组和替班。
  4. 运行排班校验，按具体设施和干员修复冲突。超时或预算不足表示未完成校验，不等于所有组合已经通过。

主班、替班与绑组

主班确定岗位身份，替班提供休息时的完整替换。一个干员可参与多个绑组；共享主班只有在各休息组都具备兼容替班时才允许同时休息，否则相关组等待。只有最后一个依赖组回班后，共享替班才释放。不要把“替班已填写”当作“当前替班一定可用”。

工作主班之间不能互填替班；同组主班互替仅在至少一方属于宿舍绑组岗位等条件成立时允许。最终以排班校验与实际任务安排为准。

宿舍与恢复优先级

Free 是可动态安排休息者的位置，不等于当前已确认空床。床位分配还受实际入住、预约、个人上下限和专项任务保护约束。宿舍按分床优先级、单回位归属及心情恢复缺口安排，不使用固定“4个VIP加8个非VIP”的通用公式。

已有单回目标不因心情变化主动重排；更高优先级的新入住者可按规则接管较低优先级单回位，同级不抢占。个人回满目标可能低于24，达到上限离宿不等于立即安排上班。

副表、产物与岗位兼容

副表不能改变主表生产设施的类型和岗位数。排班高级设置中的“自动切换产物与订单”默认关闭；关闭时副表不能指定与主表不同的产物或订单目标，相关状态条件和切产物选项隐藏。普通换班、产物收取及葛朗台跑单仍保留。

主班身份、岗位和绑组没有相关变化时，副表切换优先保留休息、床位与回班状态；替班不足、预约或专精保护冲突时按实际规则等待或召回，不把退出副表理解为强制所有主班回班。

基建、日常与排班高级设置

邮件、签到与线索

在“邮件提醒”配置账号及 SMTP，使用“发送测试邮件”验证。收件人列表为空时发给自己；删除空白项，不要保留一条空字符串。QQ 邮箱使用授权码，自定义邮箱按服务商要求选择 SSL/TLS 或 STARTTLS，勿向助手提供密码或授权码。

“每日任务”按需选择森空岛及游戏签到等项目；森空岛账号、库存与干员数据同步按对应页面配置。基建设置中的“线索收集”和赠送选项控制会客室任务，好友和信用任务按各自入口选择执行方式。

跑单、无人机与产物

按实际排班配置跑单干员、房间与无人机使用方向。葛朗台跑单与葛朗台切产物分别配置；关闭自动切产物不会关闭普通跑单。启用切换时核对无人机和损耗设置，避免把切产物等待误当作连接故障。

下班与回班

达到心情阈值后还需有效观测、完整替班匹配和可用恢复床位。用尽下班使用有效消耗速率，不保证固定提前两三小时。心情卡牌预估辅助筛选，不能当作实测回满或确定的恢复结束时间。

“组内心情差距过大时延后回班”比较参与计时成员的最晚与最早预计恢复完成时间，默认阈值60分钟，并受额外等待上限约束；不是固定心情点差。

宿舍不养闲人与分床顺序

“宿舍不养闲人”只控制普通满心情清退任务。关闭后仍安排恢复、补床和优先级接管，个人及令夕上限仍生效。主表与副表可设置宿舍优先级顺序，留空按当前规则处理；更换宿舍布局后核对相应设置。

自动救急

在 Mower 设置 → 基建设置开启“自动救急”，通过旁边“救急排班”编辑独立主表和副表。默认关闭；初始化发现多组主班低于各自救急线、仍有人等待休息且普通轮休无法安排时才接管。双方副表生效后的工作设施类型、等级和产物必须一致。

救急冻结正常副表，驻员、跑单、宿管和菲亚梅塔按救急表配置，未配置专项任务不自动继承正常表。正常排班可以接回周转时退出，仍需恢复的组继续休息，不要求所有组回满。开关不随正常排班导入导出。

菲亚梅塔充能

配置菲亚梅塔的宿舍位置、充能对象及相关阈值，充能期间保留专项任务和床位保护。自动救急使用救急表自己的配置；存在主班等待床位时，菲亚梅塔按救急分床规则让床。调整前先核对当前生效排班和具体日志，不把普通宿舍补床当作充能任务。

MAA、刷理智与大型任务

MAA 安装与测试

  1. 需要 MAA 执行的任务，在 MAA 设置检查目录及平台，未安装时按页面“下载 MAA”获取组件。
  2. 已有安装使用“检查 MAA 更新”“更新 MAA”；MAA 资源独立检查和更新。下载后的目录需包含完整的平台运行库、资源与接口。
  3. 点击“测试连接”，按日志区分目录、运行库加载与设备连接故障。Android 的组件和连接按应用管理提示处理。

当前页面提供各平台的组件管理，不再按旧教程手动复制 Windows Python 文件夹拼装 macOS MAA，也不通过旧版 Mower 下载器替换 DLL。

刷理智周计划

  1. 开启“刷理智周计划”，选择或创建方案，再选择执行方式：MAA 或 Mower。Mower 本地作战不依赖 MAA。
  2. 在列表或表格安排每天关卡，两种视图编辑同一份计划；在列表配置吃药次数及理智阈值。
  3. 库存选关规则按方案保存，只作用于已选择的关卡，不自动加入关卡；检查限制是否使关卡被跳过。
  4. 活动方案可设置结束后的目标和切换时间，查看当天实际生效方案。

大型任务独立开关

“大型任务”独立控制集成战略、保全派驻、生息演算和隐秘战线等任务，不需要额外开启一个空刷理智计划。带“(MAA)”的任务依赖 MAA，其余类型使用对应的 Mower 流程。

开始时间与停止时间相同表示全天；停止时间早于开始时间表示运行到次日。还需检查对应任务模式、日常任务间隔、基建任务空闲时间及运行日志。

养成、专精与加工

先同步，再添加目标

养成页面统一管理等级/精英化、基础技能、专精和模组目标，并展示材料、龙门币及经验需求。同步干员练度与库存后再安排目标，区分“需要准备的材料”和“已经满足的开训条件”。

自动专精与材料合成的范围

“全自动专精”控制自动专精及养成材料自动合成。精英化、基础技能升级和模组开启/升级仍需在游戏手动完成后同步；添加目标不代表 Mower 会自动点击完成全部养成。

专精开训要求精英二、基础技能7级及对应材料，并受训练室岗位和协助路线保护。计划可处于待执行、安排中、训练中、待收取、已完成或失败；查看失败原因后再决定重试。

自动合成按统一养成计划顺序及本地库存预算备料，保护正在训练的需求和已确认的库存变动。完整材料不足的未开工项目不会部分占用材料；刷新较晚的云端库存不等于可以覆盖本地刚完成的合成。

AI 助手当前的专精重试工具会重置全部失败计划，不按传入干员筛选；只想重试一项时，先核对页面支持的操作及实际范围。

配置备份、迁移、多开与退出

完整备份与恢复

  1. 在 Mower 设置 → 配置导出与导入点击“导出配置”，保存当前实例 ZIP。
  2. ZIP 包含 config 原文件、主副排班及持久化 tmp 数据，包括专精计划、专精路线、历史与库存；不包含 state.json、资源包、更新文件、日志、其他实例和浏览器偏好。
  3. 导入前停止任务，选择备份 ZIP，核对覆盖范围再确认；导入前自动生成恢复 ZIP。
  4. 成功后页面刷新加载配置，不自动开始任务。当前管理端口、访问令牌与本机网络等设置保留；旧调度缓存清空。
  5. 换电脑后重新检查设备与 MAA 路径。需要撤销时可导入自动生成的恢复 ZIP。

不要只按旧教程复制根目录 conf.yml、plan.json 或 temp 文件夹；完整备份包含凭据，请妥善保管。

实例隔离与进程操作

多开时确认当前实例名称、数据目录、端口和绑定设备，各实例的配置与运行数据分别管理，软件和资源更新按共享安装范围生效。

设置页底部“进程操作”只操作当前实例。“重启续接”保留队列继续运行；普通“重启 Mower 进程”重置运行缓存后重新开始；“结束 Mower 进程”正常停止任务并结束此实例。关闭窗口可能仍在后台运行，以托盘或多开管理器设置为准。

日志、排错与 AI 助手

先看具体证据

运行日志查看任务、时间、设施、干员和异常堆栈。报错归档保留对应现场；选择具体归档后可使用 AI 分析。连接状态、更新日志和排班任务日志分别对应不同问题，单独一条 ERROR 不能证明唯一根因。

清理数据先导出备份，再在运行日志页面的“数据库管理”选择确实需要删除的类别。心情记录、专精计划、专精路线、库存和运行缓存彼此独立，不全选、不直接删 data.db。

DeepSeek、本地与在线模型

  1. 在 Mower 设置 → AI 助手与模型服务选择 DeepSeek 预设、本地 OpenAI 兼容接口或在线模型/中转商。
  2. 自定义接口填实际模型ID与接口地址。本地需兼容 OpenAI Chat Completions，通常可不填密钥；在线接口要求 HTTPS 和对应密钥。
  3. 聊天工具调用需要服务及模型支持工具调用。助手可查 FAQ、日志及数据库、分析漏单与错误、管理专精计划及按明确要求发送反馈。
  4. 核对工具实际返回。AI 建议中的推测不等于已证实的根因，也不代表排班已自动修改。不要发送密码、API密钥或访问令牌。

漏单分析先选择具体记录或提供完整本地时间，再结合任务时间线；漏单报警的时间不一定是原任务时间。

常见问题

连接不上，是否直接换端口或截图方案？

先看设备连接状态与修复提示，核对预设和所选实例。不同平台、模拟器及实例的能力不同，不猜默认端口，不把所有问题都改为 ADB+Gzip，也不改连另一台在线设备。详见 设备连接。

红脸或到阈值还不下班？

检查有效心情、个人规则、组绑定、完整替班、床位和预约。共享替班、训练保护或无法安排完整恢复都可能造成等待；按日志中的阻塞条件调整。详见 排班与宿舍。

不刷图、不运行生息演算，是否要打开空周计划？

大型任务与刷理智周计划是独立开关。分别检查执行方式、任务类型、时间窗口、当天方案及库存限制。详见 作战与大型任务。

白屏、数组报错或历史报表为空？
