Mower 一条龙入门说明

本说明更新于 2026-10-10，按首次运行顺序介绍部署、连接、排班和任务配置。已有用户可从左侧目录查找对应功能。

先完成设备连接和普通轮休，再逐项添加自动化。遇到校验失败或任务等待时，按页面提示和日志调整配置。

  1. 部署并确认版本：源码部署或从项目 Releases 获取完整包，确认平台依赖。
  2. 绑定设备与选择性能档位：检测实例、明确选择，再测试连接；性能通常保留自动。
  3. 导入或编写排班：核对设施、干员、替班、宿舍与校验结果。
  4. 配置基建与日常：只开启需要的任务，先观察一轮下班和回班。
  5. 配置 MAA 与作战：区分刷理智周计划与独立大型任务。
  6. 安排养成与专精：同步练度和库存，再准备材料及训练路线。
  7. 导出完整备份：保存配置和持久化业务数据，迁移或重要修改前重新导出。

出现问题时，按日志与 AI 排错步骤整理证据，再通过反馈入口求助。

安装、软件更新与资源更新

优先按部署方式选择安装步骤

macOS 和 Linux 虽有独立包，仍建议优先使用源码部署。Windows、Linux、macOS 的环境、前端构建及启动命令统一放在项目主页 README；本地打包和 Docker 的 Markdown 链接也在 README 中。

首次使用独立包

  1. 从项目主页的 Releases获取适合系统、架构的完整包，核对发布说明与 SHA256SUMS。
  2. Windows 解压完整目录后运行主程序；Linux 解压后检查宿主系统库；macOS 将应用移出 DMG，放到可写位置再运行。
  3. 独立包支持 Windows x64、Linux x64/ARM64 和 macOS ARM64；Intel Mac 使用源码部署。Android 的程序更新 ZIP 在已有应用内导入。
  4. Windows 与 macOS 包没有平台发行签名。确认下载来源后按系统提示处理；Linux 缺少 GTK/WebKit2 时按启动提示安装依赖。

首次安装从项目 Releases 下载，后续使用程序内更新。

已有安装：使用内置更新

  1. 打开 Mower 设置 → 软件更新，核对当前版本、部署方式及渠道，再检查更新。
  2. 选择页面提供的正式版、公测版或开发版目标。源码开发版跟随所选分支。
  3. 更新会重启同一安装目录下的运行实例并恢复原运行状态；后台静默重启控制是否重新打开窗口。
  4. 独立包可在“手动应用”上传匹配的 Release 包；源码部署使用在线源码更新或 Git 更新。强制源码更新会覆盖本地修改，操作前先保存。

三类更新分别处理

内容入口与生效方式
Mower 程序Mower 设置 → 软件更新，安装后重启相关实例。
Mower 识别等资源Mower 设置 → 资源更新；同一安装共享，在任务间歇加载，通常无需重启程序。
MAA 本体与资源MAA 设置中分别更新；MAA 正在执行任务或测试连接时，等待其释放后操作。

下载失败时，在“网络与下载代理”运行对应测试，并查看下载日志。

设备连接与性能适配

先选预设，再选实例

  1. 进入 Mower 设置的设备连接区域，选择与当前系统和模拟器对应的预设。
  2. 按字段帮助填写路径，使用“检测实例”或“启动并检测”，从结果中选择目标实例。
  3. 核对实例及游戏包，执行连接测试。程序保存所选实例，并在连接验证通过后保存 ADB 地址和游戏包。
  4. 检查游戏区服、横屏尺寸与连接状态，使用预设检测到的路径和端口。

例如 MuMu 12 同时开着主号和小号：选择 MuMu 12 预设，检测实例后选中主号对应的实例，再测试连接。以后继续使用这个实例，地址由检测结果填写。

检测、只读测试与启动的区别

“测试连接（只读）”检查已运行的设备；“启动并检测”用于支持自动启动的预设。连接失败时，按状态提示检查设备启动、ADB 或实例信息。

截图、触控与实体设备

优先使用预设推荐的截图和触控组合。选择 MuMu IPC 截图时，触控也使用 MuMu IPC。

其他模拟器或实体设备在高级设置中明确填写目标 serial，再测试连接。实体设备默认检查横屏 1920×1080；页面提供的临时整备只对本次运行授权，结束后按恢复规则还原。macOS 源码部署需按 README 准备 ADB，Linux 使用配置的路径或系统 adb。

性能档位如何选择

在 Mower 设置的设备连接区域选择性能档位，首次运行建议使用“自动”。自动档根据选人反馈调整，桌面端从极高开始，Android 从中开始。两端均可手动选择低、中、高或极高档。

档位选人策略
极高连续点击重排，适合能及时响应输入的设备。
高缩短清空和翻页等待，操作完成后统一校验。
中等待稳定画面后继续操作。
低多确认一帧，优先处理响应较慢的情况。

连接测试会显示设备的 CPU 核数和内存总量。截图间隔、选人采样间隔和页面切换超时可单独配置，建议先使用默认值。

游戏内性能测试

  1. 停止 Mower 自动任务，等待 MAA 测试、更新及其他设备操作结束。桌面端核对并保存设备设置，再测试连接；Android 由应用管理后台设备。
  2. 点击“游戏内性能测试”。程序连接所选设备，启动游戏并进入基建宿舍一。需手动启动设备、完成登录验证或协议确认时，按提示处理后重试。
  3. 测试从极高档开始。每次先清空暂选、复位列表并连续滑动三次，再选人、重排并核验实际名单。每档须连续三次完整选人通过；一次选人失败立即降一档重新计数，低档失败不给出建议。导航、准备或设备故障直接中止，先排查具体错误。
  4. 进度下方显示本次游戏画面，点击可放大。测试期间保持游戏交由程序操作；需要中止时点击“取消测试”，等待退出选人页。
  5. 完成后核对“实测建议”，点击“采用建议”才保存该档位。结果只适用于本次设备和截图、采样及页面切换时间参数；修改这些设置后重新测试。

测试结束或取消时会放弃暂选，保留原驻员。若设备断开导致清理未完成，先在游戏中返回并放弃换人。采用建议后使用手动档位，也可选回“自动”。

例如极高档第一轮通过、第二轮选人失败，测试会降到高档，从第一轮重新计数；高档连续三轮通过后，点击“采用建议”即可保存为高档。

滑动、选人或重排失败时

核对目标实例、截图与触控后端，记录失败档位、轮次、画面及日志。导航失败时检查登录和页面状态；误选或重排失败时，附上实际选中名单。

导入排班与启动校验

导入后逐项核对

  1. 排班页面支持排班 JSON、排班图片，以及从备份 ZIP 中只读取排班。导入别人的表后，先替换未持有或不适用的干员。
  2. 核对设施类型、等级、产物与岗位数。办公室、训练室、回收站的本地显示及导航顺序须与游戏布局一致；这项顺序不随排班导出。
  3. 核对主表及全部副表中的主班、每列绑组与替班，检查副表任务及触发条件。
  4. 点击“验证排班”，按错误提示修改后重新验证；校验超时时按提示重试。

持有和训练位检查

同步森空岛干员名单后，校验会检查主表、副表及换人任务中的干员。

训练室第二个位置是训练位，要求基础技能达到 7 级且至少有一项技能尚未专三。这项检查覆盖训练位主班、各绑组替班和副表换人任务；协助位沿用原有条件。

  1. 基础技能不足 7 级：先在游戏中升级至 7 级；所有技能均已专三：更换训练对象，或按用途放到协助位。
  2. 到“养成规划”页面手动点击“刷新”，同步最新干员数据，再回到排班页面重新验证。技能字段缺失或缓存无效时也使用这一入口。
  3. 提示未持有干员时，核对账号并获取或替换干员，再刷新验证；提示资源缺少森空岛 ID 时，更新资源包。

例如阿米娅被填在训练位，校验提示基础技能只有 6 级：在游戏中升至 7 级，再到“养成规划”点击“刷新”，回排班页面验证。

通过校验后仍要观察一轮

静态校验确认配置是否可行，运行时还要考虑实际心情、占床、任务预约和训练保护。先确认普通下班、替班接岗、主班入宿与回班连续正常，再开启复杂副表或专项安排。

排班表编写理论：岗位、轮休与副表

Mower 根据心情、驻员和任务状态动态调度。编写排班时确定四件事：谁工作、谁接岗、哪些人一起换班、到哪里恢复。

先确定主班与绑组

每个主班占一个岗位。需要配合技能、一起上下班的成员填写同一组名，其余成员可单独安排。为每组分别配置替班和恢复床位。

每组至少有一名普通或低优的固定工作主班决定上下班。这名干员应只绑定该组，并且属于非宿舍、非零心情工作、非候补的工作主班。宿舍跟随成员、候补和共享成员按各自规则参与换班。

三人贸易站的完整替班示例

以下各例分别演示一种填法，可按持有干员、已解锁的基建技能和设施布局调整。

岗位主班组替班
贸易站第 1 位能天使贸易一组空爆
贸易站第 2 位德克萨斯贸易一组古米
贸易站第 3 位拉普兰德贸易一组月见夜

这组下班时，空爆、古米、月见夜分别接替三个岗位，能天使、德克萨斯、拉普兰德进入宿舍恢复，需要三张可用恢复床。整组满足回班条件后，三名主班回到贸易站，替班离岗。与另一组共用替班时，安排错开的休息窗口。

替班列表填写候选干员，程序结合岗位占用、任务预约和训练保护选择当前可用的人选。

宿舍固定岗位、Free 与绑组

主表每间宿舍填满五个位置：先填具名驻员，再连续填写 Free，至少保留一个直接填写的 Free。宿管人数按实际技能和恢复需求安排。Free 与菲亚梅塔保持无绑组，菲亚梅塔的替换名单填写充能对象。

例如一间宿舍依次填“杜林、安赛尔、Free、Free、Free”，两名具名驻员均不绑组，就提供三张普通恢复床。

宿舍具名成员的替换组下班时恢复容量
非主班干员候选接替固定宿舍岗位。保留固定宿舍岗位。
同组工作主班工作主班进入该固定宿舍岗位恢复，可与宿舍主班双向互替。使用该固定恢复位。
Free宿舍成员随组离岗待命，临时开放恢复容量。在相应组状态允许时，计入绑组 Free 额度。

例如古米在贸易站、月见夜在固定宿舍，两人都填“贸易二组”，古米的替班填月见夜，月见夜的替班填古米。换班时月见夜接贸易站，古米进入月见夜的固定宿舍位置恢复，使用这一张固定恢复床即可。

另一种填法是古米的替班改为空爆，月见夜的替班改为 Free，组名仍相同。下班时空爆接贸易站，月见夜离宿待命，临时增加一份“贸易二组”的恢复额度，供古米等符合条件的成员使用；月见夜待命期间没有心情恢复。主班互替仅限同组且至少一方是宿舍成员。

普通 Free 与绑组 Free 额度

Free 额度按数量计算。需要恢复的受保护工作主班使用普通额度或自身绑组额度，高优替班使用普通额度；候补、普通替班和空闲干员可使用两类额度。分配时优先使用符合条件的绑组额度，为外组保留普通额度。

运行时按实际驻员、入住预约和本轮已安排人数计算剩余容量；静态校验计算普通额度与本组配置额度。宿管回班收回额度时，程序通过换位或安排离宿调整容量。

例如当前剩余普通 Free 额度为 2，“贸易一组”的绑组额度为 1：能天使、德克萨斯、拉普兰德这组三名普通主班可合计使用三份额度。若另组的空爆、古米、月见夜也需要一起休息，它们只能使用两份普通额度，要等普通容量增加后再下班。两组均需先备齐各自替班。

一个岗位参与多个绑组

在同一个岗位点击组旁“+”，为每个绑组分别填写不同的组名和替班。每个关联组仍须有只绑该组的普通固定工作主班决定上下班。

主班组该组替班候选
砾（同一岗位第一列）赤金一组香草、芬
砾（同一岗位新增列）赤金二组芬、克洛丝
斑点（只绑赤金一组）赤金一组史都华德
泡普卡（只绑赤金二组）赤金二组安德切尔

两个组同时休息时，砾的替班取两列的共同候选，此例为芬；史都华德、安德切尔分别接替斑点、泡普卡，三名替班都须可用。若芬已被其他任务占用，新申请休息的组等待。砾作为共享主班只占一张恢复床，零心情工作成员不申请恢复床。

每组保留独立状态。一个组回班不提前释放另一个在休组仍需的共享替班；最后一个依赖组回班后再恢复共享主班。共享宿舍成员和临时 Free 同样遵守依赖关系。共享成员或候补个人失床不召回整个组。

分床顺序与已占床保护

分床顺序为：宿舍高优先级干员 → 普通主班 → 宿舍低优先级主班 → 宿舍高优先级替班 → 休息候补 → 普通替班 → 空闲干员。同级按距各自心情上限的缺口排序，缺口较大者优先。

前四层已占用的恢复床受保护，保留到按清退、个人上限、正常回班或明确排班任务等规则离宿。同级恢复申请保持已有住员。

前四层申请者可接管候补、普通替班和空闲床位。候补可接管普通替班和空闲床位；普通替班可接管空闲床位，但这两类申请者都须有有效实测心情且不超过自身上限的 80%。普通满心情清退、个人上限强制离宿、正常回班和明确排班任务另按各自条件执行。

单回目标保留已有安排，符合条件的新高优目标可替换较低层级目标。宿舍优先级决定有效床位的选用顺序。

候补待命与升优

“宿舍休息候补干员”对符合条件的工作主班生效。需要有符合规则的正常恢复主班提供待命依据；有床则恢复，无床可离岗待命，待命不恢复心情。用尽、强制回满、固定宿舍和零心情工作配置保留各自规则，不直接按普通候补处理。

下班分床前，候补低于个人急救线会升为低优并必须取得床位；恢复途中越过急救线也不降回候补，实际回到工作岗位后才清除本轮提升。因此静态配置容量通过，运行时仍可能因升优成员需要额外床位而暂缓下班。

心情上下限与工休估算

全体设置提供默认范围，令夕及其组内规则可覆盖，指定干员设置优先级最高。上下限在 0 至 24 点内且下限小于上限；用尽以下限为目标，回满以上限为目标。

下班参考线 = 下限 +（上限 − 下限）× 心情阈值 工作时间 ≈（回班心情 − 下班心情）÷ 每小时消耗 恢复时间 ≈（回班心情 − 下班心情）÷ 每小时恢复

无自定义上下限时，下班参考线还按程序规则取整。阈值只是参考，实际下班还要求整组替班、合法床位与任务时间均可行。提高阈值通常更早申请休息，也增加周转压力。

例如给能天使设置下限 4、上限 20、心情阈值 0.5，下班参考线就是 12。假设你观测到当前组合每小时消耗 2 点心情、宿舍每小时恢复 4 点，从 20 工作到 12 约需 4 小时，从 12 恢复到 20 约需 2 小时。

估算后再留出换人、排队、跑单和充能余量。普通组按组内恢复情况回班；强制回满和组内心情差设置会改变回班时间。成员达到个人上限后可先离宿待命，等整组满足条件再回岗。

主表稳定后再增加副表

主表写日常配置，副表写特定条件下的变化。例如深海组下班后调整制造站替班，或固源岩积攒到一定数量后开始搓玉。在排班页面点击“新建副表”，命名后分别填写触发条件和需要覆盖的岗位、名单、产物。

工作、休息与空闲：怎样判断绑组下班

写条件时，先区分干员当前的三种状态。这里看的是进驻位置，和主表中给他安排了什么岗位是两回事。

状态当前位置示例在工作在休息
工作歌蕾蒂娅在控制中枢，或鸿雪在贸易站。TrueFalse
休息歌蕾蒂娅进驻任意宿舍，包括已经回满但尚未离宿。FalseTrue
空闲／待命歌蕾蒂娅离宿后等待整组回班，当前没有进驻设施。FalseFalse

训练室也算工作设施。干员只要进驻训练室，“在工作”就是 True；要判断专精是否正在进行，选择“设施状态 → 训练室 → 是否正在训练”。例如余在训练室协助，即使没有正在执行的专精，也属于在工作。

因此，要表达“深海组没在上班”，选该组只绑一个组的普通固定工作主班歌蕾蒂娅，填写“歌蕾蒂娅 → 在工作 == False”。她在宿舍恢复、回满后离宿待命，都能保持副表生效。若改写成“在休息 == True”，她一离宿，副表就会退出。

  1. 新建“深海下班”副表，点击“编辑触发条件”。
  2. 左侧选“值 → 干员属性 → 歌蕾蒂娅 → 在工作”，中间填 ==。
  3. 右侧选“值 → 常量/自定义”，填写 False，首字母大写。
  4. 在副表填写深海组下班时需要的岗位或替班，其他岗位用 Current 继承。

同理，“鸿雪下班”可写鸿雪的“在工作 == False”。“森蚺在工作 != True”也是同一种布尔判断。用来代表绑组的干员应符合工作主班规则，不要选固定宿管、零心情工作成员、休息候补或多绑组共享成员；这些成员的个人位置不适合代表整组上下班。“在工作”包含所有工作设施，若要限定原岗位，改用“当前位置”，例如鸿雪的当前位置 == room_1_1。

多个条件用 and、or 连接

and 表示两边都满足，or 表示任意一边满足。要组合条件，把编辑器对应一侧从“值”改为“表达式”，再填写里面的左右两项。嵌套层级就是括号的层级。

（结城理在工作 == True）and（娜斯提在工作 == False） （歌蕾蒂娅在工作 == True）and（薇薇安娜在工作 == True）and（阿罗玛在休息 == True）

第一种可用于“结城理副表”：结城理上班、娜斯提不上班时使用埃癸斯与虎狼丸的会客室配置；另一张“娜斯提副表”在两人都上班时改用塞雷娅与虎狼丸。第二种则确实要求阿罗玛人在宿舍，此时应使用“在休息”，而不是把所有非工作状态都算进去。

按库存切产物：高水位启动，低水位退出

先在排班页面的高级设置开启“自动切换产物与订单”，同步仓库库存，再填写主表的日常产物和副表的目标产物。条件里的“仓库资源”使用已记录的库存数量；在仓库资源选项中核对读数后，再设置启动和退出数量。

“搓玉”示例副表使用两个数量：固源岩超过 1200 开始搓玉，已经在搓玉时继续生产，直到剩余数量不超过 200。把启动数量和退出数量拉开，就能连续生产一段时间。

切入搓玉后，补满制造队列会先把固源岩转入制造站备料。每份源石碎片需要 2 个固源岩，按 99 份队列计算，一次占用 99 × 2 = 198 个。比如仓库原有 1201 个，补满队列后变为 1003 个；这 198 个已放进制造站，并非立即全部制成了碎片。“仓库资源”条件比较仓库里的数量，不包含制造站中已投入的备料，数量变化会在库存记录更新后反映到条件中。

（固源岩数量 > 1200）or （（固源岩数量 > 200）and（3-3 当前产物 == 源石碎片（固源岩）））
  1. 新建“搓玉”副表，最外层运算符填 or。
  2. 左侧选“表达式”：左值选“仓库资源 → 固源岩”，运算符填 >，右值填 1200。
  3. 右侧选“表达式”，运算符填 and。其左侧再建表达式“固源岩 > 200”，右侧再建表达式“设施状态 → 3-3 → 当前产物 == 源石碎片（固源岩）”。产物的保存值为 orirock。
  4. 副表的 3-3 保留制造站类型和原岗位数，产物选“源石碎片（固源岩）”。示例的三名主班是褐果、艾雅法拉、地灵；填写时也为他们配置可用替班，并核对与宿舍岗位的冲突。
  5. 主表的 3-3 填日常产物，例如赤金。副表退出后，恢复主表与其他生效副表合并后的目标。

设置两条库存线时，要给制造站备料留出余量。例如把启动线改成 300、退出线仍为 200，仓库 301 个时会启动，补满 99 份后只剩 103 个；更新库存后就满足退出条件，容易刚切入又切出。示例的 1200／200 留出了这部分空间。退出线 200 表示仓库余量，制造站里还可能有已投入的固源岩；多站同时搓玉时，按各站实际队列合计预留原料。

“卖玉”副表用同样结构：源石碎片超过 2000 时，把 1-1 贸易站切为“开采协力”；已经在接合成玉订单时，继续到源石碎片不超过 50。示例使用能天使、绮良、鸿雪，主表日常订单为“龙门商法”。

（源石碎片数量 > 2000）or （（源石碎片数量 > 50）and（1-1 当前订单类型 == 开采协力））

编辑时把制造站的“当前产物”换成贸易站的“当前订单类型”，右值选“开采协力”，保存值为 orundum。例如碎片为 1000、正在接开采协力订单时继续；降到 50 时退出。搓玉与卖玉分成两张副表，可分别控制原料消耗和碎片消耗。

切产物怎样执行：先切目标，再换班

主副表中的产物是生产目标；设施状态里的“当前产物／当前订单类型”是从游戏读取的状态。例如“鸿雪下班”副表目标为中级作战记录，3-1 实际还在做赤金，程序就需要先完成这次切换。

  1. 根据副表条件合并生产目标；若这次换班会改变条件，先演算换班后的目标。多张副表覆盖同一设施时，以最后生效的目标为准。
  2. 进入相关设施，读取实际产物、当前一份的制造进度、生产力与无人机数量。实际产物已符合目标的站点直接跳过。
  3. 制造站按下面的无人机设置完成当前一份，再取消后续旧计划、改选新配方，并把新队列补到仓库容量允许的最大值。贸易站直接切换接单策略。
  4. 重新读取并确认目标，再执行对应的切表与换人。换班依赖切产物时，等待期间保留原班；例如鸿雪下班会触发赤金转经验，就等当前一份赤金处理完、目标切成经验后，再完成相应换班。

制造站处理的是正在生产的这一份，不必把整条旧队列全部生产完。制造站已空闲时直接更换配方。多个制造站同时需要切换时，先巡检再统一计算无人机用量，执行前复核进度，已自然生产掉的部分会减少无人机需求。

设施可选目标执行方式
制造站赤金、中级作战记录、源石碎片（固源岩）、源石碎片（装置）。处理当前一份后改配方，再补满新队列。
贸易站龙门商法、开采协力。修改接单策略，已有订单仍按原订单交付，新订单按新策略生成。开采协力需要三级贸易站。

例如 1-1 切到开采协力后，新接合成玉订单；原有贵金属订单仍需赤金交付。切贸易策略本身不消耗无人机。生效目标或实际订单类型为开采协力时，该站退出葛朗台跑单，恢复龙门商法后再按跑单配置参与。

葛朗台切产物与无人机：带数值的例子

“葛朗台切产物”默认开启。每架无人机抵扣 3 分钟基础制造时间；程序先用整架无人机抵扣，再决定剩余零头是否值得多用一架。默认“无人机损耗容限”为 30 秒：零头达到 2 分 30 秒就再用一架，否则等它自然完成。关闭葛朗台切产物后，按完成当前一份所需的数量向上取整使用无人机。

以下“剩余时间”均指加速面板的基础时间。自然等待还要除以制造站生产力，例如生产力为 2，80 秒基础时间约需等待 40 秒。

当前一份剩余基础时间葛朗台模式，损耗容限 30 秒关闭葛朗台模式
7 分 20 秒用 2 架，余下 80 秒基础时间自然完成。用 3 架完成。
2 分 40 秒用 1 架，损耗 20 秒，在容限内。用 1 架完成。
2 分 20 秒用 0 架，等当前一份自然完成。用 1 架完成。

“切产物单次无人机上限”默认 0，表示不限制；每个制造站切换时分别应用。例如当前一份还剩 7 分 20 秒，上限设为 1，就只用一架，剩余 4 分 20 秒基础时间自然完成。这个上限在关闭葛朗台模式时也生效。

葛朗台模式下，关闭“切出源石碎片时使用无人机”，就会等当前一份碎片自然完成再切回赤金或经验；相关换班也一起等待。例如“搓玉”条件在固源岩降到 200 时退出，3-3 正在做的这一份碎片仍先完成。

“允许无人机不足时直接切换产物”默认关闭：无人机不够时，程序结合制造进度和无人机恢复时间安排复核；换班依赖切换时保留原班。开启后，可取消当前未完成这一份的进度并直接切换。例如切换计划需要 5 架、当前只有 2 架，关闭时等待，开启时允许放弃当前份进度；关闭“切出源石碎片时使用无人机”的自然等待规则仍保留。

“葛朗台切产物缓冲时间”默认 2 秒，表示当前一份预计完成后，再稍等两秒确认取消旧制造计划。日常无人机加速使用独立的“无人机使用阈值”和“无人机加速间隔”；要给切产物留更多无人机，可提高日常使用阈值。首次配置可保留默认损耗容限和缓冲时间，先观察日志里的计划用量、等待时间与最终产物。

副表顺序、Current 与名单增减

副表可以同时生效，按列表从前往后覆盖；同一岗位或产物有冲突时，后面的生效副表优先。例如“深海下班”把 3-1 设为赤金，“鸿雪下班”排在后面并把 3-1 设为中级作战记录：两张同时生效时，3-1 生产中级作战记录；只有前者生效时生产赤金。编写完成后，回主表点击“验证排班”，核对可能同时生效的组合。

Current 用于副表，继承前面合并结果的整个岗位，包括主班、组与替班。需要修改时，填写主班及完整绑定。Free 用于宿舍。

想实现的效果副表填法生效结果
沿用主表岗位主班填 Current。继承能天使／贸易一组／空爆的整套配置。
保留主班，只改替班主班填能天使，组填贸易一组，替班填月见夜。能天使仍在原岗位，该组改由月见夜替班。

普通副表的回满、用尽及优先级名单使用“增”“减”列，先增后减；留空表示继承，后面的副表仍可重新加入。救急表使用独立名单。副表可调整 Free，但最终每间宿舍仍至少一个直接 Free，恢复容量也必须可行。

例如主表“回满”名单只有能天使，副表在“增”填德克萨斯、“减”填能天使，这张副表生效后，“回满”名单变为德克萨斯；退出副表后恢复主表名单。

副表的生产设施类型与岗位数须和主表一致；切换产物或订单时，开启对应高级开关。退出副表后，程序按最终合并表和当前休息状态安排岗位。

副表配置与“编辑任务”分别何时使用

副表岗位描述生效期间的排班与替班规则；“编辑任务”填写这张副表从未生效变为生效时，要明确执行的换人安排。任务中的 Current 表示这个位置保持原驻员。只调整轮休规则或切产物时，先填写副表配置；需要切入时立即换指定干员，再填写任务。

例如“深海强制上班”，触发条件为歌蕾蒂娅心情 > 23.5，任务在中枢对应位置填歌蕾蒂娅，其余中枢位置填 Current，并在制造站对应位置填写乌尔比安、斯卡蒂、幽灵鲨、安哲拉。它在切入时生成这次换人安排；要再次触发，需要条件先变为 False，再变为 True。副表退出时，任务改过的岗位按最终生效排班恢复，仍在休息的主班按替班规则安排。

从零写表的检查顺序

  1. 按游戏布局填设施与主班，先建立简单、完整的普通轮休。
  2. 为每个组保留合格的普通固定工作主班，并为每个岗位准备不冲突的替班。
  3. 区分固定恢复位、普通 Free 和绑组额度；再核对保护住员、预约和候补升优后的容量。
  4. 需要共享时逐组填写候选，检查同时休息的交集和最后依赖组回班行为。
  5. 同步干员练度，校验持有、训练位及主副表组合；观察完整下班与回班后再增加专项功能。

“养成规划”页面管理等级、精英化、基础技能、专精和模组目标，并展示材料、龙门币及经验需求。绑定账号后点击“刷新”同步练度，再排序目标；游戏中升级、获取干员或完成专精后再次刷新。通过库存扫描更新本地材料数量。

自动化范围与训练冲突

“全自动专精”控制自动专精和养成材料自动合成。精英化、基础技能升级、模组开启与升级仍需在游戏手动完成，再同步数据。开训要求精英二、基础技能 7 级和对应材料，并核对训练位、协助路线及训练保护。

自动专精的被训练干员不能同时占用非训练室排班；出现冲突时按计划原因解除冲突，等待下一次库存扫描重新评估。训练位的基础技能和全技能专三校验也检查主副表替班和任务，见排班校验。

合成按计划顺序和本地库存备料，并保留正在训练阶段所需的材料。进度和缺料情况在计划状态中查看。

AI 助手的专精重试会重置全部失败计划，执行前核对范围。

备份、迁移与多开

导出完整实例备份

  1. 在 Mower 设置 → 配置导出与导入导出 ZIP。包含 config 原文件、主副排班及持久化 tmp 数据，例如专精计划、路线、历史和库存。
  2. 日志、资源包及其他实例数据需另行保存。
  3. 迁移时停止自动任务并等待更新结束，选择备份导入。覆盖前会生成恢复 ZIP；失败时按页面提示处理，成功后刷新配置，不自动开始任务。
  4. 当前管理端口、令牌及本机网络等设置保留，旧调度缓存清空。换电脑后重新核对设备、ADB 和 MAA 路径。

备份包含凭据，请妥善保管并通过私密方式传输。

区分任务停止、进程退出与窗口关闭

多开管理器分别管理实例名称、数据目录、端口与绑定设备。配置和运行数据按实例隔离，同一安装的程序及资源更新按共享范围生效。

“进程操作”只处理当前实例；重启续接保留已保存队列，普通重启重新安排运行缓存。结束进程会停止该实例；关闭窗口可能仍保留后台运行，具体由托盘和多开管理器的关闭设置决定。手动操作游戏前先停止自动任务。

日志、排错与 AI 助手

先定位任务和时间

  1. 确认当前实例、发生时间及具体任务，区分设备连接、软件更新、排班和 MAA 日志。
  2. 保留完整错误上下文、实际画面及对应报错归档。排班等待先读缺少的替班、恢复容量或保护条件。
  3. 需要清理数据时先备份，再从运行日志页的“数据库管理”选择对应类别；不要全选或直接删除 data.db。

配置模型后从左侧打开助手

模型配置放在 Mower 设置 → AI 助手与模型服务。DeepSeek 使用一个服务选项，可选 deepseek-flash、deepseek-v4-pro 预设，或填写官方模型 ID；本地及在线接口分别填写实际地址、模型和密钥。本地接口须兼容 OpenAI Chat Completions，在线接口须使用 HTTPS；工具调用还需服务和模型支持。

点击左侧“Mower AI 助手”直接打开对话。桌面窗口可拖动标题栏调整位置，收起保留草稿和当前会话；新对话会清空会话。Enter 发送，Shift+Enter 换行，回复期间可继续写草稿。

助手可查询 FAQ、日志与数据库，分析漏单和报错、管理专精计划，并按要求发送反馈。分析报错时选择对应归档，分析漏单时提供具体记录或完整本地时间范围。

排错建议结合日志核对后再应用。提交给模型的问题和日志需隐去密码、访问令牌及 API 密钥。

常见问题

连接失败如何排查？

核对预设、目标实例和设备状态，按页面提示检测或修复。操作步骤见设备连接。

有空床或已到心情线，为什么不下班？

下班需要整组替班和恢复容量同时可用。检查共享替班、Free 额度、入住预约及训练保护，具体规则见排班理论。

训练位导致验证失败，如何修复？

核对训练室第二个位置及其替班、副表任务。基础技能不足时在游戏中升至 7 级，全技能专三时更换训练对象；随后到“养成规划”手动点击“刷新”，再验证排班。协助位不受这两项训练位检查。具体步骤见持有和训练位检查。

如何选择性能档位？

建议先用自动档。桌面端和 Android 均可运行游戏内性能测试，从极高开始，根据选人及重排结果采用建议。见性能适配。

刷图或大型任务未运行，检查哪些设置？

周计划与大型任务独立。分别检查执行方式、当天配置、时间窗口、库存条件和独立开关，见作战配置。

白屏、数组错误或报表缺记录怎么办？

白屏时检查窗口依赖和页面加载；数组错误附完整堆栈和画面；报表缺记录时核对实例和时间范围。将对应日志或报错归档交给 AI 分析，也可附在反馈中。
