# UI Subtree Contract

Local contract for the Vue 3 frontend application under `ui/`.

## 1. Frontend State & Configuration Contracts

- **Persistent vs Ephemeral Isolation**: The configuration store (`conf.device`) persists only explicitly confirmed user selections. Selecting a detected instance saves its preset, paths, instance identity and identity verification fields before connection testing; failed readiness does not undo that selection. Manual identity edits, `last_serial` and `game_package` persist through a verified connection only. Non-identity settings (`screenshot_backend`, `touch_backend`, `recovery_timeout`, `recovery_attempts`, `recovery_local_wait`, `recovery_shutdown_wait`, `manager_query_timeout`, `simulator_hotkey`, `simulator_hotkey_delay`) persist on the user's edit. Candidate instance lists from `/device/candidates` remain ephemeral UI state.
- **Immediate Edit Payload**: An immediate save submits only the keys that one edit changed, so identity values edited in the same draft never reach the persisted profile.
- **Connection Group Placement**: The capture and touch backends render outside the advanced identity form; the recovery budget and the boss key stay with the identity fields in the advanced settings. The task checklist displays these settings directly; other device-editor callers retain their default advanced toggle. The read-only and save rules are stated in the help of the connection status tag, and the notice above the buttons carries preset-specific guidance only.
- **Label Column Width**: A device label plus its help icon needs a wider label column than the settings form's 120px default; at 120px the icon drops to a second line and every row grows taller.
- **Menu Width Follows Content**: A dropdown menu sizes to its widest option. Pinning it to the trigger width clips or shifts a longer option label.
- **Recovery Policy Binding**: Advanced recovery configuration (`recovery_timeout`, `recovery_attempts`, `recovery_local_wait`, `recovery_shutdown_wait`, `manager_query_timeout`) binds bidirectionally to backend defaults and recovery policies, without local shadow overrides.
- **ES Module Icon Imports**: `@vicons` icons come from the package's `es/` files (`@vicons/<pkg>/es/<Icon>`). The per-icon files at the package root and under `lib/` are CommonJS and render blank under the Vite 8 dev server; `no-restricted-imports` in `eslint.config.js` rejects them.
- **Target Clearance**: Modifying preset or instance selections in the UI must immediately invalidate and clear `last_serial` to prevent stale endpoint reuse.
- **IPC Backend Coupling**: Selecting MuMu IPC capture backend automatically couples the touch backend to MuMu IPC; selecting alternative touch methods disables IPC capture.
- **Bound Instance Start**: Detection starts only a selected supported instance after a stopped verdict; multiple candidates require selection. MuMu Pro may open its manager application before this check. The independent connection test performs no lifecycle actions. AVD, redroid and Genymotion requests carry the current selected instance as immediate confirmation.

## 2. Navigation Shell

- **Single Navigation Definition**: `src/navigation.js` owns page sections, labels, icons, sidebar actions and the mobile tab subset. `AppSidebar` (desktop sider and mobile page drawer) and `MobileTabBar` render from it; `App.vue` defines no navigation entries. A new page adds its route record, its `public/frontend-routes.json` entry and one navigation entry. Redirects preserve old addresses without adding duplicate navigation entries.
- **Sidebar State and Editing**: When changing grouping, placement identity, pinning, persistence or migration, apply [Sidebar Preferences](../docs/subsystems/web-access.md#sidebar-preferences) in the Arknights Mower Web Access subsystem description. When changing the fixed pinned header, scrolling navigation body, fixed footer, dragging, editor modal or page-picker confirmation, apply [Sidebar Layout and Editing](../docs/subsystems/web-access.md#sidebar-layout-and-editing). Keep `composables/sidebarPreferences.js` as the shared state owner and `SidebarEditor` as the modal editor; use the source and focused-test entry points in the [frontend development guide](README.md#修改入口与定向验证).
- **Compact App Menus**: `AppMenuBar` shares the connection, profile, view and help menus between the custom desktop title bar and browser page headers. Apply the capability-based native controls and input rules in the [Arknights Mower Desktop Window subsystem description](../docs/subsystems/desktop-window.md) when changing title-bar controls or gestures. 视图 appears between 档案 and 帮助 and provides sidebar visibility and editing actions. Hiding the desktop sidebar hides the whole sider while preserving its mounted state and drafts; the existing collapse control keeps the icon rail. Menu labels and title-bar identity text use 12px type with a 22px line height; menu triggers are 22px tall. The custom title bar remains 36px tall, with independent window-control and sidebar-icon dimensions.
- **Sidebar Versions**: When changing software version display, type language, resource labels or colors that follow event timing, apply [Sidebar Version Badges](../docs/subsystems/web-access.md#sidebar-version-badges). `SoftwareVersionPreference` and `stores/gui.js` own display preferences; `SoftwareVersionBadge`, `SidebarBrand` and `utils/versionBadges.js` own presentation. [Installed Resource Metadata](../docs/subsystems/resource-update.md#installed-resource-metadata) owns the resource API source. Branding and collapse controls follow [Sidebar Layout and Editing](../docs/subsystems/web-access.md#sidebar-layout-and-editing).
- **Route-Derived Highlight**: Each sidebar copy derives its active state from router matching (`exact-active-class`, `aria-current="page"`); copies of the current page highlight together, and no component stores a selected menu key. A mobile tab represents its own page and any entries sharing its `tabGroup`; 排班 links directly to the normal plan editor and highlights for both normal and rescue plan routes, while 设置 links directly to 全部设置. 更多 highlights only registered internal pages outside those groups; malformed paths and the catch-all NotFound page leave it unhighlighted.
- **Settings Directory Ownership**: 全部设置 uses the continuous page and directory governed by [Task Configuration](../docs/subsystems/web-access.md#task-configuration). `Settings.vue` supplies the former Mower settings panels in that tree. `/mowersettings` redirects to `/task-settings`, preserving query and hash; it does not open a separate settings modal.
- **Task Configuration Flow**: When changing the task configuration page, checklist, execution intervals, editor lifetime or legacy links, apply [Task Configuration](../docs/subsystems/web-access.md#task-configuration). `pages/TaskSettings.vue` owns `/task-settings`; `App.vue` caches only its `TaskSettings` component with `KeepAlive`. `task-workflow/TaskConfiguration.vue` owns editor selection; `TaskWorkflow.vue` owns the shared workspace, and `TaskChecklistNavigation.vue` owns its directory and search. `TaskSettingsPanels.vue` binds task and interval fields and suppresses duplicate task controls in checklist mode. `queueNavigation.js` retains backend-task-to-editor mappings. Use the source and focused-test entry points in the [frontend development guide](README.md#修改入口与定向验证).
- **Log Workspace**: The running log presents screenshot preview when available, the compact transparent task table and log output in one workspace. The screenshot and task table retain their resize controls; start/stop actions remain available in the bottom toolbar. The actual pending queue stays on the home page; the `log` route's `#task-queue` target reveals the task table. Apply the [task configuration rules](../docs/subsystems/web-access.md#task-configuration) when changing table placement, page navigation or editor retention.
- **Content-Scoped Watermark**: The watermark covers `n-layout-content` only and never overlays navigation labels.

## 3. Testing Discipline

- **Targeted Unit Testing**: From `ui/`, run only tests for modified components or utilities (e.g., `npm test -- src/utils/deviceSettings.test.js`). Use the [development guide](README.md#修改入口与定向验证) to find source and test entry points; follow the linked backend contract when the change crosses a configuration, device or scheduling boundary.
- Do not trigger full frontend build or end-to-end browser suites in rapid iteration loops.

## 4. Controlled Language

- UI labels, tooltips, and source comments adhere strictly to authoritative definitions in [CONTEXT.md](../CONTEXT.md).
- Never introduce issue tracker numbers (`#xxx`).
