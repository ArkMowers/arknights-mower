# 排班、主副表与宿舍 { #scheduling }

## 导入与核对 { #import-schedules }

1. 排班页面可导入排班 JSON、排班图片，或从配置 ZIP 读取 config/plan.json。完整配置迁移使用“配置导出与导入”。
2. 核对基建设施的位置、类型、等级与岗位数；办公室、训练室和回收站可在排班编辑器拖动交换顺序，须与游戏布局一致。该顺序用于界面显示和房间导航，只保存在本机，不随排班导出。
3. 检查主表、副表、触发条件、显式换人任务，以及对应的主班、绑组和替班。
4. 运行排班校验，按具体设施和干员修复冲突。超时或预算不足表示未完成校验，不等于所有组合已经通过。

## 主班、替班与绑组 { #main-and-replacement }

主班确定岗位身份，替班提供休息时的完整替换。一个干员可参与多个绑组；共享主班只有在各休息组都具备兼容替班时才允许同时休息，否则相关组等待。只有最后一个依赖组回班后，共享替班才释放。不要把“替班已填写”当作“当前替班一定可用”。

工作主班之间不能互填替班；同组主班互替仅在至少一方属于宿舍绑组岗位等条件成立时允许。最终以排班校验与实际任务安排为准。

## 宿舍与恢复优先级 { #dorm-management }

Free 是可动态安排休息者的位置，不等于当前已确认空床。床位分配还受实际入住、预约、个人上下限和专项任务保护约束。宿舍按分床优先级、单回位归属及心情恢复缺口安排，不使用固定“4个VIP加8个非VIP”的通用公式。

已有单回目标不因心情变化主动重排；更高优先级的新入住者可按规则接管较低优先级单回位，同级不抢占。个人回满目标可能低于24，达到上限离宿不等于立即安排上班。

## 副表、产物与岗位兼容 { #schedule-issues }

副表不能改变主表生产设施的类型和岗位数。排班高级设置中的“自动切换产物与订单”默认关闭；关闭时副表不能指定与主表不同的产物或订单目标，相关状态条件和切产物选项隐藏。普通换班、产物收取及葛朗台跑单仍保留。

主班身份、岗位和绑组没有相关变化时，副表切换优先保留休息、床位与回班状态；替班不足、预约或专精保护冲突时按实际规则等待或召回，不把退出副表理解为强制所有主班回班。

## 排班表编写理论：从岗位到轮休 { #schedule-theory }

排班表描述各岗位由谁负责、谁能替班、哪些人一起换班，以及什么条件下切换安排。Mower 根据实测心情与任务状态动态换班，不是每天按固定时刻把整张表轮换一次。编写时先让普通轮休持续运转，再加入跑单、菲亚梅塔充能和副表等专项安排。

### 主班、替班和绑组分别解决什么问题 { #schedule-design-fields }

| 配置 | 编写时要回答的问题 |
| --- | --- |
| 设施与岗位 | 房间类型、等级、产物和岗位数是否与游戏一致？ |
| 主班 | 正常工作时，哪个干员负责这个岗位？ |
| 替班 | 主班休息时，哪些候选能接替这个岗位？ |
| 绑组 | 哪些主班需要协同下班、回班，保留技能配合？ |
| 宿舍岗位与 Free 位 | 哪些岗位固定驻员，哪些随组换人或临时开放？需要恢复的人分别使用哪些床位？ |
| 副表 | 特定条件成立时，需要覆盖主表的哪些安排？ |

先按基建技能的配合关系选择主班；需要一起轮休的主班填写同一个非空组名，组名本身不代表轮休顺序。无须联动的主班可以不绑组。绑组可以跨设施；普通工作成员越多，一次下班需要同时满足的替班和恢复容量条件就越多。宿舍成员和“0心情工作的干员”不能直接按普通轮休人数计算。

替班列表是候选范围，不是把这些干员依次轮换的时间表。每次换班都要为相关岗位找到互不冲突的完整替班；把同一个干员填进多个岗位，不代表他能同时覆盖这些岗位。候选正在工作、被其他任务预约或受专精保护时，也可能暂时不可用。

### 一个三人制造站的示例 { #schedule-design-example }

假设一间三人制造站需要三名主班一起工作、一起休息。下表的甲至己是示意称呼，实际填写账号已拥有且适合对应设施的干员。

| 岗位 | 主班 | 绑组 | 替班候选 |
| --- | --- | --- | --- |
| 制造站岗位 1 | 甲 | 制造一组 | 丁 |
| 制造站岗位 2 | 乙 | 制造一组 | 戊 |
| 制造站岗位 3 | 丙 | 制造一组 | 己 |

1. 主班甲、乙、丙正常工作，丁、戊、己作为替班候选，不再填成其他工作岗位的主班。
2. 配置能容纳三名主班同时恢复的有效 Free 位，并核对实际入住、优先级和专项预约。不能只数表格中写了几个 Free。
3. 满足下班条件且替班、床位均可用时，由丁、戊、己接替三个岗位，甲、乙、丙入宿。
4. 满足回班条件后主班恢复工作，替班释放，再按宿舍恢复规则参与休息。观察下一轮是否仍有完整替班和床位。

若三个岗位都只填丁作为替班，就无法同时替换整组。多个组共用丁、戊、己时，也要检查休息窗口是否重叠；顺序可用不等于同时可用。

这个示例使用普通工作主班与非主班替班。当前也支持宿舍绑组、同组主班互替和多绑组，床位需求需按下面的对应关系另算。

### 宿舍绑组：固定互替与临时 Free { #schedule-design-dorm }

宿舍中的具名干员也可填写组名，随同组工作成员换班。宿舍成员本身不作为普通下班、用尽或回班计时的依据，也不因随组离开宿舍而额外申请一张恢复床。该组必须有可轮休的非宿舍成员，多绑组还须满足下一节的单绑组成员要求。

| 宿舍「替换」的写法 | 组下班时的效果 | 恢复容量怎么计算 |
| --- | --- | --- |
| 填写非主班干员 | 由候选接替宿舍固定岗位；按已知心情从低到高选择，已在该岗位者可保留。 | 仍是固定岗位，不能把换下宿舍成员的原位另算成 Free 床。 |
| 填写同组工作主班 | 工作主班可入住这个固定宿舍岗位并恢复；也可与宿舍主班双向互替。 | 已在固定岗位恢复的工作主班不再重复申请动态床，该岗位也不开放给任意休息者。 |
| 填写 Free | 宿舍成员随组离岗后，该岗位临时开放为动态恢复床；回班关闭时重新安排其住客。 | 仅在对应组状态允许开放时增加有效床位，不能当作永久空床。 |

例如，以下两名主班属于同一个“互替组”，甲是工作干员，乙原本在宿舍：

| 岗位 | 主班 | 组 | 替换 |
| --- | --- | --- | --- |
| 办公室岗位 | 甲 | 互替组 | 乙 |
| 宿舍固定岗位 | 乙 | 互替组 | 甲 |

满足换班条件时，乙去办公室接岗，甲进入乙的固定宿舍岗位恢复；回班时交换回来。两人的主班身份不变，甲使用固定恢复位，无须再占一张 Free 床。实际干员须适合对应设施，并满足完整匹配、预约、个人心情限制和训练保护。工作主班之间互替、跨组互替和自身替班仍不允许；宿舍主班之间互替不会减少同组工作成员所需的恢复容量。

若改用临时开放方案，可以让甲的替换为非主班丙，乙的替换为 Free。组下班时丙接办公室，乙离开固定岗位待命，该宿舍位置临时用于恢复。乙离岗待命不恢复心情，不额外占恢复床；这与上面的固定互替是两种不同写法。

主表每间宿舍填写完整五个位置，至少保留一个直接填写的 Free，且这些 Free 连续排在具名驻员之后；只有宿舍替换中的 Free 不能代替这项主表要求。当前不强制每间固定配置两名宿管，恢复速度取决于实际技能组合。Free 本身和菲亚梅塔不能绑组；菲亚梅塔的替换名单用于充能对象，不是普通宿舍替班。

### 多绑组：每组分别填写替班 { #schedule-design-bindings }

同一主班仍只占一个配置岗位。点击组旁的“+”新增绑组，在每个绑组内分别填写组名和替换；不要在多个岗位重复填写同一主班。该岗位的各个组名必须非空且互不重复，每个绑组都要有替班。每个关联组至少有一名只绑该组、需要轮休的非宿舍工作成员，负责该组的心情与回班计时；共享成员不参与这些计算。

例如甲共享给 A、B 两组，乙只属于 A 组，丙只属于 B 组。下面甲的两行是**同一个岗位中的两个绑组**：

| 工作主班 | 组 | 该组替换候选 |
| --- | --- | --- |
| 甲（同一岗位） | A | 己、庚 |
| 甲（新增绑组） | B | 庚、辛 |
| 乙 | A | 丁 |
| 丙 | B | 戊 |

A、B 同时休息时，甲的共同候选只有庚；还需丁、戊等其他岗位替班均可用，且不能重复占岗。若两列没有共同可用候选，新申请休息的组等待，不能简单把两列候选合并使用。甲需要恢复时只占一张床；甲若配置为 0 心情工作则不占恢复床，仍须满足共享岗位的替班兼容条件。

某组回班时，仍保留其他休息组需要的共享替班，最后一个依赖组回班后才恢复共享主班。共享宿舍成员也遵守逐组兼容关系；多个依赖组使用同一临时 Free 时，该床保持开放直到最后一个依赖组回班。

### 心情阈值、上下限与回满 { #schedule-design-mood }

在“设置心情上下限”中，全体设置提供统一范围；令夕及其组内规则可覆盖全体设置，指定干员设置的优先级最高。未自定义时沿用程序的自动规则。下限必须小于上限，范围在 0 至 24 点内。“需要用尽心情的干员”按适用下限安排用尽，“需要回满心情的干员”以适用上限为恢复目标，不一定是 0 和 24。

普通下班参考线按上下限区间折算，未自定义上下限时程序还会取整。例如下限为 0、上限为 24、心情阈值为 50%，参考线为 12 点：

```text
下班参考线 = 心情下限 +（心情上限 − 心情下限）× 心情阈值
```

这只是阈值换算，实际下班还受整体心情、组状态、替班、床位和任务时间约束。调高阈值通常会更早申请休息，也会增加床位和替班压力；调低则减少工作余量。“宿舍高优先级”影响分床与单回安排，不直接让某组先下班。

普通组的回班不必等所有人恢复至上限；要求回满的成员和“组内心情差距过大时延后回班”等设置会改变回班时间。全体上限用于确定回满目标，不会仅因此强制留空宿舍；个人设置及令夕规则的强制离宿仍生效。不要把“达到上限离宿”理解为立即回到工作岗位。

### 分床优先级与休息候补 { #schedule-design-priority }

当前分床顺序为：宿舍高优先级干员 → 普通主班 → 宿舍低优先级主班 → 宿舍高优先级替班 → 休息候补 → 普通替班 → 空闲干员。同级比较距各自心情上限的缺口，缺口更大者优先；有效床位、预约与已有入住保护仍需满足。优先级决定分床和单回机会，不直接改变下班顺序。

“宿舍休息候补干员”有床时恢复，无床或被更高优先级接管后可离岗待命，需要有正常优先级主班在休息。绑组候补随组回班，未绑组候补随下一批回班；低于个人急救线后升为低优并保床。待命不恢复心情；用尽、回满、固定宿舍和 0 心情工作干员不适用。

“宿舍优先级排序”默认按 1→2→3→4 的高优位，再安排各宿舍低优位，也可把低优位插入顺序。它决定选用哪些有效床位，不增加床位数量；每间最前面的有效 Free 位作为高优位，不能固定认定为某个物理编号。副表留空继承此前顺序，改变生效顺序时可重新分床，日常不会仅因心情变化反复搬床。

### 估算工休比与周转能力 { #schedule-design-cycle }

在要求回满、工作与恢复速率近似稳定的假设下，可用心情变化估算一轮工休时间。设上限为 U、下班心情为 H，工作每小时消耗 d 点，宿舍每小时恢复 r 点，且 d、r 均大于 0：

```text
工作时间 ≈（U − H）÷ d
恢复时间 ≈（U − H）÷ r
工休比 ≈ r ÷ d
```

例如 U=24、H=12、d=1、r=2，则工作约 12 小时、恢复约 6 小时，工休比约 2:1。这里的速率仅用于演示；实际消耗和恢复受技能、设施与宿舍配置影响，应从自己的运行记录核对，不能直接套用为固定时间表。

- **检查替班覆盖时间：**主班休息期间，替班必须有足够心情持续工作；主班回班后，替班也要有机会恢复，才能覆盖下一轮。
- **检查床位占用时间：**估算各组何时入宿、占几张床、何时释放。长期没有空余恢复容量，或多个大组集中下班时，即使所有人都填了替班，也可能排队等待。
- **检查技能组合：**替班效率、组内心情消耗差异和宿管恢复能力都会影响长期收益；不要只比较主班在岗时的加成。

以上估算不包含换人耗时、排队、跑单与充能等事件。先观察至少一轮完整的下班与回班，再调整心情阈值、组规模或替班名单；一次校验通过不能证明长期周转没有瓶颈。

### 主表稳定后再增加副表 { #schedule-design-backups }

主表是日常基准，副表是在条件成立时覆盖部分安排，不是必须手动轮流启用的第二班。先确认主表能独立轮休，再为确有需要的场景添加副表，填写触发条件并核对覆盖范围。多个副表可能同时生效，后面的覆盖会影响前面的结果，应验证组合后的最终安排。

副表岗位选择 Current 表示继承前面合并结果的**整个岗位**，包括主班、绑组和替换，不是保留游戏此刻驻员；不能靠在 Current 后填写组名或替换来局部覆盖。要修改某岗位的替班，需明确填写该岗位主班及完整绑组、替换。主表不使用 Current，Free 只用于宿舍。副表可增减宿舍 Free 位，仍须保证每间至少一个直接填写的 Free，以及最终恢复容量可行。

普通副表的回满、用尽及宿舍优先级等干员名单分为“增”和“减”：先加入增列，再移除减列，后面的副表可以重新加入。留空表示继承此前结果，不是清空名单。例如要让甲在某副表生效时不再要求回满，在“需要回满心情的干员”的减列填写甲；副表退出后按主表和其余生效副表重新合并。独立救急表仍使用单列名单。

副表仍需完整的替班与床位覆盖，也不能改变主表生产设施的类型和岗位数；切换产物或订单还需启用对应高级设置。退出副表后重新依据主表和其余生效副表安排，不保证所有主班立即回岗。

主表页面的“验证排班”会检查主表及可能同时生效的副表组合，而非只看当前编辑的一张表。预算不足时提示未完成，不能当作验证通过。验证通过也不代表启动时替班一定空闲或能长期持续周转，仍需观察实际换班。

### 从零写表的检查顺序 { #schedule-design-checklist }

1. 按游戏实际布局填写设施、等级、产物与岗位，再填主班。
2. 按技能配合设置普通绑组，为每个需要轮休的岗位准备可用替班，先避免复杂共享。
3. 填满宿舍五个位置并保留连续 Free；按普通动态床、宿舍固定互替和临时开放床分别核算恢复容量，再调整分床及床位顺序。
4. 核对心情上下限、回满和用尽名单；“0心情工作的干员”只填写确实适用的干员。
5. 验证主表，再逐个添加副表、跑单、充能与专精相关安排，重新验证受影响的组合。
6. 启动后核对实际驻员、心情变化、下班替换、入宿和回班，稳定后导出备份。
