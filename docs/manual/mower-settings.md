# 基建、日常与排班高级设置 { #Mower-settings }

## 邮件、签到与线索 { #email-notification }

在“邮件提醒”配置账号及 SMTP，使用“发送测试邮件”验证。收件人列表为空时发给自己；删除空白项，不要保留一条空字符串。QQ 邮箱使用授权码，自定义邮箱按服务商要求选择 SSL/TLS 或 STARTTLS，勿向助手提供密码或授权码。

“每日任务”按需选择森空岛及游戏签到等项目；森空岛账号、库存与干员数据同步按对应页面配置。基建设置中的“线索收集”和赠送选项控制会客室任务，好友和信用任务按各自入口选择执行方式。

## 跑单、无人机与产物 { #order-running }

按实际排班配置跑单干员、房间与无人机使用方向。葛朗台跑单与葛朗台切产物分别配置；关闭自动切产物不会关闭普通跑单。启用切换时核对无人机和损耗设置，避免把切产物等待误当作连接故障。

## 下班与回班 { #mood-threshold }

达到心情阈值后还需有效观测、完整替班匹配和可用恢复床位。用尽下班使用有效消耗速率，不保证固定提前两三小时。心情卡牌预估辅助筛选，不能当作实测回满或确定的恢复结束时间。

“组内心情差距过大时延后回班”比较参与计时成员的最晚与最早预计恢复完成时间，默认阈值60分钟，并受额外等待上限约束；不是固定心情点差。

## 宿舍不养闲人与分床顺序 { #dorm-optimization }

“宿舍不养闲人”只控制普通满心情清退任务。关闭后仍安排恢复、补床和优先级接管，个人及令夕上限仍生效。主表与副表可设置宿舍优先级顺序，留空按当前规则处理；更换宿舍布局后核对相应设置。

## 自动救急 { #emergency-threshold }

在 Mower 设置 → 基建设置开启“自动救急”，通过旁边“救急排班”编辑独立主表和副表。默认关闭；初始化发现多组主班低于各自救急线、仍有人等待休息且普通轮休无法安排时才接管。双方副表生效后的工作设施类型、等级和产物必须一致。

救急冻结正常副表，驻员、跑单、宿管和菲亚梅塔按救急表配置，未配置专项任务不自动继承正常表。正常排班可以接回周转时退出，仍需恢复的组继续休息，不要求所有组回满。开关不随正常排班导入导出。

## 菲亚梅塔充能 { #phalanx }

配置菲亚梅塔的宿舍位置、充能对象及相关阈值，充能期间保留专项任务和床位保护。自动救急使用救急表自己的配置；存在主班等待床位时，菲亚梅塔按救急分床规则让床。调整前先核对当前生效排班和具体日志，不把普通宿舍补床当作充能任务。
