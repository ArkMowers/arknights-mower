# Garrison Simulation

The long-task editor offers personal quick simulation with three wins per strategy for a gold medal or six for the plated medal. Mower opens the rightmost terminal tab and the activity's open simulation entry. When the team lobby offers matchmaking, Mower switches to personal simulation and waits for its quick simulation or reconnect button. While the lobby controls are loading, Mower recaptures the screen for up to twelve seconds until it can identify an eligible action. Before reconnecting, Mower checks the personal simulation label and the highlight on its side of the mode selector. An unreadable selection or a highlighted team mode leaves the match pending for manual review. The solver checks for quick simulation before processing the match.

## Gameplay and device ownership

On first use Mower retrieves the Python script and tile layout directly from [GarrisonFarm](https://github.com/UnknownGlyph/GarrisonFarm/tree/fd373c9b1ab1e8fbb52ad78b8da4c461ab325abb). The [adapter](../../arknights_mower/solvers/garrison/upstream.py) verifies both files against pinned SHA-256 digests and stores them under the shared instance-data root in `downloads/garrisonfarm/<revision>/`. A verified cache supports offline use. The Mower distribution contains the adapter. Each session initializes separate upstream gameplay state and uses the low-requirement preset team profile.

When a match screen is unconfirmed, Mower captures fresh frames for up to fifteen seconds. If the screen is recognized but a required button, tactical decision option or theme label is unreadable, Mower rechecks it for up to eight seconds where no step-specific limit applies. Mower requires the matching screen and its control before tapping, and confirms the quick simulation mode and start button before saving a pending start. The scheduling deadline and user stop can end the recheck early. If recognition remains incomplete at the end of the wait, Mower preserves unfinished progress and hands the device back to the scheduler.

The script reads 1920 × 1080 frames through Mower's recognizer and OCR engine. The deployment cost icon identifies battle frames when the kill counter replaces the round label. Taps and swipes use the current device. Dragging a unit across multiple frames uses Android pointer events on that same ADB connection. The scheduler keeps control of the worker throughout the task. The [long-task dormitory rules](base-scheduler.md#long-task-dormitory-maintenance) govern admission. Each new match requires at least twelve minutes before the scheduling deadline. The solver checks the budget after settlement and immediately before starting a match, so navigation time and changes to the base queue count against the available window. A saved match can resume when at least nine minutes remain before the next deadline. The same budget applies when an ordinary dorm release can be deferred. After squad confirmation, Mower waits up to sixty seconds for gameplay or settlement while the opening animation and operation title play. The same sixty-second window applies when entering the event lobby from the terminal, starting or reconnecting to a simulation, confirming a battle replay, returning from settlement to the lobby, or waiting for an unrecognized loading screen after battle. The first actionable screen ends the wait. User stop and the scheduling deadline still interrupt either transition. An active match can continue past twelve minutes while its scheduling window remains open. When the game reports that a battle timed out and will be replayed, Mower confirms the replay once per observed round and waits for the match to resume. Handover releases a held touch, closes the game and invalidates the cached scene. The next entry uses the game's saved match when available. If reconnect opens difficulty selection, Mower returns to the lobby once and checks the active mode and entry again. A second diversion to difficulty selection ends the attempt with progress retained. Reconnect also recognizes the tactical decision and readiness prompts. Acting on either prompt requires quick simulation confirmation. Mower records a pending start before tapping the start button and confirms the match when it observes an in-match quick simulation screen. For a pending start, the selected personal lobby may instead show both `极速模拟` and `独立模拟`. With both new-match controls visible and no reconnect or abandon prompt, Mower can start again using the full twelve-minute budget. If the saved match contains only the active phase, Mower confirms the personal new-match controls on a fresh capture before using the same twelve-minute budget. A reconnect entry on the fresh capture takes priority. A record containing round progress still requires the reconnect entry.

## Shop theme

The shop reader uses the card layout of the default theme `卫戍协议终端`. At entry, Mower waits up to twelve seconds for the wrench icon in its lobby position before opening `更换主题` and reads the equipped theme from the panel title and `已设置` button. If a change is needed, it saves the original theme in the account and device progress record before applying the default. Gameplay starts after the panel confirms the selection. An already settled match can be recorded before the next visit to the lobby.

When base work interrupts farming or the current window ends, Mower retains the default theme and the original theme record. The next eligible window resumes the unfinished goal. Unlimited level farming also keeps the default theme across windows. When the goal is reached, Mower restores the recorded theme and verifies the equipped label before clearing the record. If restoration is interrupted, the next eligible window can finish it even after reaching the goal. An unreadable theme leaves the original name in the progress record for the next eligible window.

## Strategy progress

For medal farming, Mower checks the badges on one grid frame before opening cards. A gold or colored badge skips the card for a three-win goal. Only a colored badge skips it for a six-win goal. Mower scrolls past marked cards to look for a candidate. If that search finds none and at least one card was skipped for its badge, Mower scans back through all visible cards and reads their panels regardless of badge appearance. Level farming can select a marked card immediately.

Mower reads the completion banner after recognizing the open strategy panel. For medals, Mower uses the first usable win count and retries an unreadable panel for up to four seconds per card. A blank banner can indicate zero only for a recognized strategy. A lower reading preserves the recorded wins. A readable positive count can guide selection even when the name is unknown. Only a recognized strategy contributes to the per-account, per-device progress record. The results screen counts attempts. On the first settlement of each match Mower submits the result frame to the instance screenshot archive under `garrison_result` before tapping the return button. Medal completion requires observed counts for all strategies in the season.

Stopping a run or failing to recognize the game screen hands the device back to the scheduler. The same worker skips repeat dispatch while the next base task and daily execution period remain the same. A new eligible idle window or a new worker can resume the saved match with its recorded progress. The editor displays the last error until the next attempt. Saved failures from earlier versions also resume automatically. The editor offers `重新核对并继续` for an explicit recheck. Rechecking clears the observed victory cache and keeps the pending match. Changing the target preserves observed wins. See the [focused tests](../../arknights_mower/tests/garrison_tests.py) for progress, admission and handover cases.

## Match-count goal

For level farming the long-task editor accepts a target number of settled matches. Zero allows continued play in eligible idle windows. This mode accepts an already decorated strategy. Both wins and losses count when the simulation result offers a return to the lobby. Mower saves the count before leaving that result. Reconnecting to an unfinished match or observing the same settlement twice adds no extra match.

Changing the match limit retains the recorded count for the current device and account. Reaching a positive limit ends the task and skips future dispatch until the user increases the target or starts a fresh count with `重新计数并继续`.
