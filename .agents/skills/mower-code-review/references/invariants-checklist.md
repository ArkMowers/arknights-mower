# Arknights Mower Invariants & Standards Checklist

Checklist for evaluating pull requests and git diffs under the Standards axis of `mower-code-review`.

Use the entries relevant to changed call paths. Follow each owning contract for full conditions, limits and ordering; the questions below identify evidence to inspect.

---

## 1. Universal Hygiene & Resource Contracts (All Subsystems)

- [ ] **Shared Logger**: Do application log calls follow the [shared logger rule](../SKILL.md#shared-logger), including import-cycle handling and the documented offline-analysis and output-channel exceptions?

- [ ] **Zero Issue Numbers**: Does changed text follow the [root execution constraints](../../../../AGENTS.md#4-global-execution-constraints)?
- [ ] **Monotonic Deadline Budgets**: Do process, socket and polling callers honor their deadlines through failure paths? See the [resource lifecycle contract](../../../../CODING_STANDARDS.md#3-concurrency--resource-lifecycle).
- [ ] **Guaranteed Compensation**: Does each acquired resource reach cleanup on completion, failure and shutdown? See the [resource lifecycle contract](../../../../CODING_STANDARDS.md#3-concurrency--resource-lifecycle).
- [ ] **Bounded Memory**: Do actual collection producers enforce capacity and eviction? See the [cleanliness contract](../../../../CODING_STANDARDS.md#4-code-cleanliness--smells).
- [ ] **Controlled Language**: Does changed prose use the [domain glossary](../../../../CONTEXT.md) and its [Chinese mirror](../../../../CONTEXT.zh.md)?
- [ ] **Scope**: Does the review cover the actual requested comparison, including staged, unstaged and untracked files for worktree requests? Are production callers and affected tests inspected?
- [ ] **Record Ownership**: Are same-topic repairs, tests and incidental simplification recorded under the existing decision, with any independent record justified by [ownership rules](../../../notes/AGENTS.md#1-record-ownership)?
- [ ] **[Concept Impact Review](../../../../CODING_STANDARDS.md#concept-impact-review)**: Does the review identify changed names, meanings, boundaries or relationships, or justify why they are unchanged? Does any glossary diff have exact [root approval](../../../../AGENTS.md#4-global-execution-constraints)?
- [ ] **Verification Evidence**: Are structural gate results, real behavior tests and semantic review conclusions separate? Does evidence support implementation status independently of Git commit status?
- [ ] **Migration and Policy Coverage**: Do changed paths or defaults account for their consumers and shipped installation layout under the [verification workflow](../../../AGENTS.md#4-verification-and-reporting)?
- [ ] **Targeted Verification Only**: Are executed tests focused and hermetic under the [root constraints](../../../../AGENTS.md#4-global-execution-constraints) and [verification discipline](../../../../CODING_STANDARDS.md#5-verification-discipline)?
