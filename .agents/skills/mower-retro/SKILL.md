# Mower Retro

## 输入与输出

输入为用户指定的编码会话或 PR 交付过程及其原始记录；未指定时使用当前会话。PR 链接用于定位最终改动和正文，初稿、修订过程、相关会话及当时的指令用于还原交付经过。输出为按影响排序的环境改进建议，说明会话证据、成因、最小改进、维护位置和验证方法。默认交付只读报告。

## 复盘流程

1. **确定范围。** 读取 [Arknights Mower Agent 工作流程](../../AGENTS.md#1-task-selection)，确定本次复盘与已有授权的范围。使用当前对话、用户提供的材料或宿主可读取的指定会话记录；只查找与该会话有关的内容。报告采用[项目文风规范](../mower-prose-standard/SKILL.md)及其术语来源。

2. **还原关键经过。** 从用户要求、实际命令与输出、改动和评审反馈中定位找错入口、返工、误判、遗漏或重复读取。将已观察的问题与待确认的原因分开。复盘 PR 时对照首次交付、用户或评审反馈与修订稿，定位事实何时丢失、补充依据及发布前检查覆盖。当前源码、最终正文、作者自述和成功状态不能单独证明先前执行过某一步或遗漏原因；原始记录缺失时说明缺项，缩小结论范围。

3. **核对当时的环境。** 检查问题涉及的导航、规则、脚本和 CI。以会话使用的版本、比较范围和工作目录解释结果；必要时用 `git show <commit>:<path>` 读取旧版。已有改进能解释旧问题时，说明它已被覆盖。只有当前文件可读时，保留版本差异的不确定性。

   分别核对指令是否被访问、内容是否完整可见、条件是否被正确判断、关键事实是否在交接中保留，以及发布前检查能否发现遗漏。工具记录显示读取了 skill，只能证明访问；作者对原因的解释需与原始材料和实际产物相互核对。将现有要求未落实与规则或流程缺口分开，再判断需要修复入口、条件表述、交接或完成标准中的哪一处。

4. **选择改进方向。** 按下表检查与已观察问题相关的维度。先检查已有机制的覆盖和执行情况，再决定补充或调整什么。

   | 维度 | 判断与项目入口 |
   | :--- | :--- |
   | 导航 | 是否反复绕路查找实现、调用者或测试？检查[后端源码地图](../../../arknights_mower/README.md)或[前端开发指南](../../../ui/README.md)，修复发生问题的入口指针。 |
   | 自动检查 | 检查能否发现错误，是否执行且结果可信？先读[检查入口](../../../scripts/README.md)、项目配置和 `.github/workflows/`；机械违规交给已有检查器、lint 或 CI。权限、依赖和比较范围错误分别归因。 |
   | 编码规范与评审 | 业务判断是否缺少明确的输入、结果或失败边界？[Arknights Mower 项目编码规范](../../../CODING_STANDARDS.md)规定共享行为、资源和验证要求，具体业务规则由所属子系统说明维护。实施前读取受影响规则，评审继续核对真实调用者与失败路径。 |
   | 入口指令 | `AGENTS.md` 是否重复详细规则、缺少读取条件或引入无关步骤？保留执行边界，将细节放回责任文档，通过条件指针访问。 |
   | 工具成本 | 是否重复搜索、整份读取或输出截断？按实际工具记录缩小范围；缺少耗时或 Token 数据时，说明可观察的重复工作。 |
   | 无效指令 | 哪些要求引入无关步骤或产物？提出删减或澄清候选，用相同任务比较；一次未使用不足以证明应删除。 |
   | 信息访问 | 判断缺少哪些日志、版本、测试或配置？优先提供本地只读入口；新增外部访问沿用用户授权。 |

5. **筛选并交付。** 优先保留能减少重复失误、又有证据支持的少量建议。每项写清具体观察及来源、实际影响、成因或待确认假设、最小调整与维护位置、验证场景及主要代价。找不到足够证据或现有机制已覆盖时，明确说明结果，不为凑数量增加规则。

## 验证与后续落实

验证建议使用原失败类型和一个正常场景，观察入口是否选对、错误是否被发现或返工是否减少。复用已有脚本和定向离线测试；结构检查、行为验证和语义判断分别报告，测试命令本身不代表已执行。执行范围与检查入口沿用[项目验证流程](../../AGENTS.md#4-verification-and-reporting)。

落实建议沿用已有授权与任务流程。导航、规则和文档调整复用现有责任位置；长期独立决策按[记录归属](../../notes/README.md#record-ownership)判断是否需要记录。涉及领域概念时按[概念影响复核](../../../CODING_STANDARDS.md#concept-impact-review)处理，实际术语表修改遵守[根指令的明确批准要求](../../../AGENTS.md#4-global-execution-constraints)。复盘调用本身不增加记录、编号或生命周期步骤。

## 完成

每项建议均能追溯到指定会话或 PR 交付记录，已核对相关现有机制，并有维护位置和可执行的验证方法。资料缺口与未验证效果保持明确；只读复盘以报告结束。

[评估用例](evals/evals.json)检查会话证据、检查复用和资料不足时的结论范围。评估输入与预期结果分别提供给隔离执行者和评估方，运行产物保存在 skill 目录外。
