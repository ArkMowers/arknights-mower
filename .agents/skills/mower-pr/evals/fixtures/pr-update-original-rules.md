# 修改前的写作资料

这些文档是评估提供的修改前输入，用于核实旧规则和模板的实际内容。

## 修改前的 mower-pr 指令

```markdown
---
name: mower-pr
description: 为 Arknights Mower 编写或更新中文 PR 标题和正文，从实际问题、最终变更和验证证据组织说明，并简短记录适用要求。仅在准备或更新 PR 说明时使用；代码评审与实施沿用对应项目工作流。
compatibility: 依赖 Arknights Mower 仓库及其契约，是项目本地 skill；文档链接相对仓库布局解析。

# Mower PR

输入是用户需求、实际 diff、验证结果和已有 PR。输出是中文标题和正文。复用本次实施与评审记录，沿用[项目工作流](../../AGENTS.md#1-task-selection)；发布、推送和合并按用户已有授权执行。

## 工作流

1. 确认需求与比较范围。分支用实际 base 和 head；工作区包含暂存、未暂存及范围内未跟踪文件。读取最终 diff 和已有 PR，再按受影响行为读取[根指令](../../../AGENTS.md)、[编码标准](../../../CODING_STANDARDS.md)及所属契约。完成时能区分已提交内容与准备提交的修改。
2. 先提取事实：什么条件触发问题、原来发生什么、现在如何处理、什么证据支持变化。每项主要改动都要有这些事实，文档或工具改动说明读者或使用者实际获得什么。从 diff 和已有记录补齐事实，标题和开头直接描述最终结果；标题沿用仓库的类型与范围写法。
3. 按审阅价值选择结构，再使用[正文骨架](assets/pr-body.md)。小改动用改动与验证两段即可；多项独立变化用条目；跨组件时序、状态或职责变化用图或短 diff。Before/After 用于展示同一场景的实质差异。影响与回退用于说明具体兼容风险、数据迁移或操作后果，写清代码回退与状态恢复的关系。保留有信息的栏目。
4. 整理证据。依照[验证与报告规则](../../AGENTS.md#4-verification-and-reporting)，写实际命令、结果、对应版本和覆盖行为，同一次检查集中写一处。验证段用“已检查的结果 + 待验证的行为”交代证据范围，读者据此判断验证进度。已有旧版代码或文档可以说明原行为；缺少旧版运行记录时说明依据。评审后补做的测试保留在验证段，注明结果来自补做后的版本。
5. 留下简短可追溯的要求记录。记录实际使用的指令版本，以及影响本次实现、验证或表达的要求，采用“来源 + 已发生的动作”，引用上文已有证据。未提交规则或临时用户要求保留必要原文或差异。规则本身发生改动时，分别定位执行依据与修改后的规则。
6. 回读成稿，将证据排除句改成具体结果或待验证行为，例如“结构检查不代表启动通过”改成“结构检查通过；Windows 启动待实测”。同一缺口只写一处。合并重复事实，保留条件、时序、例外和失败后果。更新已有 PR 时保留仍有效的证据，围绕最终方案重写标题和正文。

## 文风

采用[项目文风规范](../mower-prose-standard/SKILL.md)和[术语来源](../mower-prose-standard/references/mower-terminology-guide.md)。用具体主体和动作表达事实，证据缺口集中写明待验证的行为。一段表达一个主要意思；命令、字段、数字和正式术语保持准确。

行为示例：“切换实例后，连接测试可能继续使用旧地址。现在切换时立即清空 `last_serial`，连接失败时保留用户保存的实例。”

验证示例：“离线测试覆盖旧地址清理和失败后保留实例，8 passed。真实设备连接待实测。”

工具或文档验证示例：“评估 JSON 解析通过，`git diff --check` 通过。三个生成场景待执行。”

## 完成条件

读者能从开头理解问题与结果，每项验证结论有依据，必要要求有来源与证据，实际风险和待验证行为清楚。模板提示已替换或删除，篇幅与变更相称。发布前将仓库路径转换为相应提交的可访问链接；草稿请求以交付标题和正文结束。

[评估用例](evals/evals.json)用于独立比较行为修复、小文档改动与技能新增说明。执行者只获得请求和必要输入，期望结果交给后续评估；中文文风由用户判断。
```

## 修改前的正文模板

```markdown
## 改动

〈用一段话说明触发条件、原有问题和修改后的行为。多项独立变化可列条目。〉

〈图、短 diff 或 Before/After 有助于审阅时，选择一项展示关键差异。〉

〈需要解释方案依据时，按行为名称直接链接所属契约或决策。〉

## 验证

〈写实际命令、结果、对应版本和覆盖行为；同一次检查写一处。〉

〈证据缺口集中说明待验证的行为；证据齐全时删除本行。〉

〈有具体兼容风险、数据迁移或操作后果时，补充影响与回退。〉

依据：〈简短记录实际使用的指令版本和影响本次改动的适用要求，链接来源与上述证据。需要多条时列条目。〉
```
