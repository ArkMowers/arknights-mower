# 完整 PR 交接评估

[评估定义](evals.json)的完整交接场景复用原始材料，分别测试数据修复、场景计时和简单文档改动。按修改前的 skill 快照与候选版本运行相同任务，版本依赖分别固定；预期结果只提供给评估方。

每个场景按以下顺序使用三个互不继承上下文的执行者：

1. **整理者：** 接收自然任务请求、完整原始材料、最终 diff 和指定版本的写作规则，生成交接材料。候选版本使用[交接模板](../assets/pr-handoff.md)，基线按其原流程整理。
2. **写作者：** 只接收该版本整理者的交接、最终 diff、自然任务请求和指定规则及依赖，生成标题与正文。原始讨论和评估预期留在该阶段之外。
3. **最终复核者：** 接收共同原始材料、交接与成稿，按指定规则核对事实依据及遗漏，保存发现与修订稿。候选版本在交接表标明正文落点。

发布阶段使用实际 CLI 检查修订后的 JSON，再以相同检查核对模拟远端回读 JSON；比较标题正文与 head，保存结果。全部使用本地模拟产物，评估不发布远端 PR，也不运行给定材料中的业务测试。

产物进入 skill 外部的评估工作区。各运行的 `outputs/` 保存交接、初稿、复核发现、修订稿与发布检查记录；逐项记录事实在各阶段的保留或遗漏，分别报告程序检查和语义复核。耗时与 Token 只采用宿主提供的实际记录。

另将[给定遗漏反例](fixtures/handoff-omissions.json)交给复核阶段，确认未提交数据修复、错误证据版本、缺少计时关系和不完整回退条件能够被发现；反例不提供给整理者或写作者。正常小改动保持简短。结果不足时定位失败阶段，沿用原失败场景复验。
