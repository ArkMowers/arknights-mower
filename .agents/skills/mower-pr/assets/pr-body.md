## Summary（改动与方案）

Changelog: 〈用一句自然短句交代被修改的功能或维护对象，以及新增的能力、解决的问题或具体要求；信息取舍按共享 Changelog 规则执行。〉

**问题与方案：** 〈承接首段，说明原问题、原因和主要方案，不重复摘要。没有发布说明时，先交代最终变化。文档要求写明具体格式、内容或操作。关系图或短 diff 紧接方案放置。〉

**方案与取舍：** 〈用明确的主语和动作解释方案，新出现的对象同时交代用途与本次变化。后续句子按实际关系衔接。有序步骤用编号列表，同层要点用项目列表，解释或因果用自然段。〉

**方案关系：** 〈输入与多项输出、组件职责或步骤依赖需要说明时，紧邻方案放置多行关系图。纯文本图使用 text 代码块，以缩进、分支线和箭头表示已核实的对应与依赖；保留已有图仍有效的必要节点和结构，并校正文字。不需要关系图时删除本项。〉

## Evidence（验证与评审）

**〈对应的主要变化〉：** 〈逐项对应 Summary 的变化，交代被测对象、输入条件与版本，再说明结果、来源及未验证范围。文档要求对照两版原文的具体内容；缺少执行记录时写明影响结论的具体缺项。同一场景有前后对照时保留下列两项或改用对照表，并保留条件与例外。〉

- **修改前：** 〈本次修改前在相同场景下的行为，注明对应 commit 或文档版本的来源。〉
- **修改后：** 〈最终版本在相同场景下的行为及来源。〉

**〈相关检查或缺口〉：** 〈说明实际失败或重要缺口的对象、原因及影响，多项独立结果分别列项。保留判断结论所需的方法与版本，完整输出按需链接到独立记录；同一检查或缺口只写一处。〉

## Merge Danger（影响与回退）

**影响范围：** 〈说明采用后影响的功能、流程或维护对象。多个对象的影响或兼容条件不同，分别列项。〉

**可逆性：** 〈按方案采用后的状态确定回退对象及恢复动作，包含方案产生的产物。逐项核对需单独处理的对象及条件；恢复操作有顺序时使用编号列表。小改动可与上一主题合并。〉
