# 中文标题规则

本文件由 mower-commit 维护，供 Git 提交标题和 PR 标题共用。调用方先确定实际改动范围：提交标题依据本次提交的完整 diff，PR 标题依据整个 PR 的最终 diff。

先对照需求和已确定范围的完整 diff，列出实际对象及可核实的前后变化。先独立写出整体范围陈述：谁使用或维护什么，原有问题是什么，最终怎样改变；再据此确定主要变化或共同维护对象，最后合成标题。业务改动写具体功能、流程或配置；工程、文档和 skill 改动写实际维护对象及其职责、格式或使用方式的变化。

多项变化共同实现同一结果时，概括这个有事实依据的结果；变化相互独立时，按需求和方案确定主次，并在工作材料中保留主次判断的依据。文件数、行数、测试数量、材料顺序及命名难易均不能决定主线。多个局部变化可以使用同一个动词，并不证明它们合成了完整范围；共同维护对象和整体变化仍须从需求与方案确认。

一个主要动作支配完整对象；保留对象的名称与种类，以及辨认变化所需的条件、场景和结果。次要细节进入正文，标题长度由识别变化所需的信息决定。

标题中的方法、原因及属性修饰需要明确所指对象。逐个回答它说明谁的动作、什么对象的属性或哪些对象之间的关系，答案必须能从标题本身读出；事实材料中有解释仍不足以通过。需要的限定写明具体关系，不影响辨认变化的含糊修饰可以省去；不能通过追加抽象修饰来弥补范围。

标题必须遵循 [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/)。以下规则补充项目类型选择和中文表达要求。

格式为 `<type>(<scope>): <description>`。type 从 `feat`、`fix`、`docs`、`style`、`refactor`、`perf`、`test`、`build`、`ci`、`chore`、`revert` 中按主要目的选择。scope 选填，省略时一并省略括号，采用项目已有英文范围名称；冒号后一个空格，中文描述末尾不加句号。

标题的宾语采用需求与最终 diff 共同指向的对象，保留材料给出的名称与种类；描述写出该对象在修改前后的差异。可以写由多项改动实际形成的整体结果，正文再解释理由和实现细节。type 表示改动性质。描述不含开发过程编号或临时标记，不用 `+`、`/`、`、` 串联不同动作。

类型按实际主要目的选择：feat 表示新增功能，fix 表示修复问题，其他类型结合项目约定及实际目的判断。是否改动业务运行源码不能单独决定类型，chore 也不表示改动很小。

复核时先对照需求和完整 diff 检查范围与事实，再把标题与独立范围陈述并排核对：逐项主要变化是否仍属于标题所指对象及变化，省略的是实现细节还是另一项主要结果。若标题只有局部对象，回到共同维护对象重写，不能靠正文补足标题缺失的范围。脱离正文确认对象种类、条件和结果清楚后，最后检查中文修饰关系、动宾结构、格式及类型。工作材料保留范围核对；正式标题不包含核对过程。事实有出处不能代替这项检查。
