# 重启就绪扫描预算

## 契约

[INV-UPD-02] 要求严格登记扫描在共享单调时钟预算内重试不可读文件，保留未经核实的登记，并在预算耗尽时通过 `InstanceScanError` 报错。重启持久性测试在 30 秒就绪期限内使用完整快照。

## 简化审计

`ProcessRestartPersistenceTests` 包含一个局部就绪轮询。零超时参数在并发发布登记时禁用了扫描函数已有的重试策略。轮询复用扫描函数的五秒预算，并以剩余就绪时间限制该预算；不增加新辅助函数、生产重试策略或尽力扫描回退。

## 验证

重启持久性测试在读取子进程登记时注入一次 `PermissionError`，验证后续读取成功，再检查配置、排班文件字节和更新确认状态在两次重启后保持一致。`InstanceScanTests` 覆盖短暂错误恢复、共享重试预算、持续错误的结构化报错及登记保留。

## Standards Findings

通过。变更限定于测试和登记扫描契约。子进程清理与有限期限保持约束。现有领域定义无需修改术语表。Ruff 和治理检查通过。

## Spec Findings

通过。就绪等待容忍 Windows 登记文件的短暂占用，持续不可读仍产生结构化失败。生产更新准入、进程控制和扫描行为保持现有契约。进程控制、运行时扫描及治理定向测试通过 52 项测试和 33 项子测试；两项原生 Windows 测试在 macOS 上跳过。原生 Windows 验证以 CI 为准。
