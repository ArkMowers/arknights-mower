# 设备测试夹具隔离

## 契约

离线测试明确声明设备预设要求的宿主平台，使用当前接口签名，并释放其取得的每一个已验证 MAA 连接。平台拒绝、目标身份、启动期限和资源补偿保持生产行为。

[INV-DEV-05] 要求原生截图前检查后端兼容性。Windows MuMu 测试在截图边界指定 Windows 宿主；独立兼容性测试保留不支持平台的拒绝行为。[INV-DEV-03] 要求临时整备和预检共用启动预算。整备夹具提供明确的实体设备配置、ADB 解析器和匹配本次运行的授权，再断言清理行为。

## 简化与边界

夹具修复复用现有模拟边界和不变量，不增加生产回退或夹具框架。桌面启动测试提供进程与通道元组，并验证所有权登记，不启动进程。纯启动接口测试在所有宿主运行，继承 POSIX 管道的测试保留平台限制。HTTP 工作线程夹具接受当前仅限关键字的整备参数。不支持宿主与缺少适配器保留不同的结构化错误。

MAA 连接测试在初始化成功后立即登记 `VerifiedAsst.stop` 清理。这保留资源更新器的实际忙碌保护，同时防止回调引用保留活跃状态并影响后续测试。未分类启动故障仍先请求应用退出再统一清理；已分类预检拒绝释放资源而不退出应用。

## 验证

定向测试复现 CI 失败案例，覆盖 Linux 截图边界，并在同一进程内先初始化 MAA 再更新资源。原有资源补偿和不支持平台的断言继续生效。Ruff、仓库规范检查及其定向测试验证仓库契约。
