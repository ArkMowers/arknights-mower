# 跑单原班恢复

[English](2026-10-08-run-order-roster-compensation.md)

## 决策与依据

[事故分析](../../../../docs/postmortem/2026-10-01-proviso-run-order.md)记录空房原班通过 `Free` 选人恢复，以及前序恢复失败后任务计划为空的现象。`BaseSchedulerSolver.agent_arrange` 中的另一个静态主班恢复分支也混用实际人员和配置目标，可能用正在休息的主班替换实际工作的替补。两种来源都不能确定实际原班。

任务保存的一次实际观察成为从准入到确认恢复的唯一原班来源。移除竞争的静态恢复分支属于同一次恢复责任修复，没有独立公共接口、另一套名单解析器或配置开关。简化移除一个恢复分支和一个竞争名单来源；生命周期修复不以总行数减少衡量。

修复延伸既有 [INV-SCHED-04](../../../../CODING_STANDARDS.md#2-subsystem-invariants)，完整操作规则由[换班补偿契约](../../../../docs/subsystems/base-scheduler.md#251-shift-compensation-and-run-order-restoration)定义。正常原班异常时返回普通纠错。换入未完成、局部异常和保存任务重新进入均保留同一原班，只继续恢复。共享但书的跑单等待前一任务恢复。自动救急保留其独立的实际空位恢复语义。

`record.current_state` 保存的队列共享正在执行的任务。因此，确认阶段或葛朗台等待期间的保存可能同时包含待恢复标记和换入计划或空计划。在队列恢复、调度重启与安排入口重建原班恢复计划，覆盖这些实际重新进入路径。统一关键任务准入保留恢复优先级，只估算剩余人员安排时间，不加入葛朗台等待，也不将恢复作为无人机订单调整目标。

概念影响评估保留排班表、实际驻员／预演驻员、动态换班的名称、含义和边界。本次变更在既有契约内修复执行顺序与恢复责任，不需要词汇表修改或新的不变量编号。

## 验证

离线[恢复测试](../../../../arknights_mower/tests/run_order_restoration_tests.py)覆盖无效原班、首次换入选人失败、后续选人及读秒异常、有界恢复重试、确认完成、队列清理、原班预留、跨房间共享但书等待和救急隔离。Pickle 保存回放覆盖确认阶段、葛朗台等待、保存的空计划和 `back_to_index` 开关两种状态；每次重新进入只恢复原班。

[调度任务套件](../../../../arknights_mower/tests/scheduler_task_tests.py)验证恢复优先级、只估算人员安排时间、严格离宿保护及恢复不成为无人机订单调整目标。[基建调度套件](../../../../arknights_mower/tests/base_scheduler_tests.py)覆盖实际调度派发与队列保留。这些离线检查不能确定事故中历史房间错位的原因。
