# 跑单原班恢复

[English](2026-10-08-run-order-roster-compensation.md)

## 决策与依据

[事故分析](../../../../docs/postmortem/2026-10-01-proviso-run-order.md)记录空房原班通过 `Free` 选人恢复，以及前序恢复失败后任务计划为空的现象。修复前，`BaseSchedulerSolver.agent_arrange` 中的静态主班恢复分支也混用实际人员和配置目标，可能用正在休息的主班替换实际工作的替补。两种来源都不能确定实际原班。

任务在换入前保存的一次实际观察成为直至确认恢复的唯一原班来源。移除竞争的静态恢复分支属于同一次恢复责任修复，没有独立公共接口、另一套名单解析器或配置开关。

修复延伸既有 [INV-SCHED-04](../../../../CODING_STANDARDS.md#2-subsystem-invariants)，完整操作规则由[换班补偿契约](../../../../docs/subsystems/base-scheduler.md#251-shift-compensation-and-run-order-restoration)定义。正常原班异常时返回普通纠错。换入未完成、局部异常和保存任务重新进入均保留同一原班，只继续恢复。恢复尚未完成时，所有排队的正常换入任务均等待，以保护但书等共享跑单干员。自动救急保留其独立的实际空位恢复语义。

`record.current_state` 保存的队列共享正在执行的任务。因此，确认阶段或葛朗台等待期间的保存可能同时包含待恢复标记和换入计划或空计划。在队列恢复、调度重启与安排入口重建原班恢复计划，覆盖这些实际重新进入路径。可执行的恢复任务保留关键任务优先级，只估算剩余人员安排时间，不加入葛朗台等待，也不将恢复作为无人机订单调整目标。

原班驻员仍占用其他设施时，无条件保护恢复任务的关键窗口，会在每次重试时推迟源设施纠错。后续等待该恢复的换入任务也会延续同一依赖。根据实际驻员判断可执行性，允许前置释放工作执行，同时保留补偿任务、首次快照和预约。源设施实际读回确认释放后，同一个恢复任务重新获得关键任务资格；预演释放不能提前解除等待。这是既有恢复责任决策的延伸，不改变旧的自动救急快照协议。

启动新的自动救急也可能删除普通源设施纠错，而补偿任务仍在等待该设施中的原驻员。救急部署随后等待补偿预约，导致两项操作均无法继续。在新的救急准入或其原生轮休交接队列替换之前，先完成待执行的正常补偿，保留前置释放工作。已有救急批次则暂缓补偿房间并保留其未完成目标，同时安排其他可执行房间，允许源设施释放原驻员，并防止局部部署被标记为全部完成。其专项恢复协议仍然独立。

维护副表进入会绕过普通调度，直接调用跑单调时。提前等待中的换入任务，或将尚不可执行的已标记恢复任务保留在维护批次中，均可能再次阻塞源设施安排。在调时和维护进入时共用等待任务排除规则，保留前置释放工作；可执行的已标记恢复仍保留批次保护。

主循环在仓库扫描派发到期专精任务后也会重新调度。该入口遗漏实际驻员时，再次保护尚不可执行的恢复，将源设施纠错推迟到下一次恢复重试之后。传入既有 `Operators` 数据，在同一准入契约下保留源设施释放资格。

概念影响评估保留排班表、实际驻员／预演驻员、动态换班的名称、含义和边界。本次变更在既有契约内修复执行顺序与恢复责任，不需要词汇表修改或新的不变量编号。

## 验证

离线[恢复测试](../../../../arknights_mower/tests/run_order_restoration_tests.py)覆盖无效原班、首次换入选人失败、后续选人及读秒异常、有界恢复重试、确认完成、队列清理、原班预留、跨房间共享但书等待和救急隔离。Pickle 保存回放覆盖确认阶段、葛朗台等待、保存的空计划和 `back_to_index` 开关两种状态；每次重新进入只恢复原班。

恢复套件中的源设施释放回归执行真实的 `scheduling(..., op_data=...)` 与 `infra_main` 调度循环：源设施的 `SELF_CORRECTION` 通过普通换班预演、选人和房间读回完成，随后同一个队列任务恢复原班。测试离线替换屏幕 I/O，不在两次派发之间手动释放原驻员。保存的恢复、换入和空计划均覆盖有、无后续排队换入任务两种情况，完成过程中不再次选择但书，也不使用无人机加速。源设施选人发生短暂错误时，同样通过有界重试完成，再恢复原班。

[关键任务准入套件](../../../../arknights_mower/tests/priority_admission_tests.py)区分实际驻员与预演驻员，在重复准入检查中保留等待任务对象与预约，并验证阻塞时让出关键窗口、可执行后重新保护恢复。[调度任务套件](../../../../arknights_mower/tests/scheduler_task_tests.py)验证恢复优先级、只估算人员安排时间、严格离宿保护及恢复不成为无人机订单调整目标。[基建调度套件](../../../../arknights_mower/tests/base_scheduler_tests.py)覆盖实际调度派发与队列保留。这些离线检查不能确定事故中历史房间错位的原因。

[自动救急套件](../../../../arknights_mower/tests/automatic_rescue_tests.py)覆盖保存的恢复、换入和空计划对新的救急准入的影响，以及已有救急批次恢复部署时，救急目标与原班相同或不同两种情况。源设施安排先释放原驻员，再恢复原班；延后的救急目标在确认前始终保留为未完成。[维护套件](../../../../arknights_mower/tests/maintenance_run_order_tests.py)执行直接调时与真实副表进入，覆盖已有批次标记，以及恢复尚不可执行或已可执行时的源设施换班预演。

[调度恢复套件](../../../../arknights_mower/tests/scheduler_recovery_preservation_tests.py)在仓库扫描与到期专精派发后执行真实的 `simulate` 与 `scheduling` 调用。回归离线替换设备和扫描 I/O，验证立即派发源设施纠错，恢复任务时间与快照保持不变。该入口传入实际驻员之前，回归测试失败；修复后整个套件的 147 个测试通过。

审查验证在测试进程内阻止网络连接和 HTTP 请求，执行 14 个针对性的离线套件：816 个测试及 73 个子测试通过。变更范围内的 Ruff 代码与格式检查通过。`python scripts/verify_governance.py --base 2eb3f3413207de3709ffcf0503193d5d833fa3ae` 的三个治理检查均通过，保留两条未变动的归档测试引用警告。
