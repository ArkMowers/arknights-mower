# MAA 核心代次校验

## 契约

[INV-MAA-11] 在连接前验证桌面核心身份与版本。[MAA 运行契约](../../../../docs/subsystems/maa-runtime.md) 定义初始化、安全空闲重载与进程重启兜底。标识使用 MAA 命名空间，因为软件更新命名空间的第二个标识已分配给登记扫描。

## 原因与简化

外部更新替换磁盘文件，却不替换运行中的原生映像。确认实例销毁、动态库所有权和实际映像卸载后，现有缓存清理为 Windows 和 Linux 提供统一恢复路径。仅记录 SDK 重复打开次数仍不足够：GNU_UNIQUE 符号、NODELETE 动态库和外部打开引用可在全部追踪关闭成功后保留映像。恢复在重新导入 SDK 前确认已加载函数的映射已移除。macOS MAA 注册的 Objective-C 类在关闭动态库后仍然存在，因此保留进程重启恢复。有限时的子进程版本探测避免在主进程注册重复原生类。

核心代次记录解析后的目标文件，而非符号链接条目，因此目标替换会使缓存版本失效，探测和加载后再次检查其身份。备份所有权保留现有 `lstat` 辅助函数；该语义服务于不同的生命周期，保持不变。两项审查缺陷均扩展既有 [INV-MAA-11] 保证，不引入新标识。

原生打开记录在初始化尚未完成版本验证便失败时也保留文件身份。将该身份放入既有加载记录，修复首次初始化失败后的缺口，不把失败探测视为已验证版本，也不增加另一份缓存。核心未变时仍可重试；核心替换后在新资源到达旧映像前触发恢复。未追踪的预加载动态库不能仅凭版本相等建立身份。本次修复复用 [INV-MAA-11] 和原记录归属。

调度器将实例构造交给受测试的运行时加载器，保留资源诊断与回调初始化。不增加配置开关、恢复工作线程或排班状态。既有领域概念的名称、含义与边界保持一致，无需修改术语表。本次审查修复在原三件套内更新，保留 implemented 生命周期。

主动更新入口遵守相同生命周期边界：仅更新资源时保留核心；完整核心安装完成后，若安装后的激活需要重启，仍保留安装结果。把清理失败当作安装失败会丢失已提交的结果及其备份引用。Windows 替换目录前的清理仍是安装前提。本次修复同时遵守 [INV-UPD-04]，不新增不变量或决策。

## 验证

定向离线测试覆盖核心校验、同版本替换、符号链接目标替换、探测期间目标变化、仍被引用的空闲实例与原始 SDK 实例、未追踪加载、重复打开原生库、卸载失败或无法确认、SDK 重新导入、新实例选项、资源诊断、回调路由、活动导航、共享 ADB 传输及源码和打包版本探测分派。编译生成的原生测试库验证实际动态库卸载，并在版本字符串不变时确认新构建。Linux NODELETE 与额外打开引用场景要求重启，不向驻留映像加载替换后的资源，后续重试同样拒绝。测试在独立子进程运行；依赖映射检查的场景需要 Linux，原生测试需要 POSIX C 编译器。

新增原生场景分别让资源加载、打开核心后的 SDK 加载、实例构造或磁盘探测连续失败两次，再进行同版本替换。Linux 在一次清理后取得构建 2；macOS 要求重启，不进行第三次资源加载。资源或探测失败后核心未变时，无需清理便可重试并恢复构建 1。四个替换场景在前一实现上均失败，保留原生打开身份后通过。

使用本地官方 macOS MAA v6.17.0 核心的无设备检查确认重复初始化与核心文件替换后的重启兜底。离线 Linux 容器中的官方 MAA v5.24.2 确认同版本替换，以及符号链接目标替换后实时磁盘版本为 v5.24.3 时均要求重启；两个场景都不向驻留核心重新加载资源，也不复用已失效的 SDK。上述检查不连接设备或启动自动化。本地仍未运行实际 Windows MAA 核心或打包启动器；跨平台 CI 提供独立证据。

更新工作线程测试通过状态接口覆盖三种桌面平台的资源更新与完整核心更新。不能安全清理时保留成功的安装结果和重启提示；清理成功、安装后版本探测失败、实际安装失败及 Android 资源打包分别保留对应结果。两个不能安全清理的场景在更新入口修复前失败，修复后通过。

## 规范审查

通过：清理拒绝仍可达的实例和未知所有权，保留忙碌准入，原生版本探测在主进程之外运行。领域概念与排班计划保留既有契约。治理检查提供独立于行为测试的结构证据。

## 需求审查

通过：Windows/Linux 在确认实际映像卸载后至多尝试一次空闲重载，取得新的 SDK 类与选项定义，并在连接前与实时磁盘探测版本和解析后的目标身份比较。不能安全恢复或恢复失败时保留明确的进程重启提示；macOS 遵守该边界，不关闭其原生映像。
