# MAA 核心代次校验

## 契约

[INV-MAA-11] 在连接前验证桌面核心身份与版本。[MAA 运行契约](../../../../docs/subsystems/maa-runtime.md) 定义初始化、安全空闲重载与进程重启兜底。标识使用 MAA 命名空间，因为软件更新命名空间的第二个标识已分配给登记扫描。

## 原因与简化

外部更新替换磁盘文件，却不替换运行中的原生映像。确认实例销毁和动态库所有权后，现有缓存清理为 Windows 和 Linux 提供统一恢复路径。记录 SDK 重复打开次数，避免只关闭一次后原映像仍驻留。macOS MAA 注册的 Objective-C 类在关闭动态库后仍然存在，因此保留进程重启恢复。有限时的子进程版本探测避免在主进程注册重复原生类。

调度器将实例构造交给受测试的运行时加载器，保留资源诊断与回调初始化。不增加配置开关、恢复工作线程或排班状态。既有领域概念的名称、含义与边界保持一致，无需修改术语表。本次审查修复在原三件套内更新，保留 implemented 生命周期。

## 验证

定向离线测试覆盖核心校验、同版本替换、仍被引用的空闲实例与原始 SDK 实例、未追踪加载、重复打开原生库、卸载失败、SDK 重新导入、新实例选项、资源诊断、回调路由、活动导航、共享 ADB 传输及源码和打包版本探测分派。编译生成的原生测试库验证实际动态库卸载，并在版本字符串不变时确认新构建；测试在独立子进程运行，缺少 POSIX C 编译器时跳过。

使用本地官方 macOS MAA v6.17.0 核心的无设备检查确认重复初始化与核心文件替换后的重启兜底。不连接设备或启动自动化。本地未运行实际 Windows/Linux MAA 核心或打包启动器；跨平台 CI 提供独立证据。

## 规范审查

通过：清理拒绝仍可达的实例和未知所有权，保留忙碌准入，原生版本探测在主进程之外运行。领域概念与排班计划保留既有契约。治理检查提供独立于行为测试的结构证据。

## 需求审查

通过：Windows/Linux 至多尝试一次已验证的空闲重载，取得新的 SDK 类与选项定义，并在连接前与实时磁盘探测版本比较。不能安全恢复或恢复失败时保留明确的进程重启提示；macOS 遵守该边界，不关闭其原生映像。
