# MuMu 启动命令期限

[English](2026-10-03-mumu-startup-command-deadline.md) | [中文](2026-10-03-mumu-startup-command-deadline.zh.md)

## 契约

[INV-DEV-20] 命令输出所有权使 MuMu 启动观察与默认受保护 ADB 命令的等待不受继承输出句柄影响。超时仅终止自有命令，最多额外等待一秒回收进程，并保留实例绑定和共享服务。[设备控制](../../../../docs/subsystems/device-control.md)定义接口契约。[共用执行决策](../simplification/2026-10-03-device-command-output.zh.md)定义 runner 复用。

## 证据边界

报告中的 UI 停在连接就绪消息，所选 MuMu 实例停在桌面。UI 日志显示 INFO 及以上级别；中间启动操作原本仅有 DEBUG。报告缺少连接消息之后的 DEBUG 文件日志，也无法访问故障主机，因此不能确认现场根因。

Windows Python 3.12 离线夹具以 0.5 秒超时调用生产预检适配器，并由后代保留 stdout/stderr。使用管道的实现中，休眠命令与成功退出的命令均超过两秒仍然阻塞。释放后代才允许返回。这独立确认了可复现的命令生命周期缺陷。

## 实现

预检、MuMu 输入版本查询、ADB 命令执行、共享服务版本检查与启动使用 `run_command`。默认厂商观察采用同一有界机制。捕获流使用临时文件与有限读取，输出收集不等待后代 EOF。命令参数、Windows 隐藏窗口标志、共享 ADB 保护、退出码错误、二进制截图帧数据与文本解码保留现有职责。不增加重试或主机范围清理。

设备控制在预检开始、辅助服务初始化开始及初始化完成时输出 INFO。DEBUG 命令边界记录外部操作和有效超时。[启动诊断步骤](../../../../docs/cookbook/device-startup-stall.md)区分命令阻塞、预算内等待与 UI 日志传递失败。

## 验证

定向离线测试覆盖继承 stdout/stderr、正常完成、超时、分离及合并输出、二进制与文本解码、输出限额、进程回收、流关闭与所选目标启动失败结果。设备与网络操作保持隔离。报告主机的确认仍依赖 DEBUG 文件日志或应用本改动后的运行记录。

验证通过 509 项定向测试与 193 个子测试，覆盖 MuMu Pro、DroidCast、共享 ADB 保护、会话启动和仓库治理。Ruff 检查、格式检查与差异空白检查通过。

## 标准审查结论

PASS：共用 runner 实现 [INV-DEV-20]，不创建读取线程或终止后代。共享 ADB 协商与实例身份保持完整。启动失败暴露现有 `frame_failed` 结果并解除设置锁定。现有词表定义覆盖这些执行边界，持久化字段与领域含义保持其契约。定向测试、Ruff、文档链接与仓库治理检查通过。

## 需求审查结论

PASS：真实 Windows 后代使原预检超过超时仍等待；预检、受保护 ADB、版本查询、共享服务启动与 MuMu 输入现在均在后代仍存活时返回。成功与失败退出保留原有结果。输出通道、二进制数据、文本换行与 Python UTF-8 模式保留 subprocess 行为。进程创建遵循操作系统的可中断性。缺少报告主机 DEBUG 日志时，现场归因仍未确认。
