# 未应答连接的重启证据

## 现象

共享 ADB 服务停止应答主机握手后无法恢复。每个恢复周期都记录 `设备恢复暂停，30 秒后重新检查所选目标：共享 ADB 握手无法验证，保留现有监听`，所选模拟器在外部工具重启该服务之前始终不可用。实测故障中该警告持续二十八分钟，服务始终无响应。

## 根因

`probe_adb_server` 区分两个超时阶段。接收主机应答超时抛出 `SharedADBHandshakeTimeout`；TCP 连接阶段超时抛出的是普通 `SharedADBError`。

`SharedADBRecovery._require_host_timeout` 只接受 `SharedADBHandshakeTimeout` 作为主机故障证据，其他探测错误一律抛出 `共享 ADB 握手无法验证，保留现有监听`。因此连接阶段超时在首次观察时即中止恢复，早于 `_failed_probes` 与 `_failed_since` 的更新，既未进入持续故障窗口，也未到达重启判定，协调器始终不会停止已卡死的服务。

该分类与观察所证明的事实不符。TCP 握手完成但无应答，与连接始终未完成，都表示监听者没有给出任何应答。只有连接被拒绝才证明端口空闲，只有收到应答才证明进程存活。

## 契约

[INV-DEV-19] Shared ADB Recovery 要求每一次未应答的主机握手都提供重启证据。在预算内没有给出任何应答的监听者即为这种证据：主机始终未完成 TCP 连接、已连接但监听者未回应，或已部分送达的应答中途停滞。两种观察都计入同一持续故障窗口，即在至少三十个单调秒内至少两次观察，且只有该窗口授权显式协调重启。

未应答的连接并不证明端口上没有存活进程。它只表明服务未在预算内应答，因此其效力不高于未应答的回应，同样必须走完整个窗口。

以畸形响应作答、或在响应完成前关闭连接的监听者仍是另一种观察。它证明端口上存在存活进程，因此不提供重启证据，并保留该进程。连接被拒绝仍是唯一的“不存在”结果，因此允许在不发送 `kill-server` 的前提下进行受保护启动。

[端口占用进程核验后停止的决策](2026-10-07-verified-adb-listener-stop.md) 扩展协议停止边界。停止请求超时允许使用其 Windows 进程核验兜底；未通过核验或停止失败仍保留尝试记录、冷却，并拒绝启动服务。

[INV-05] Shared ADB Guard 保持不变：隐式 `kill-server` 仍被禁止，显式主机恢复边界仍是停止共享服务的唯一途径。

## 实现

`probe_adb_server` 通过单一处理分支把任一阶段的超时上报为 `SharedADBHandshakeTimeout`，对畸形响应、在响应完成前关闭的连接、无效协议版本以及非超时的连接失败继续保持 `SharedADBError`。单一分支同时移除了原先用于区分阶段的标志位，以及重复同一种判定的重复抛出。

`SharedADBRecovery` 保留原有全部闸门：两次观察、三十个单调秒、主机共享跨进程锁、持久化的墙钟冷却以及持锁复探。闸门未变，放宽的是哪一种未决观察可以提供证据。

## 验证

`adb_server_tests.py` 验证连接停滞与握手停滞都以同一条不含阶段假设的判定抛出 `SharedADBHandshakeTimeout`，连接被拒绝仍是唯一的“不存在”结果，非超时的连接失败仍未经验证，畸形或截断响应仍为 `SharedADBError`。

`adb_shared_server_tests.py` 验证连接阶段超时计入持续故障窗口而非中止恢复，前两次未应答观察后不尝试停止服务，首次重启判定推进共享 generation，且端口占用进程未通过核验时仍保留尝试记录、冷却，并拒绝启动服务。
