# 智能救急初始化清退窗口

## 契约

[INV-SCHED-03] 要求初始化观察无论是否存在活动智能救急批次，都遵守严格清退操作窗口。每房实测后先刷新清退，再开始下一次操作。卡牌扫描的四十五秒预算不足时初始化让出执行时间。已选中的清退先于待完成初始化执行，不在每次派发尝试时被替换。

初始化未读房间独立于救急批次状态持久化。初始化延期保留首次心情门禁，不授权副表切换或救急判定，仅继续未读房间。卡牌扫描等待期间，已完成读房的空列表与尚未开始读取保持区分。初始化成功后清除待读列表。恢复的房间身份只包含当前排班仍有的房间。

## 简化

初始化共用现有读房、清退生成、操作预算判断和救急复查任务。当前运行快照只新增一个可空房间列表，不构造占位救急批次或兼容路径。[基建调度契约](../../../../docs/subsystems/base-scheduler.md)持有接口保障。

## 验证

离线测试使用真实基建派发边界、严格清退生成和运行快照。虚拟时间覆盖已缓存和未缓存的清退、新实测完成、部分初始化恢复、卡牌扫描延期和已选清退派发。原有初始化心情与智能救急测试保留普通启动行为。设备与存储边界隔离。

## 审查

Standards Findings：初始化进度共用现有持久化和有限观察机制，保留强制清退及首次心情门禁。

Spec Findings：启用智能救急但尚无批次的初始化不延误个人心情上限离宿。默认满心情宿管仍按共享恢复层级让床。

十个定向离线套件通过 616 个测试及 26 个子测试；治理测试通过 14 个测试及 4 个子测试。限定范围的 Ruff、格式、差异检查及全部治理门禁通过。发布前由全新独立会话审查不可变提交。
