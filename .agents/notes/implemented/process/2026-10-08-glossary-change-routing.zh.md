# 按任务选择治理流程与决策归属

## 背景

无条件六阶段流程和简化技能的独立提案要求，按技能调用划分记录，替代了决策归属。同主题审查修复因此产生重复记录、链接和生命周期工作。无条件同步术语表又把执行规则当作定义，在含义未变时发起审批。结构检查无法证明行为或含义正确。

## 契约

- [代理流程](../../../AGENTS.md#1-task-selection) 按只读审查、局部修复、独立设计或文档维护选择必要工作。仓库技能拥有政策，通用技能提供方法，不增加第二套强制产物。实施前检查在受影响范围内查找相关调用者、契约、决策、故障记录和测试。
- [记录归属](../../AGENTS.md#1-record-ownership) 管理复用和合并。同主题修复、测试和附带简化更新原三件套；日期、分类、技能或会话不能单独成为新建理由。合并保留有效双语内容和元数据；未提交的重复产物与有历史价值的记录分别处理。
- [代码标准](../../../../CODING_STANDARDS.md#1-core-invariants) 登记编号及简要保证；子系统契约拥有完整定义，审查清单引用它们。先复用已有保证，独立的新保证才登记新编号。验证跟随真实调用者，检查保证要求的返回值、状态、持久化、副作用或异常。
- [生命周期条件](../../AGENTS.md#2-lifecycle-taxonomy) 根据实施、针对性行为验证和审查确定 implemented 状态，独立于 Git 提交、推送或合并状态。提案可以记录已完成的局部工作，同时明确剩余工作。
- [INV-06](../../../../CODING_STANDARDS.md#1-core-invariants) 统一规定概念变化与未变化的处理分支。根目录和后端指令引用它，替代无条件同步术语表的要求。
- [文档归属规则](../../../skills/mower-doc/references/doc-hierarchy.md#routing-rules) 区分概念本身、业务行为保证、实现契约和开发操作步骤。确定概念边界的约束属于定义。
- 有依据地确认概念未变化，即可完成检查，无需修改术语表。定义发生变化时，先提出中英文精确文本，并在写入前取得[明确的术语表审批](../../../../AGENTS.md#4-global-execution-constraints)；名称未变化但含义变化也适用此要求。
- 审查报告记录归属判断及其理由。现有术语表用于查询定义，不能作为把新增操作规则写进术语表的依据。
- 自动检查成功仅表示记录结构及必要引用、检查范围内的相对文档链接和禁用词通过。新增或变更的 active 记录要求测试路径存在、不变量有真实声明。工作区覆盖暂存、未暂存和未跟踪文件，分支采用实际指定的比较基准；历史缺失引用保留兼容警告。代码符号存在性、元数据重合、行为、文档归属和批准仍由审查判断；不导入生产模块解析符号。

## 验证

`arknights_mower/tests/verify_governance_tests.py` 从真实治理 CLI 验证引用校验、实际 Git 比较范围、历史兼容、异常元数据及不导入生产模块的副作用边界，也验证成功报告准确限定范围，以及任一门禁失败时返回失败并继续运行其余检查。

[流程案例](../../../skills/mower-code-review/evals/evals.json) 定义七类任务和必要的隔离输入。只读的整改前后演练覆盖工作区审查、同主题修复及简化、已有保证、独立协议、重复文档、概念未变和定义改变。两版规则下均有正确判断；新规则直接消除旧六阶段与归属要求之间的冲突。演练复用了带有此前上下文的会话，每组案例也共享上下文。全新隔离 CLI 尝试无法在其执行策略下读取文件，因此未声称新会话成功率、较弱模型表现或 Token 开销改善。只读演练没有实施假想协议、合并文档或修改术语表。

[概念影响复核步骤](../../../../docs/cookbook/review-glossary-impact.md) 保留六个较窄的含义判断案例。结构测试不声称验证了 agent 的判断行为。

本次复用 [INV-06] 和现有扫描器，不增加含义分类器或领域运行时抽象，不贡献术语表改动。评估输入中的报告修复有自己的决策和交付范围。
