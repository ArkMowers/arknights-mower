# 按任务选择治理流程与决策归属

## 问题

无条件六阶段流程和简化技能的独立提案要求，按技能调用划分记录，替代了决策归属。同主题审查修复因此产生重复记录、链接和生命周期工作。无条件同步术语表又把执行规则当作定义，在含义未变时发起审批。结构检查无法证明行为或含义正确。

## 决策

- [代理流程](../../../AGENTS.md#1-task-selection) 按只读审查、局部修复、独立设计或文档维护选择必要工作。仓库技能拥有政策，通用技能提供方法，不增加第二套强制产物。实施前检查在受影响范围内查找相关调用者、规范、决策、故障记录和测试。
- [记录归属](../../README.md#record-ownership) 管理复用和合并。局部修复证据可以保留在 PR 或改动报告；有独立长期价值的理由才需要记录。新决策使用带 `format: decision` 的中英文双文件和直接链接，旧三件套保持既有格式与元数据。
- [代码标准](../../../../CODING_STANDARDS.md#1-core-contracts) 拥有六项全局保证。子系统说明维护有名称和稳定锚点的业务规则，审查直接引用它们。当前所有保证都使用行为名称，无需额外编号或中央登记；冻结的历史编号仅供旧元数据兼容。验证跟随真实调用者，检查保证要求的返回值、状态、持久化、副作用或异常。
- [生命周期条件](../../AGENTS.md#2-lifecycle-taxonomy) 根据实施、针对性行为验证和审查确定 implemented 状态，独立于 Git 提交、推送或合并状态。提案可以记录已完成的局部工作，同时明确剩余工作。
- [概念影响复核](../../../../CODING_STANDARDS.md#concept-impact-review) 统一规定概念变化与未变化的处理分支。根目录和后端指令引用它，替代无条件同步术语表的要求。
- [文档归属规则](../../../skills/mower-doc/references/doc-hierarchy.md#routing-rules) 区分概念本身、业务行为保证、实现规范和开发操作步骤。确定概念边界的约束属于定义。
- 有依据地确认概念未变化，即可完成检查，无需修改术语表。定义发生变化时，先提出中英文精确文本，并在写入前取得[明确的术语表审批](../../../../AGENTS.md#4-global-execution-constraints)；名称未变化但含义变化也适用此要求。
- 审查报告记录归属判断及其理由。现有术语表用于查询定义，不能作为把新增操作规则写进术语表的依据。
- 自动检查成功仅表示记录结构、指定范围的引用、相对文档链接和禁用词通过。变更的 active 旧记录保持测试路径和编号检查；新决策检查相对源码与测试链接，不导入目标。工作区覆盖暂存、未暂存和未跟踪文件，分支采用指定比较基准；历史缺失引用保留兼容警告。文件存在不证明测试通过，行为、归属、含义和批准仍由审查判断。

这轮适配移除中央业务登记：98 条正文与所属子系统说明一致，其余 31 条逐项对照完整子系统正文，并保留缺失的空位填充、重连、字形、UI 策略和识别边界。规则和清单使用名称及直接锚点，六项全局要求在描述性标题下保留完整要求。初次迁移保留 134 个唯一历史编号作为兼容输入。基于最新 alpha 整理时，再保留上游已声明的五个编号，冻结集合共 139 个；不为原有的重复业务编号重新指定含义。PR 指令也改为使用规则名称和链接，避免重新引入编号。

[生命周期正文](../../README.md#body-by-lifecycle) 保留问题、真实替代方案和代价。提案还说明可观察的验收条件与风险；实施记录说明实际决策和后果；拒绝记录保留原提案与拒绝理由。状态迁移同时修改 status 和目标正文。新格式对两种语言执行机械章节检查，归属、替代方案是否真实及证据是否有意义仍由审查判断。

目录 README 把职责连接到真实源码、所属子系统说明和定向验证：[文档](../../../../docs/README.md)、[后端](../../../../arknights_mower/README.md)、[solver](../../../../arknights_mower/solvers/README.md)、[设备控制](../../../../arknights_mower/utils/device/README.md)、[测试](../../../../arknights_mower/tests/README.md)与[脚本](../../../../scripts/README.md)。设备和测试目录的 AGENTS 增加局部修改入口与隔离要求，继承父级约束。根指令链接这些导航地图，行为定义仍留在原有归属处。

## 考虑过的替代方案

保留缩小后的登记表虽然能减少正文复制，但仍要求每个业务规则拥有额外身份、每份记录手工关联元数据。所选方案把当前行为放在规范中，把必要理由放在双语决策中。照搬全部上游包模板会引入没有对应 Mower 使用者的模型运行时栏目；现有参考文档改为提供真实入口、可观察的失败处理、离线验证范围和相关限制。

所有生命周期使用同一个压缩正文虽然节省模板文字，却会混淆拟议行为与实施证据，丢失拒绝理由。所选生命周期骨架保留这层必要结构，同时不强制无关技术栏目，也不要求每次编辑都新增记录。

给每个文件夹都添加 README 和 AGENTS 会产生重复政策或空内容。所选入口对应 Mower 需要定位的职责或需要执行的额外局部约束；生成资源和普通子目录不为覆盖率新增文档。

## 后果

继续维护两种语言。为保留已发布记录，接受旧三件套和冻结编号文件的兼容成本。取消新记录 sidecar 后，源码和测试不再拥有单独的手工清单；直接链接和针对性行为证据保留必要引用。结构检查仅判断可机械验证的事实。

## 验证

治理与归档合并定向测试通过 62 个测试和 85 个子测试；六个改动 Python 文件的 Ruff 与格式检查通过。真实 Git 测试仓库覆盖比较范围、格式降级、不同分类同名和本地文档清单。非法样本验证不完整或混合格式、异常兼容数据、无效本地源码链接，以及仅改状态却保留提案正文的迁移都会失败。双语生命周期检查区分正文与 frontmatter、代码示例和注释。目录指南只允许放在 notes 根目录、生命周期和分类三层。清单获取失败返回错误；被忽略的本地残留不阻断链接检查，已跟踪和未被忽略的新文档仍被检查。

补齐评审闭环、历史兼容和锚点检查后，基于 alpha `97f4fba5da551030d0c0a839c81383a830a44178` 的发布工作区通过 69 个测试和 104 个子测试。实际 CLI 回归验证新历史三件套、增删冻结编号、缺失或仅在示例中的锚点都会失败，原有记录编辑和生命周期迁移继续有效。冻结集合与基线全部 139 条声明一致。合并后的规范经复核保留最新上游行为及例外；PR skill 已包含在该基线中。

操作手册使用真实的 DeviceControl、DeviceSession 和配置接口，并提供任务导航与执行目录。静态源码复核检查接口名、示例和测试选择器。两个未继承会话历史的只读代理定位截图恢复与换班状态的生产调用者和测试；设备调查识别出已有修复，调度调查区分可疑的前置写入与已复现缺陷，并发现测试范围缺口。输入和预期保留为导航案例 8–9。两次调查均未运行行为测试或实施修复。这些结果支持相应案例的导航与判断，不证明游戏行为或已测量的效率改善。

`arknights_mower/tests/verify_governance_tests.py` 从真实治理 CLI 验证引用校验、实际 Git 比较范围、历史兼容、异常元数据及不导入生产模块的副作用边界，也验证成功报告准确限定范围，以及任一门禁失败时返回失败并继续运行其余检查。

CI 回归读取真实文档工作流中声明的命令，在干净且已提交的 Git 测试仓库中执行。PR、推送与手动指定比较均拒绝变更 active 记录中的缺失引用，未变更记录继续保留兼容警告。缺少或不可用的基准返回失败；新分支与未指定基准的手动运行执行[引用政策](../../AGENTS.md#5-references-and-compatibility) 中明确的全量 active 检查。

近期合并改动审查发现文件迁移遗漏调用方、策略说明过期以及检查晚于交付完成。[验证流程](../../../AGENTS.md#4-verification-and-reporting) 现为这些情况提供按需的完成条件。按住截图与发布范围的清单条目改为审查问题，并链接权威规范。这些指令经过静态审查，本次未测量新的 agent 演练成功率。

前七个[流程案例](../../../skills/mower-code-review/evals/evals.json) 定义任务和必要的隔离输入。只读的整改前后演练覆盖工作区审查、同主题修复及简化、已有保证、独立协议、重复文档、概念未变和定义改变。两版规则下均有正确判断；新规则直接消除旧六阶段与归属要求之间的冲突。演练复用了带有此前上下文的会话，每组案例也共享上下文。全新隔离 CLI 尝试无法在其执行策略下读取文件，因此未声称新会话成功率、较弱模型表现或 Token 开销改善。只读演练没有实施假想协议、合并文档或修改术语表。

[概念影响复核步骤](../../../../docs/cookbook/review-glossary-impact.md) 保留六个较窄的含义判断案例。结构测试不声称验证了 agent 的判断行为。

演练后根据真实的点击、缓存清除、截图和邮件调用链澄清了报告动作表述，发布的案例也明确列出必要输入。这些澄清经过源码和文档复核，没有重新进行全新 agent 试跑。

本次复用概念影响复核要求和现有扫描器，不增加含义分类器或领域运行时抽象，不贡献术语表改动。本文是旧记录，在 sidecar 中保留冻结编号以兼容历史。评估输入中的报告修复有自己的决策和交付范围。
