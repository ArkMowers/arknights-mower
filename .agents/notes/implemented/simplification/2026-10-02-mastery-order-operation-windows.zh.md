# 专精换人与跑单操作窗口

## 契约

[INV-SCHED-17] 保留贸易跑单任务时间，并提前与其冲突的专精换人。[子系统契约](../../../../docs/subsystems/base-scheduler.md)定义时间与派发规则。

## 简化依据

原调度器中的 `_support_swap_gap` 有三个生产调用点，对称的至少十分钟间隔控制跑单冲突检查、无人机加速准入、换人后延期，也控制普通宿舍补位。调度器删除此辅助函数与跑单延期规则。现有提前量与每房间操作预算判定冲突；普通宿舍补位保留独立的保守窗口。此次调整不新增配置或耗时历史。

冲突触发换人提前并标记提前执行。专精协助执行器保留训练状态、槽位与候选资格校验，符合条件的提前换人不再重新排到理想时刻。现有术语表定义保持准确。

维护避让复用这一提前执行边界及已有换人操作预算。主循环预算选择与空闲等待在确定等待时间前执行保护，否则恢复或新生成的换人任务可能一直休眠到停服期间。换人使用公告的完整维护区间，因为提前登录时间不能证明服务器已经可用。此扩展不新增任务类型、持久化配置或领域概念。

## 验证

离线测试覆盖反馈中的剩余九分五十四秒窗口、已流逝倒计时、完成与换人精确边界、独立于订单碰撞间隔的小数前置延时、多订单冲突单轮收敛、重复规划、多个换人任务、一分钟训练室换人窗口、过期跑单派发、归位任务和无人机加速中断。协助执行测试区分普通时间安排与提前执行，并保留训练剩余不足时的拒绝行为。

`mastery_maintenance_tests.py` 覆盖两个派发入口、维护边界及最后半小时、较晚获知公告、关闭专精、缺少公告、操作预算、重复规划、快照恢复、普通任务准入、既有跑单加速、主循环日常任务准入、空闲等待及协助执行不重排理想时间。测试隔离配置和应用数据，并替换设备操作及外部请求。

`news_checker_tests.py` 为主循环维护唤醒回归提供完整的 `SchedulerTask`。测试进入设备恢复边界时立即失败，保留离线隔离，并使不完整的任务夹具直接报错而不等待恢复。测试核验空闲唤醒后先检查维护，再派发任务。

维护唤醒夹具修复通过 222 项定向测试及两项子测试，覆盖公告检查、专精维护、主循环初始化、设备恢复监督和调度恢复任务保留。改动文件的 Ruff lint、格式、差异空白及治理门禁通过。
