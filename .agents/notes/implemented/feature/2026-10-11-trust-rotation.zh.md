# 日常自动切换信赖

## 契约

[INV-SCHED-48] 自动切换信赖保留普通工作与休息状态；现任达到更换条件前保持原位，同类名单排除其他现任，副手与活动室允许重叠。已验证的信赖升序名单没有低于200%的同类合格候选时，保留安排并结束本轮该类剩余检查。

日常任务窗口按可调间隔执行一次可取消检查，默认24小时。功能与阈值优先开关均默认关闭，阈值默认100%。关闭阈值优先时，现任达到200%才更换。开启后，现任达到阈值且存在低于阈值的候选时允许更换；没有此类候选时保留至200%。最高位置副手先选择信赖最低的合格候选，仍受保护的现任保持原位。

副手和活动室各自排除本类全部现任，包括尚未检查的房间；两类允许重叠。普通工作与休息安排、心情记录及排班驻员保持原状。未建造活动室不接收输入，每间已建造活动室最多点击一次使用者。未知信赖、选中状态不明确或页面未确认时不确认候选。仅完整检查记录完成时间，失败留待后续日常窗口重试，两类分别计算候选是否已满信赖，下个间隔重新检查新干员。

## 简化审查

日常已有九分钟调度窗口。一个求解器复用设备、识别器、场景导航及运行状态原子写入，不增加调度任务类型、普通房间安排或投影抽象。既有gaming_1至gaming_3排班位置不描述八个活动室位置；向右平移后直接识别已建造活动室标签，普通设施坐标保持原状。

## 实现与验证

求解器确认信赖排序、当前选中状态与目标姓名后提交，再确认返回设施页面。离线测试覆盖阈值准入、分别排除候选、满信赖提前退出、日常间隔、失败持久化、信赖不可读与未建造房间。设备检查通过连接的模拟器执行相同求解器方法。


选人页取消已启用的基建技能优先，确认全职业筛选和信赖升序箭头，并在有限预算内滑至稳定的名单起点。副手以现任姓名实读排除本类名单；活动室标记排除尚未检查房间的使用者。候选姓名不在本地干员表或既有姓名模板无法匹配时跳过且不提交，现任姓名未知时停止检查。空位只有确认中性卡片上的白色入驻十字后才补入。

检查使用八分钟单调时钟预算，距下一项调度任务至少保留一分钟。停止请求直接传递且不记录完成，下次检查先取消已识别的待确认选择再导航。

## 审查证据

- 规范轴无剩余发现：日常入口复用设备与识别器，完成时间与配置分离，不写入普通干员状态。
- 需求轴无剩余发现：分别排除本类名单、跨类重复、阈值回退、保留受保护现任及按类提前退出符合已批准契约。
- Python 定向验证：`trust_rotation_tests.py`、`config_tests.py`、`verify_governance_tests.py` 与 `base_scheduler_tests.py` 的日常窗口用例共142项通过。
- 前端定向验证：`TrustSettings.test.js`、`config.test.js`、`configPartial.test.js` 与 `MaaBasic.test.js` 共68项通过。生产构建、Ruff与格式检查通过；构建保留依赖格式及包体大小警告。
- 用户授权的模拟器检查：五个不同副手均为0%信赖，重复检查保留原位。一间活动室的200%使用者换为合格的0%干员，其余两间已建造活动室使用者保持原位，替换者同时保留副手身份。选人前已取消启用的基建技能优先；观察到待确认选人恢复、未建造房间跳过及普通设施导航。
- 证据限制：最初连接的账号有三间已建造活动室，后续远端账号提供八间已建造活动室。候选全满、阈值回退及取消由离线测试覆盖。候选在资源可识别前需要通过本地干员表姓名校验。
- 结构治理检查通过，保留两条既有历史归档测试引用警告；代码符号经过静态核对。

## 姓名识别修复证据（2026-10-12）

远端两个受影响实例的日志在收集现任副手姓名时退出，尚未检查活动室。回放其中一个实例保存的失败截图，复现文本检测将「克莱门莎」拆为「克莱」与「莎」，置信度过滤后丢失中间字符。另一实例保存的 JPEG 可以正确识别「罗德岛隐秘队」，因此该实例原始姓名读取失败未在压缩截图上复现。一个活动室无损截图还复现无检测 OCR 将「旅骨」读为「旅骨商」的问题，其保存的 JPEG 未复现该失败。

既有选人姓名模板可以识别这两类姓名区域。选择页裁剪从 `(20, 155)–(350, 215)` 改为 `(20, 160)–(350, 205)`。活动室裁剪从 `(1420, 640)–(1750, 710)` 改为 `(1440, 650)–(1690, 695)`，避开上方标签和两侧白边。选择页深色文字反向二值化，活动室浅色文字正向二值化，阈值均为140。完整姓名按各模板的文字高度等比例缩放，以半像素步长允许一个像素的抗锯齿差异，兼容旧模板中长姓名的较小字号，保留标点和字距。固定选择页缩放0.725倍会使实图中的七字名「泰拉大陆调查团」超出200像素模板画布；按文字高度匹配能够识别完整姓名。

匹配复用既有选人模板及归一化相关性，要求分数大于0.6且不同姓名分差至少0.05，最多缓存256个完整姓名区域。资源重载同时清理该缓存和普通姓名缓存。文字触边、文字高度不足15像素、归一化轮廓超大、模板未匹配或姓名未知时仍视为不可读，匹配前后均检查时间预算。其他页面标签与信赖数值仍使用 OCR。本次修复仅改变姓名读取像素，领域契约与术语表保持原状。

二十六张真实姓名区域涵盖二十二名干员，全部匹配正确，包括七字中文名、分离的标点和 `Miss.Christine`。二十五张选择页及此前活动室样本的诊断最佳匹配分数为0.86～0.96，新增活动室样本验证「泰拉大陆调查团」的完整回读。测试图片仅保留姓名条，周围像素足以验证生产裁剪范围。`trust_rotation_tests.py`、`name_template_cache_tests.py`、`character_name_roi_tests.py` 与 `base_scheduler_tests.py` 的日常窗口入口用例共121项通过，覆盖 `run()` 的现任名单收集、`_replace()` 的候选校验与活动室回读、空白／裁断／超大／弱匹配区域、模糊或未知姓名、超时、两类姓名缓存失效及普通选人像素保持一致。

此前的 OCR 补充识别版本提供运行历史：一个实例的正常日常入口完成检查并写入 `2026-10-12T05:33:09.624205`；另一实例的一次独立检查以219.63秒完成，保留五名受保护副手，完成六次活动室更换及回读。这些观察发生在模板实现之前。远端保留原求解器及模板修改前源文件的备份。后者的普通排班仍因进入日常窗口前发生的独立宿舍换班目标冲突而停止。

已部署的按文字高度匹配版本完成用户授权的活动室手动入驻验证：200%信赖的「泰拉大陆调查团」在选择页和活动室回读中均匹配正确。后续完整检查以78.5秒完成，读取全部五名副手姓名并保留受保护安排，访问八间已建造活动室，将该200%使用者换为0%的「克莱门莎」，确认返回后的姓名与信赖读数，设备清理成功。安装后通过进程控制重启两个受影响实例，保留原端口和停止状态，其他实例进程保持原状。
