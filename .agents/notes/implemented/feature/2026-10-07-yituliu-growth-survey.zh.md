# 一图流养成调查与本地干员统计

养成规划在现有 Mower 界面中展示本地计算的干员统计与公开社区调查筛选。干员卡片、已选养成目标、材料预算和执行操作继续沿用现有归属。社区观测描述样本，不作为官方推荐或战斗强度排行。

[INV-GROWTH-02] 将公开调查与本地身份、凭据及计划修改隔离。后端请求 `https://auth.yituliu.cn/open/ak-operator-statistics/result`，不携带 token 或本地账号字段。已校验缓存保留二十四小时；刷新失败保留最后一份有效快照，返回过期状态与错误信息。缺失或无效指标保持未知。个人统计仅从本地已有干员数据计算，绝不进入公开调查请求。用户配置只写 token 后，每次实际成功刷新森空岛都自动上传一次；读取已有缓存或保存 token 不触发上传。独立的手动操作立即上传当前缓存练度，不重试网络请求。公开调查读取不依赖该 token。上传失败保留本地缓存与森空岛刷新成功结果，另行显示可读的同步状态。设置控件位于 Mower 设置的森空岛账号下方。凭据接口只返回是否已配置，不回显密钥，日志不记录密钥。第三方个人资料读取接口不属于本功能。

固定上传目的地为 `POST https://backend.yituliu.cn/open-api/operator/upload`，`Authorization` 携带原始只写 token，不加 Bearer 前缀。服务方契约以已核验的[公开 OpenAPI 文档](https://backend.yituliu.cn/v3/api-docs)为准。请求体只包含游戏 UID、昵称、渠道或区服身份，以及 `operatorDataList` 中的持有情况、等级、精英阶段、潜能、星级、基础技能等级、专精等级和模组等级，不包含账号密码、森空岛凭据或仓库库存。本地缓存保存用于上传的明确玩家绑定信息；缺少该身份的旧缓存须先成功刷新森空岛。token 使用独立的受限权限本地配置文件保存，不进入通用配置响应。

前端使用公开观测筛选、排序本地拥有的干员，明确区分数据不可用与真实零比例。筛选仅改变展示。用户勾选和移除继续使用现有计划接口。个人统计组件及调查筛选替换原概览与通用筛选区域，不添加并行路由或重复计划存储。

实现使用自行编写的代码。仅名为 LICENSE、但未授予软件许可的仓库文件不作为复制实现的授权。界面注明调查来源为一图流，链接来源与 CC BY-NC 4.0 内容许可，并说明数据非官方、非强度排行。

离线验证覆盖无凭据请求、响应校验、新鲜缓存复用、过期缓存保留、缺失比例、本地个人汇总、筛选不改变计划、成功刷新后的单次上传、手动固定目的地上传、上传失败隔离与凭据不泄露。养成规划子系统契约定义实现后的接口字段和指标分母。

本地鉴权接口包括 `GET /growth-survey`、`GET/PUT/DELETE /growth-sync-token` 及明确确认后的 `POST /growth-sync`。`cultivate.start` 通过 `sync_after_cultivate` 单次上传本次刚持久化的精确快照，`/cultivate-fetch` 独立报告上传结果。token 状态仅返回配置情况及成功或失败元数据，不返回完整或部分凭据。token 文件权限为 `0600`。

个人干员、材料消耗和投入排行三个标签页汇总一至六星干员。统计区域默认收起，并按每个星级的实际养成能力展示。共用进度的形态在持有数量、等级进度和基础技能费用上去重，各形态的独立技能及模组分别计数。调查阈值以样本中拥有对应干员的人数为分母，仅在直方图完整时显示比例。未知观测不能使干员被当作已完成而隐藏。[子系统契约](../../../../docs/subsystems/growth-planning.md)定义接口字段、缓存期限、指标公式与上传行为。

进程共享锁串行化每次完整的森空岛请求、缓存写入与上传事务，保证并发刷新时的练度顺序。双线程离线测试验证滞后的旧请求不能在较新事务后上传。
