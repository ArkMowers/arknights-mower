# Delegated Drop Data Upload

[中文](2026-10-01-maa-report-upload.zh.md)

`arknights_mower/utils/maa_report.py` performs the drop-data upload MAA core delegates to its client, and `BaseSchedulerSolver.on_maa_callback` in `arknights_mower/solvers/base_schedule.py` hands every `ReportRequest` payload to it. The [subsystem specification](../../../../docs/subsystems/maa-integration.md) owns the delegated-upload contract and the callback consumption boundary.

**[INV-MAA-03] Detached Bounded Upload**: A delegated report upload runs off the MAA callback thread, applies a finite connect and read deadline within a bounded number of attempts, and reports its outcome as a log line rather than an exception.

MAA core does not upload drop data. It decides whether a drop report is produced, builds the complete HTTP request, and hands it to the client through the `ReportRequest` callback (AsstMsg `30000`), whose payload carries `url`, `headers`, `body` and `subtask`. `REPORT_REQUEST = 30000` names that code in `maa_callback.py`.

The previous callback handler ignored the handover: `log_maa` logged the payload at DEBUG and did nothing, while the Fight task unconditionally sent `"report_to_penguin": True`, so no upload ever happened. DEBUG records in this host's `log/runtime.log` files hold the dropped payloads, for example a request to `https://penguin-stats.io/PenguinStats/api/v2/report` with `subtask` `ReportToPenguinStats`, `uuid` `3176499b735f1245`, `User-Agent` `MaaAssistantArknights/6.18.0-beta.1`, `X-Penguin-Idempotency-Key` `MAA1406c368ae984aae0698da55f2480`, and a body carrying `"source":"MaaAssistantArknights"`, `"stageId":"wk_toxic_5"` and `"version":"v6.18.0-beta.1"`. Nothing performed the POST, so a selected report never reached a statistics site. This upload supersedes the unhandled-request paragraph of [MAA Callback Logging](2026-09-30-maa-callback-logging.md).

`upload_report` accepts one payload and returns whether a request started. A `url` or `body` that is missing, empty or not a string makes it log one warning and return `False` without starting the POST; a `headers` value that is not a mapping is treated as empty, and a `url` without a host is refused the same way. An accepted payload starts the POST on a daemon thread named `maa-report`, so the MAA callback thread never blocks on the network and never observes an upload failure. A `RuntimeError` from thread creation returns `False` behind the same warning, and `on_maa_callback` guards the call, so the callback raises nothing even when the thread cannot start.

`_upload` merges the request headers into a `CaseInsensitiveDict` seeded with `Accept: application/json`, updates it with the payload headers, and adds `Content-Type: application/json; charset=utf-8` only when that key is absent. Header names are case-insensitive in HTTP, so a payload `Content-Type` wins under any spelling. The body is encoded UTF-8. Targets are the payload URL, plus — only when `subtask` is `ReportToPenguinStats` and the URL host equals `penguin-stats.io` — the same URL on `penguin-stats.cn`; every other target is attempted on its own domain only. The host is compared as a host through `urlparse`, so a domain embedded in a path or query selects no backup. The backup domain exists because the primary domain is unreachable on some networks.

`_attempt_domain` makes up to `REPORT_ATTEMPTS` (3) attempts on one domain, each attempt carrying a `REPORT_TIMEOUT` (15 s) connection and read deadline. Only a 5xx response retries, after `REPORT_BACKOFF` (3 s) and then `REPORT_BACKOFF_FACTOR` (1.5, so 4.5 s). Success is strictly status `200`, so a redirect or another 2xx counts as a failure for that target. A network exception ends that domain at once, without retry. A penguin report that fails on both domains costs six POSTs at most, with two backoff sleeps per domain, so a report whose attempts each reach the connection deadline occupies its worker for about 105 s. The deadline is per phase rather than per attempt, since `requests` applies it to the connection and again to each read, and neither covers name resolution.

`_post` guards its whole body. An exception escaping a worker thread reaches only `threading.excepthook` and leaves no record in the runtime log, so every failure has to become a log line here rather than propagate.

Success logs one INFO line naming the destination, `企鹅物流上报成功` or `一图流上报成功`. A penguin failure logs one WARNING line naming the destination and giving up on that report. A failure for any other destination logs the same text at DEBUG, mirroring the client's deliberate silence for 一图流, except that the first such failure of the process is promoted to WARNING: the WebSocket log page carries INFO and above, so a permanently failing destination would otherwise be invisible there.

`SUBTASK_TEXT` maps `ReportToPenguinStats` to 企鹅物流 and `ReportToYituliu` to 一图流; `report_label` uses that name, the raw `subtask` string, or `MAA` when `subtask` is not a string. The label selects wording only, so an unknown subtask still uploads.

Uploads log through the project's shared `from arknights_mower.utils.log import logger` rather than a module-local `logging.getLogger(__name__)`, so each line reaches the terminal, `runtime.log` and the WebSocket log page.

The network parameters, the success criterion, the backoff schedule and the backup domain are ported from the MAA desktop client's `GameDataReportService.PostWithRetryAsync` and `HttpService.BuildHttpClient` on branch `dev-v2` at commit `4a2084f2dad2740d388ad71305a3d5beac7fa498`: a 15 s connection and read deadline per attempt, 3 attempts per domain, 5xx-only retry, 3000 ms backoff multiplied by 1.5, strict `200`, and `https://penguin-stats.cn` as the backup. Three client behaviours stay out deliberately. The client skips penguin uploads for the `txwy` client, while `_maa_client_type` returns only `Official` or `Bilibili`, so that branch holds no reachable case here. The client skips reporting under a PC-connect profile, and this backend has no such profile. The client writes a returned id back through `x-penguin-set-penguinid`, and persisting configuration from a background upload thread sits outside this change. Three further differences follow from the port itself: one client deadline covers a whole attempt while `requests` bounds the connection and each read separately, the client selects the backup domain with a substring match on the URL while this port compares the host, and the client sleeps once more, after its last 5xx in a domain.

Reporting is now opt-in. `Conf.maa_report_to_penguin` defaults to `False`, the Fight task sends `"report_to_penguin": conf.maa_report_to_penguin` in place of the hard-coded `True`, and `maa_penguin_id` is documented as 仅在开启上报时有效, matching the existing `maa_yituliu_id`. `ui/src/components/MaaWeekly.vue` renders a 上报至企鹅物流 checkbox whose id input stays disabled while unchecked, mirroring the 一图流 row; the help text states that both sites upload only when checked and that a blank id uploads anonymously. `ui/src/stores/config.js` carries the new ref through load, save and export.

`log_maa` is renamed `on_maa_callback`, because it performs the upload rather than only logging; it calls `upload_report(d)` when `msg == REPORT_REQUEST` and then logs the translated line as before.

`arknights_mower/tests/maa_report_tests.py` holds 25 hermetic tests. They replace `threading.Thread` with an inline fake and patch `time.sleep`, so uploads and backoff run synchronously, and cover refusal of a missing or non-string `url` or `body` without any POST, refusal of a `url` that exposes no host before any thread starts, a `RuntimeError` from thread creation reported rather than raised, an exception escaping the worker becoming a log line, the exact `requests.post` arguments including `Accept`, the default `Content-Type` and the payload value that overrides it under three spellings, tolerant handling of missing or non-mapping `headers`, the strict `200` criterion, 5xx retry with the 3 s and 4.5 s backoff before giving up, a 4xx response not retried inside its domain, a network exception ending its domain, the penguin backup domain, the backup domain staying unused for 一图流, for a foreign URL and for a penguin domain appearing only in a query string, the one-shot WARNING and the later DEBUG line for 一图流, both labels, and scheduler wiring proving `30000` reaches `upload_report`, that other message codes do not, and that an upload failure never escapes the callback. The penguin tests of `maa_stage_inventory_scheduler_tests.py` are rewritten for the opt-in default, and the existing suites pass.

Interface evidence: [MAA callback protocol](https://docs.maa.plus/zh-cn/protocol/callback-schema.html), [MAA desktop client callback handler](https://github.com/MaaAssistantArknights/MaaAssistantArknights/blob/dev-v2/src/MaaWpfGui/Main/AsstProxy.cs) and the client sources at [commit `4a2084f2`](https://github.com/MaaAssistantArknights/MaaAssistantArknights/commit/4a2084f2dad2740d388ad71305a3d5beac7fa498).

## Standards Findings

Pass: the upload leaves the MAA callback thread at once on a daemon thread, so no network wait reaches the callback and no pending upload holds process exit. The worker converts every HTTP and network exception into a log line, and `_post` guards its whole body so an exception that escapes the inner handler still becomes a line instead of a silent `threading.excepthook` report. The retry budget is bounded twice over — `REPORT_ATTEMPTS` per domain inside the `REPORT_TIMEOUT` connection and read deadlines, with retries confined to 5xx so a client fault never multiplies requests — which is what [INV-MAA-03] fixes. Payload and URL validation complete before any thread starts, and `on_maa_callback` guards the handover, so neither a refused payload nor a failed thread start can raise out of the C callback boundary. Lines go through the project's shared logger, so they keep the runtime log policy that serves the terminal, `runtime.log` and the WebSocket log page. The new configuration field follows the pydantic default and docstring convention of its neighbours, and the UI row mirrors the existing 一图流 control rather than adding a new pattern. No Device Profile, Scheduling Plan or glossary definition changes; `CONTEXT.md` and `CONTEXT.zh.md` remain untouched.

## Spec Findings

Pass: the change implements the delegation split the MAA protocol defines — core decides reportability and prepares the request, the client sends it — and `on_maa_callback` hands exactly the `30000` payload to `upload_report`. The network policy matches the ported client behaviour parameter for parameter: a 15 s connection and read deadline per attempt, 3 attempts per domain, 5xx-only retry with the 3 s and 4.5 s backoff, strict `200`, the penguin backup domain, and DEBUG for a non-penguin failure apart from the first one, which is promoted to WARNING so the WebSocket log page carries it. Each of the three client behaviours left out — the `txwy` skip, the PC-connect skip and the `x-penguin-set-penguinid` write-back — is recorded with its reason, as are the three differences the port itself introduces. Refusal of an unusable or host-less payload, tolerance of a missing or non-mapping `headers` value, case-insensitive `Content-Type` precedence for a payload-supplied value, host-level comparison for the backup domain, the label fallback for an unknown subtask that still uploads, and the opt-in default that closes the silent drop all match the stated contract and the [subsystem specification](../../../../docs/subsystems/maa-integration.md). Offline tests cover every boundary above; live uploads to the statistics sites stay outside them.
