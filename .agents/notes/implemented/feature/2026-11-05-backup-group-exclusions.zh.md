# 支持显式互斥的并行副表分组

## 问题

[副表分组选择](../../../../docs/subsystems/base-scheduler.md#backup-group-selection)原先只选择一个分组及其中一张互斥副表。贸易与制造的独立替代方案必须改成全局叠加项才能同时生效。

## 决策

按现有分组优先顺序选择满足条件且可共存的分组，显式互斥关系双向成立。每个生效分组提供一个互斥副表名额，跨组复用的副表占用所有生效归属分组的名额。全局副表继续受分组归属限制，按副表顺序只合并一次。导入旧配置时保留原有组间互斥关系。初版实现沿用单组选择时的默认组兜底规则；当自定义条件覆盖上班和休息等全部状态时，默认组中的副表永远无法参与选择。默认组现改为与自定义组同时参与选择，其中的副表仍须满足自身条件。

## 考虑过的替代方案

增加域或场景可以提供独立选择，但加重编辑与嵌套。任意副表互斥把配置分散到更多副表上。有向分组压制需要处理第二套优先关系及循环。分组互斥复用现有组顺序，用户只需配置一次关系。

## 验证

初版实现的本体定向测试通过 358 项，包含完整换班生效与元组状态存档、跨组合并校验失败、默认兜底、条件关联、快照隔离、共享互斥名额及不变状态收敛。初版实现的前端与演算定向测试通过 154 项，覆盖双向编辑与删除、旧配置及并行配置的 JSON 保存、优先级选择、各组独立选择及投影生效。生产构建包含收益 Worker。离线浏览器操作确认互斥双向同步及新建分组的 `True` 条件。本次未使用真实设备。

默认组修正由本体选表与合并驻员校验测试、演算选表测试，以及 [`incomeDefaultGroup.test.js`](../../../../ui/src/riic/incomeDefaultGroup.test.js) 中的原表覆盖。阿罗玛上班和下班时，远牙低优休息配置均能随自身条件应用和移除；预热 3 天、统计 28 天的完整演算中，该副表能启用和退出，原表保持不变。验证采用全员满练和无限材料，没有使用现场练度或库存快照。

## 后果

并行分组会产生新增的合并驻员冲突。旧版本只选择一个分组，不支持并行配置；恢复升级前配置才能恢复原有选择规则。跨组互斥副表优先保留当前项，因此不保证同时选出的方案数量最多。用户已批准精确的双语术语定义。新建分组条件默认为 `True`；旧配置缺省条件及显式空条件仍不生效。互斥名单保留原有组间限制，但冲突统一按分组列表优先级处理，不再保留优先级较低的当前组。
