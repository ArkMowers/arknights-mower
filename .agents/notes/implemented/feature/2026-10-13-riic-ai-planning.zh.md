# 基建 AI 排班

## 问题

Mower AI 缺少将已保存的干员练度、已有基建组合和设施驻员关联起来的工具。完整导入外部机制 skill 的目录和浏览器资源会重复 Mower 已维护的数据。

## 决策

[AI 助手说明](../../../../docs/subsystems/ai-assistant.md#riic-tools) 定义三项只读工具：干员与组合概览、当前技能及嵌套术语查询、独立排班草案检查。完整草案与局部主班共用试排工具；`plan_generation` 主题指导按当前 BOX 和库存设计单一布局。[实现](../../../../arknights_mower/agent/tools/riic.py) 使用已有阶段选择和 BOX 读取逻辑。用户明确给出的拥有和练度仅在本次调用优先于 BOX，并单独标注来源。

前端与 AI 共用一份 JSON 中的二十组组合定义。仅补充 v078 中缺失的三名干员，同名资源包记录优先。补充的角色标识在通用映射尚未收录时解析 BOX 拥有状态。现有词汇定义保持原义；此适配不修改排班执行逻辑或持久化结构。

## 考虑过的替代方案

复制完整外部目录及 HTML 浏览器保留了第二份 skill 分发包，但会重复干员与术语来源。精简解释指南配合三条缺失记录，使用现有 Mower 读取逻辑保留所需信息。

独立 skill 执行器或优化器增加运行时依赖，三项工具操作并不因此改善。现有聊天工具流程分发相同函数。用户撤回独立生成按钮和固定整表构造器，因为预设表无法覆盖不同 BOX 的选择。[已归档原型](../../archived/feature/2026-11-17-main-plan-generator.zh.md)保留比较依据，后续使用已有 skill 与原生校验。

## 后果

试排展示拥有、练度、当前技能阶段、已配置工位和主班重复占岗错误，不保存或执行草案。旧的局部主班检查不检查替班匹配；完整草案保留替班和多绑组，在隔离模型中运行原生结构校验。救急草案解析继承工位，新填写的干员排除正常排班已占用的姓名。副表触发、实际心情恢复、全局联动、电力和长期收益仍有明确限制。检查通过不表示长期轮休可行或 Scheduling Plan 最优。数值验证仍使用已有前端收益窗口，此扩展没有增加后端演算执行器。

固定外部指南覆盖 432 名干员。共享目录在本工作区原有 429 条记录上补充德·托莱多、克莱门莎和旅骨。资源更新提供同名记录后自动替代补充记录。

## 验证

[定向离线测试](../../../../arknights_mower/tests/riic_assistant_tests.py) 覆盖同槽升级、用户覆盖、缺失 BOX、拥有与练度错误、保留设施冲突、容量及两种模型分发流程。[共享资源测试](../../../../arknights_mower/tests/building_skills_tests.py) 覆盖补充角色的 BOX 身份和资源包同名记录优先。前端测试覆盖共享组合及聊天建议。真实模型推理与设备操作尚未测试。

外部 skill 格式检查通过。GameData、工具箱与 PRTS 检查为 current；Mower 回收站源码检查超时，总体时效状态保留 unknown。固定指南单独记录此限制，不将其等同于运行时目录覆盖。

机制查询另补分类、排班兼容、新干员、收益导出及来源时效主题；数值请求指引[前端收益窗口](../../../../docs/subsystems/plan-editor.md#income-export)，AI 不声称已代用户运行演算。[开发者 skill](../../../skills/mower-riic/SKILL.md)规定共享资源维护、固定源码摘要及定向验证入口。六项新增查询与枚举测试通过，保持当前解锁技能、原排班和敏感配置隔离。

完整表与执行链测试另覆盖真实原生组匹配、替班及充能对象的拥有和练度、救急继承与保留姓名排除、安全上下文快照，以及保存聊天调用链中较大 JSON 的完整传递。这些仍是离线检查，不表示已完成真实模型寻优或 AI 七天演算。

可运行草案不等于优化结果。排班指南要求按实际 BOX 检查相关且有竞争力的核心组合，依据机制和约束说明纳入或排除理由。身份联动挂件与挂件本人的技能解锁分开判断。候选收益排名仍需同条件演算；结构通过或沿用原肥鸭目标均不能证明安排最优。
