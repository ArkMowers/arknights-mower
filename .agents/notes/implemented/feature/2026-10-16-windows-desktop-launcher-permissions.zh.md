# Windows 桌面程序继承启动者权限

[English](2026-10-16-windows-desktop-launcher-permissions.md)

## 问题

此前强制提权的启动策略使没有管理员凭据的普通 Windows 账户无法打开两个打包桌面入口。[原有决定](../../archived/feature/2026-10-11-windows-desktop-elevation.zh.md)通过原生清单在启动前取得提升权限并传给管理器实例，同时也把管理员授权变成所有用户的使用前提。

## 决策

[Windows 打包配置](../../../../webui_zip.spec)中的两个可执行文件通过 `uac_admin=False` 使用 `asInvoker`。管理器沿用现有进程启动方式，继承调用者权限。此决定取代此前的强制提权策略；[Arknights Mower 软件更新子系统说明](../../../../docs/subsystems/software-update.md#14-windows-desktop-launch-permissions)定义启动与目录访问规则。领域概念含义保持不变，无须修改术语表。

原实现还在实际安装目录生成可选的管理员启动链接，避免写入构建机路径，并在搬动目录后刷新。生成过程有超时限制，失败不阻止启动。这项可选功能已按用户要求移除：Windows 已提供“以管理员身份运行”，运行时生成链接还需要启动 PowerShell 并编译辅助代码。已有链接保留在磁盘上，但不再自动刷新；上述继承启动者权限的决定继续有效。

## 考虑过的替代方案

保留强制提权会排除无法提供管理员凭据的用户。在访问失败后再次请求提权仍不能让这些用户获得授权，还会增加重启行为而不解决文件权限。继承权限允许普通启动，并保留 Windows 的“以管理员身份运行”选项，供有授权且确有需要的用户使用。

## 后果

普通用户可以直接启动程序，无须请求提升权限，但便携安装目录、数据目录和 MAA 目录须允许其写入。模拟器和 Windows 施加的访问限制继续生效。已有 EXE 在被替换前保留内嵌清单，无法启动旧包的用户需要重新打包后的完整包。从已提升进程执行更新仍会继承提升权限，须退出该进程树并重新普通启动。

## 验证

原实现的发布流程、管理器和快捷方式的 57 个定向离线测试通过；一项原生 Windows Shell 测试在 macOS 跳过。修改后的启动权限检查在旧打包配置下失败。测试检查两个可执行文件声明，执行发布清单检查并输入应接受和应拒绝的清单，核对管理器直接启动实例时的参数、工作目录和环境。清单检查拒绝强制或可选提权、UI 访问、缺失清单和缺失执行权限声明。已移除的快捷方式测试曾覆盖两个桌面调用入口、平台隔离、实际 EXE 目录选择、有界进程调用和失败后继续启动。已移除的 Windows CI 原生测试读取两个快捷方式，检查目标、工作目录、提升标记、重复启动及目录迁移；此项未在 macOS 环境运行。普通账户交互启动、UAC、模拟器访问和更新重启仍须在 Windows 验证。

移除自动生成快捷方式后，发布流程、管理器、桌面进程和桌面生命周期的 70 项定向测试通过，继续覆盖清单和权限继承；当前实现不再包含快捷方式创建或 Windows Shell 集成。
