# 助手操作确认与执行依据保存

## 问题

[AI Assistant 说明](../../../../docs/subsystems/ai-assistant.md)此前将工具进度与回答混在一起，写入确认依赖模型指令。只有文本历史无法说明哪些工具实际执行，也无法防止中断请求重试时重复写入。

## 决策

随每轮对话保存有容量限制的工具依据和操作结果，由[执行模块](../../../../arknights_mower/agent/execution.py)负责工具分类、具体参数确认、停止请求和重试去重。写入前先保存执行记录，中断后保留不确定结果。只允许重试最近的中断轮次，并将操作记录带入重试。工具进度与最终回答上下文分开，用户明确核对后的摘要可以补充近期上下文。

## 考虑过的替代方案

只靠提示词无法约束实际参数。恢复执行图检查点可能在崩溃结果不明时重复操作。自动重试邮件或数据库写入也不能保证只执行一次。本方案在重试时拒绝重复任何已尝试的写入，包括结果不明的操作，并要求用户核实结果。

## 验证

[执行测试](../../../../arknights_mower/tests/ai_execution_tests.py)通过真实 WebSocket 和 HTTP 控制入口完成定向离线验证，覆盖具体确认与状态变化、拒绝和超时前无副作用、等待确认及已开始写入时停止、中断重试、子进程在写入期间退出、只读 SQL、写入回读、旧数据库迁移及明确采用摘要。协议测试使用模拟 HTTP 响应验证两种 OpenAI 格式和自动回退的持久会话流式调用。反馈检查测试使用模拟确认和 SMTP 传输，执行真实资料收集与 MIME 生成。前端测试覆盖依据、确认、停止、重试和摘要控制。未调用真实模型服务、验证邮件送达或操作游戏设备。

## 后果

停止不能撤销已经开始的操作，模型读取在下一个流式片段或既有超时后结束。邮件服务接受邮件不等于收件人收到。依据与摘要有容量限制，可能缺少更早记录；模型文字属于推断，不能代替执行结果。确认等待有截止时间，等待期间当前请求仍占用对应配置档案，不能切换档案。


当前操作规则归属 [AI Assistant 子系统说明](../../../../docs/subsystems/ai-assistant.md#confirmed-tool-execution)。现有配置档案、专精计划和排班表概念保持原义，无需修改术语表。

[会话重连规则](../../../../docs/subsystems/ai-assistant.md#live-conversation-reconnection)使原有执行不依赖查看它的连接。复用当前请求处理线程和有容量限制的内存快照，无需增加任务服务或另一套框架。用户返回后可在原截止时间前查看并决定同一待确认操作，不重新发起模型或工具调用。服务进程重启仍使旧确认失效，并沿用明确重试的边界。`ai_resume_tests.py` 使用离线模型响应，通过实际路由处理函数验证连接恢复、回执丢失、确认操作与会话归属。

[未完成任务继续处理规则](../../../../docs/subsystems/ai-assistant.md#continue-incomplete-task)沿用同一执行记录，在停止后由用户明确开启新一轮处理。复用有容量限制的已保存依据、未完成文本和原始目标，无需额外调用模型生成摘要或引入另一套持久化框架。写入尝试仍由操作记录核对，旧确认标识不能授权新一轮操作。继续处理测试覆盖查询进度传入模型、来源轮次淘汰和重新打开存储后多次继续、邮件已接受或结果不明时防止重复写入，以及停止后重新确认。测试使用离线模型响应和现有 WebSocket、控制入口。保存的进度可能被截断或过时，参数匹配不能识别所有语义相同的写入。
