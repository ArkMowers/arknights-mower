# 普通调度共用收益引擎的心情计算

## 问题

普通调度原先使用房间观测与实测心情消耗速率；[收益图片决策](../../implemented/feature/2026-10-14-plan-income-export.zh.md)则在浏览器 Worker 中运行固定版本的 TypeScript 计算器。“实时心情计算”需要使用计算器的技能效果，同时保留普通调度的任务执行、实读与重启恢复。将公式另译为 Python 会形成两份需要同步维护的实现。[Arknights Mower 基建调度子系统说明](../../../../docs/subsystems/base-scheduler.md#calculated-mood-test)负责说明本次选择形成的行为规则。

## 决策

排班高级设置中的“实时心情计算”默认关闭，开启后普通调度使用计算心情。[`runtimeMood.ts`](../../../../ui/src/riic/runtimeMood.ts)将观测输入交给收益引擎已有的心情和宿舍恢复函数。构建时将这些函数及其依赖打包成纯 JavaScript，随 Python 程序发布，由内嵌的 `quickjs-ng` 执行。用户无需安装 Node.js，也无需打开网页。收益演算继续使用浏览器 Worker；两条路径共用公式源码与技能阈值规则，分别持有状态和时间。

Python 的 [`CalculatedMood`](../../../../arknights_mower/utils/calculated_mood.py)负责观测、经过时间、操作事件和持久化模型数据；JavaScript 根据传入数据计算技能效果与速率。未来时刻查询与预演驻员使用独立状态，计算值不替代房间实读。运行快照保存普通模型数据，并去掉干员对新增运行类的引用，使旧版本仍能反序列化实际驻员与未完成任务。启动时恢复兼容的模型数据，再进行初始化实读，并保留已开始工作。观测与操作事件分别负责校准和结算，避免操作后读回心情时再次计算同一次变化。训练策略、实际换人和补偿继续由原有执行流程负责。

有有效森空岛练度缓存时，按缓存中的精英阶段和等级选择已解锁技能；用户已明确选择缺少有效缓存的干员按满练技能计算。宿舍氛围采用对应等级的满氛围，设置说明披露这两项假设。演算不将假定的练度或持有情况写入 BOX。设施等级来自运行排班的启动快照，练度缓存变化则刷新技能输入。普通调度日志继续显示收益引擎已有的未量化技能提示。

心情消耗速率、初始化心情观测、有效心情缓存及实际驻员／预演驻员继续沿用已有含义。本次选择增加计算与读取行为，不改这些概念的名称或定义，无需修改术语表。

## 考虑过的替代方案

另写 Python 公式可以减少 JavaScript 运行依赖，但会复制技能算法，使收益与普通调度的修正容易不同步。运行时要求 Node.js 会增加用户安装要求和进程管理。依赖浏览器 Worker 则要求普通调度期间持续打开页面。发布 JavaScript 产物并内嵌运行时可以共用公式源码，也符合由 Python 持有调度状态的现有责任划分，代价是增加需要发布的运行时和可重复的构建步骤。

## 验证

最终 29 组定向 Python 离线检查分五个独立进程全部通过：核心 59 项、原有行为 279 项、消费模块 240 项、调度 313 项、配置 28 项，共 919 项。[核心运行测试](../../../../arknights_mower/tests/calculated_mood_tests.py)覆盖真实 QuickJS、精确零心情技能边界、未来查询与预演隔离、绕过近期缓存的初始化实读、选人页面补齐、训练双槽读取、练度缓存更新和启动设施等级。实际确认入口验证首次提交前拒绝失效的回班、离宿安排，保留已开始或显式安排，保存失败时不点击提交。实际加工入口以泥岩满练固定减耗完成三次加工，只结算一次共 6 点心情，再以实读 22 点校准；读不清时保持未知，提交前保存失败则不提交。

[启动测试](../../../../arknights_mower/tests/calculated_mood_startup_tests.py)经过实际恢复入口，覆盖旧快照、兼容及失效模型，以及不依赖新增计算类的 SQLite 快照反序列化。[消费模块测试](../../../../arknights_mower/tests/mood_calculation_consumers_tests.py)和[预演消费测试](../../../../arknights_mower/tests/mood_calculation_projection_consumers_tests.py)覆盖替班准入、恢复期限、召回、普通轮换演算，以及没有新观测时保留失败任务且不轮询。发布验证使用实际打包函数采集资源，转换为 CRLF 后在可执行文件搜索路径为空的环境运行。前端 65 项定向检查和生产构建通过。打包源码与产物检查、文档结构检查单独通过，不替代行为证据。审查确认本记录所述责任边界；尚未观察真实设备行为，也未完成各平台发行包构建。

## 后果

共用公式源码免去另一份 Python 实现，但增加了需要发布的 JavaScript 运行时；公式源码变化后也须重新生成产物。摘要与源码检查可以发现过期或损坏产物，不能证明游戏内效果准确。缺少练度缓存时按满练技能计算，宿舍每级按 1,000 点氛围计算，部分技能仍未量化。未知设施输入或结果不确定的操作保持未知心情，等待正常观测校准，不增加专门巡检。用户不接受这些假设时可以保留默认关闭状态。普通调度和收益演算的调度策略仍分别维护，因此共用技能公式不代表演算收益已经证明真机可执行。
