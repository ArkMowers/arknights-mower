资源 OTA 仅保存新增或变化的资源文件，以及完整目标文件摘要清单。[INV-RES-02] 资源 OTA 重建要求起点资源版本精确匹配，校验所有重建目标文件，并通过现有不可变资源安装器发布完整兼容版本。在线失败回退同一发布版本的整包，手动包保持离线。

Android 发布通过现有必需文件清单与归档校验器提前检查构建后的 buffer 产物。输入缺失、为空或仅含空白时，在创建归档前失败；归档校验拒绝空条目。检查沿用 WebUI 构建的 `ui/dist/pages/basement_skill/buffer.json` 路径，OTA 重建、原始文件复制与 CRLF 处理保留在原有实现中。决策和不变量保持当前状态，领域概念和配置结构不变。

内置起点文件修复遵循[资源契约](../../../../docs/subsystems/resource-update.md#1-resource-ota)。此前的便携版测试目录包含真实应用包省略的前端源码。修订后的测试执行 WebUI 构建后的复制步骤、桌面数据收集和 Android 归档构建，再调用安装器与离线手动入口。修复前两种安装目录均重建失败，修复后所有目标字节与整包一致。外部资源版本缺少目录数据时仍拒绝安装，不借用内置数据；既有摘要、回滚和在线回退回归保留原边界。

同一测试目录覆盖 LF 与 Windows CRLF 输入。CRLF 回归先复现已有资源哈希归一后仍发生大小不匹配的问题，再验证有界的内置文本重建生成准确的发布字节，包括跨读取边界的 CRLF 字节对。文本内容篡改、二进制内容改变及外部文本换行改变仍返回失败，并保留原资源版本。编解码模块保持仅依赖标准库、可独立加载；安装器传入已有的声明文本文件集。

前置简化复用下载代理、安装锁、兼容检查、不可变版本目录与任务边界加载。生产端与安装端共用标准库编解码模块。MowerResource 最多从四个保留版本生成直达更新，差异包达到整包的百分之八十五时不发布。目标清单未包含的旧文件自然删除。

现有领域概念、调度行为与配置结构未变，无需修改词汇表。验证覆盖不可变版本目录发布和任务回退、起点与摘要不符、文件删除、非法路径、下载限制、手动安装及发布附件顺序。

标准审查确认下载预算、清单容量、暂存目录清理和活动版本保留，并复用现有进程锁与文件安装锁。规格审查确认精确起点选择、同一目标的在线回退、离线手动安装及兼容旧客户端的整包。历史发布查询或单个起点生成失败时，完整资源包仍可发布。

验证证据：OTA、进度、资源包、手动更新与版本的定向测试通过，共 94 项测试及 15 项子测试；发布端通过 17 项测试。Ruff、组件 ESLint 与仓库治理检查通过。使用已发布资源从 `v2026.09.29-5f4591c` 重建到 `v2026.10.09-466ab33`，全部目标摘要一致：1,900 个文件中 6 个变化，整包 13,495,813 字节，OTA 5,519,896 字节，缩小百分之五十九点一。这些检查验证实现；GitHub 合并和资源 Release 发布属于独立操作。

CI 代理回归覆盖 OTA 索引和回退整包经配置的 GitHub 代理站、全局 HTTP 代理及默认回退站的请求。默认站测试拒绝所有非测试服务请求，使真实 OTA 索引发布不会将该测试引向在线资源附件。

同日重建补齐头像时，上游 `last_updated` 数据快照可以保持不变。[共享资源修订契约](../../../../docs/subsystems/software-update.md#9-shared-resource-revisions) 区分渠道及已接受安装顺序与哈希排序。安装器在现有原子索引中记录内置资源基准，保持整包选择、任务边界与回滚，不改变公开资源清单。资源、OTA、进度、手动更新与版本专项通过，共 106 项测试及 17 项子测试，覆盖 `23806b7` 到 `3c94100` 的检测、同日整包与 OTA 安装、重启保留以及新内置资源优先级。
