# 运行日志的只读每日完成状态

## 问题

最初的运行日志提案需要显示“全部设置”中启用的任务在当前游戏日是否已处理。前端通过 [`model.js`](../../../../ui/src/task-workflow/model.js) 知道选中了哪些任务，但完成情况保存在调度器属性和普通运行缓存中。浏览器本地日期可能不同于北京时间 04:00 切换的游戏日。[`/status`](../../../../server.py) 已负责“开始”和“停止”按钮的状态，因此清单读取失败和额外的缓存读取需要独立处理。

每日记录不能描述所有已启用活动。公开招募、仓库扫描、信赖轮换、线索交流、购物、专精、加工、作战计划和长任务分别受间隔、条件或队列进度控制。检查返回不代表实际操作已完成，把这些事实统一标成每日完成会改变原有含义。

## 决策

只读的 `GET /daily-status` 将调度事实与前端选择分开。后端负责游戏日和记录含义；前端筛选已启用的日常任务并呈现状态。[Arknights Mower 基建调度子系统说明](../../../../docs/subsystems/base-scheduler.md#29-worker-status)负责完整的记录、活动、来源和初始日期规则。[Arknights Mower Web 访问子系统说明](../../../../docs/subsystems/web-access.md#1-session-boundary)要求在状态或文件系统读取前验证当前实例令牌，并使此接口的失败不影响 `/status`。

响应保留 `game_day`、`source` 和 `records`，另用独立的 `activities` 表达最近检查、执行条件、队列事实、实际执行观察和匹配的长任务进度。每日 `done` 表示调度器会在当前游戏日剩余时间跳过该项工作；活动签到和访友的 `attempted` 单独保留。缺少的活动事实保持未知。接口读取不改变调度、任务身份与顺序、时间戳、配置或持久化内容，读取长任务进度也不创建或保存运行记录。

`live` 读取存活工作线程中已恢复的调度器，复制回调可能修改的映射，不调用代价较高的完整运行快照。`saved` 读取普通启动会恢复的内容，省略仅运行中可知的检查时钟，并将原来的运行中观察显示为已停止。`none` 表示恢复尚未完成或没有可读的保存数据。缓存避免反复解析未变化的保存行；损坏的运行缓存不影响 `/status`。

作战计划、仓库扫描、剿灭和任务奖励检查在真实入口及退出路径记录执行观察。本地作战次数对应最近一次单关执行。MAA 观察只接受当前回调代次和已接受的任务 ID，不编造作战次数。剿灭观察在游戏周边界失效，只有实际观察到 1800 上限才报告 `reward_full`。长任务进度要求配置队列身份匹配。队列读取有数量上限，截断后仅报告下界计数，不推定最早时间。这些显示事实沿用已有保存点，不新增持久化触发。

新建调度器的五项本地每日日期统一初始化为前一个游戏日，尝试日期保持为空；恢复记录的日期不变。此前按本地日期减小时数可能使 UTC+8 以东时钟上的基报、森空岛和访友日期等于当前游戏日，例如 UTC+9 的当地 04:00 至 05:00。首次启动因此会跳过工作，并错误显示为 `done`。

最终清单只显示已启用且具有游戏日记录的任务，并且仅在调度器运行且提供实时记录时显示。2026-11-07 用户调整了原先显示保存记录的选择，因为启动时先显示保存记录、恢复期间隐藏、随后显示实时记录会使清单反复出现。接口仍保留保存来源。周期活动曾尝试横向概览和可展开列表，最终作为独立事实留在响应中。宽屏桌面显示每日任务标签，上下排列时通过标题在“运行日志”和“今日任务”之间切换。[运行日志显示规则](../../../../docs/subsystems/web-access.md#task-configuration)负责筛选、布局、刷新和取消。此选择不新增领域概念，也不改变现有完成记录的含义，因此负责领域定义的 [Arknights Mower 项目术语表](../../../../CONTEXT.zh.md)无需修改。

## 考虑过的替代方案

- 在 `/status` 中增加字段可以沿用五秒轮询，但应用启动和排班编辑会收到用不到的数据，停止期间也会额外检查缓存，每日读取失败还会影响“开始”和“停止”按钮的状态响应。
- 只报告运行中的调度器可以避免解析保存内容。原设计为停止后查看进度保留了 `saved`；后来隐藏清单不需要删除这项接口能力。
- 浏览器从日志文字推断完成状态依赖持续变化的措辞，也不能用本地时钟代替游戏日。
- WebSocket 推送可以立即更新，但这些记录变化不频繁，轮询读取已能在导航或重连后恢复显示。
- 为间隔任务增加每日完成日期需要重新定义完成含义并增加调度状态。独立活动事实可以保留部分进度、排队工作和未知内容，无需另建重复负责显示与数据来源的决策记录。

## 验证

2026-11-01 的历史验证针对原每日标签条：[`daily_status_tests.py`](../../../../arknights_mower/tests/daily_status_tests.py) 通过 11 项测试、50 项子测试，覆盖游戏日状态、令牌拒绝、实时及保存来源、无可用数据、状态不变和每个保存行只解析一次。[`daily_default_date_tests.py`](../../../../arknights_mower/tests/daily_default_date_tests.py) 在 UTC-5 至 UTC+14、三个服务器时刻下通过 18 项测试。`Log.test.js`、`LogOutput.test.js`、`model.test.js`、`mock.test.js` 四份前端测试通过；1440×900 离线浏览器预览检查了两种主题、保存来源标记和当时的移动端隐藏方式，结构检查也通过。这些结果描述早期显示，不能证明后来的清单布局已验收。

2026-11-07 至 11-08 评审通过了后端接口及活动定向测试，包括 [`daily_status_tests.py`](../../../../arknights_mower/tests/daily_status_tests.py) 和 [`activity_observations_tests.py`](../../../../arknights_mower/tests/activity_observations_tests.py)，覆盖读取前认证、实时及保存事实、队列顺序与持久化不变、本周剿灭、匹配长任务进度、截断和有效回调观察。

当前 [`Log.test.js`](../../../../ui/src/pages/Log.test.js) 通过，覆盖日常任务筛选、只选部分奖励、空记录和不可用记录、仅实时显示、请求取消和迟到响应拒绝。

本轮没有新增真实设备或真实浏览器观察。未修改的上游 `maa_daily_refresh_tests.py` 使用 `time.tzset`，在 Windows 上无法运行，没有计为通过。旧浏览器证据不能验证当前布局。

## 后果

- 清单报告调度器事实，不独立核验游戏结果。邮件流程返回即记为完成；MAA 访友没有尝试记录，`maa_mail` 没有每日记录。检查、队列安排和长任务进度不代表每日完成，MAA 任务链结束也不提供作战次数。
- 运行缓存仍沿用已有保存点。活动签到、访友尝试、MAA 回调和 `/stop` 会保存；基报、森空岛、邮件和本地访友成功后可能等待之后的保存。仅经过 `_stop_mower` 或突然终止不保存，保存来源因此可能缺少最近完成的工作，普通重启也可能重新执行。
- 宽屏桌面清单在页面可见且运行时每 30 秒增加一次请求；上下排列时只在“今日任务”中请求。停止后不再显示清单进度，但接口保留保存事实。无法兼容的缓存返回 `none`，不影响“开始”和“停止”。
