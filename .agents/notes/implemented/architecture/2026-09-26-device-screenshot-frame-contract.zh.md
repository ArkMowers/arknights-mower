# 设备截图校验与标准画面帧契约

[English](2026-09-26-device-screenshot-frame-contract.md) | [中文](2026-09-26-device-screenshot-frame-contract.zh.md)

## 1. 背景与动机
不同模拟器和设备在不同阶段（如启动中、黑屏加载中、平板横竖屏切换时）会返回尺寸各异或不符合模板匹配要求的图像。如果设备层直接对异常帧进行拉伸或裁剪，会导致 CV 识别算法产生误判。

本契约确立了统一的实际帧强类型校验标准，规定了不同截图后端的边界与单次重构机制。

---

## 2. 不变式与保证

- **[INV-01] 严格的实际帧格式**：预检与运行时仅接受形状严格为 `(1080, 1920, 3)` 的 `uint8` RGB 实际帧。禁止在设备控制层进行缩放、补边或将竖屏旋转为横屏。
- **[INV-02] 纯黑帧合法性**：全黑画面在数据结构与尺寸合规的前提下属于有效帧；像素颜色本身不决定截图通道是否异常（游戏启动冷加载期常出现短暂黑屏）。
- **[INV-03] 单次重建上限**：截图调用失败时，会话仅允许对当前选定的截图后端资源进行至多一次重建（Rebuild）；连续失败直接标记为会话异常，严守重连恢复上限，不重启模拟器。
- **[INV-04] 故障不写配置**：截图彻底失败时返回明确的错误原因与兼容的替代后端列表，绝不静默修改用户的持久化配置。

---

## 3. 后端契约实现

### 3.1 ADB gzip
- 读取目标设备的 Android SDK 版本，严格区分 12 字节头部（Android ≤ 8.0）与 16 字节头部（Android ≥ 8.1）。
- 校验 gzip 校验和与解压后的字节长度，拒绝截断或带有多余尾部字节的数据。

### 3.2 MuMu 12 Native IPC
- 保持原生返回码与返回尺寸，必须明确为 `1920×1080` RGBA。
- **显示绑定**：IPC 通道绑定实例自有显示（Display 0），而非根据游戏包名解析 Display。避免因游戏未启动渲染而导致 Display 绑定失败。
- **进程隔离**：原生调用由专属 Worker 子进程持有，单帧截图设置 10 秒硬超时。

### 3.3 DroidCast 1.3.0
- 启动后建立 HTTP 监听并校验单次请求，限制单张图像上限为 16 MiB。
