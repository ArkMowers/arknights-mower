# WebUI 与 runtime.log 的结构化日志交付

[English](2026-11-01-structured-log-delivery.md)

## 问题

原来的 WebUI 和 runtime.log 共用文本流，混合用户结果、开发参数、干员列表字面量和内部标识。对 169 个小时级文件、约十天的 214 万条记录进行调查，在 80,995 条真实 INFO 记录中发现 35,640 条场景识别日志。前端用正则重建日期、级别、设施和干员等后端已经掌握的事实。store 只保留 100 行纯文本，繁多明细会挤掉有用摘要；按子系统搜索 runtime.log 也需要解析源码路径和消息措辞。

最初实施时，另一个会话正在改写日志页面，因此先完成传输，再调整呈现。这是当时的实施顺序限制，现在已不是待完成依赖。共享 logger 和既有文本文件读取器仍是维护边界。

## 决策

[`log.py`](../../../../arknights_mower/utils/log.py) 在异步入队前捕获有容量上限的结构化快照。[`log_stream.py`](../../../../arknights_mower/utils/log_stream.py) 同时交付 `records` 和旧式 `data`；[`mower.js`](../../../../ui/src/stores/mower.js) 接受新协议及旧文本。可选元数据无效或过大时，源文字仍可读取。[Arknights Mower Web 访问子系统说明](../../../../docs/subsystems/web-access.md#live-log-records)负责字段、容量和认证要求；本记录保留源文字与结构化显示数据并存的理由。

业务调用点提供设施、干员列表、任务预告、公招结果和明确的操作身份，使页面能够更新原始摘要及其明细，不必根据附近文字猜测归属。任务预告捕获历史设施名称和驻员位置，之后编辑排班不会改写它们。[Arknights Mower 基建调度子系统说明](../../../../docs/subsystems/base-scheduler.md#task-presentation)负责任务动作和已确认进度的含义。显示快照不准备任务、不改变调度，也不单独证明操作已完成。

后端通过 [`log_history.py`](../../../../arknights_mower/utils/log_history.py) 统一保留源记录窗口。一次操作及其明确关联明细共同计为一项，额外的记录数量与序列化字节限制约束内存。稳定的流身份和序号使重连快照能够替换前端窗口而不重复追加。摘要原始记录与状态共同保留，避免明细淘汰后凭空恢复运行中或场景等待状态。[日志保留窗口](../../../../docs/subsystems/web-access.md#retained-log-window)负责完整规则。这取代原先的纯文本行数限制，因为仅在简洁模式隐藏明细不能保证摘要仍留在历史中。

[Arknights Mower 项目编码规范的应用日志规则](../../../../CODING_STANDARDS.md#6-application-logging)区分用户关心的进度与重复诊断。高频调用按该规则调整，不要求一次改写全部日志。相同场景重复、职业筛选步骤、截图遥测和内部标识仍在 DEBUG 中保留；面向用户的结果使用中文叙述。混合业务调用显式设置 `log_group`，其余由 [`log_groups.py`](../../../../arknights_mower/utils/log_groups.py) 按源码路径派生，未知来源保持无分组。

文件和终端的 `BASIC_FORMAT` 在时间戳后增加调用点显式提供的业务前缀，runtime.log 继续使用文本。结构化传输独立解析分组，不修改文件格式化器使用的字段。既有诊断时间线读取器继续接受旧格式和带前缀的行。

[`LogOutput.vue`](../../../../ui/src/components/LogOutput.vue) 呈现业务分隔、捕获的任务安排、操作进度、公招摘要和场景等待。详细及简洁模式保留源文字与时间顺序用于复制，操作关联依据明确身份，而非文字位置相邻。[`Log.vue`](../../../../ui/src/pages/Log.vue) 在宽屏中将截图和队列放在日志旁，窄屏中上下排列。[运行日志呈现规则](../../../../docs/subsystems/web-access.md#running-log-presentation)负责完整的显示与滚动行为；[每日状态决策](2026-11-01-daily-completion-status.zh.md)单独负责清单数据和筛选。日志级别、元数据和布局不改变排班表或实际驻员的含义，因此 [Arknights Mower 项目术语表](../../../../CONTEXT.zh.md)无需修改。

## 考虑过的替代方案

- 一次重写调查中的 1,583 个日志调用点，会将消息变化与并行调整的渲染器耦合，也更难逐项检查回归。先完成传输、再调整选定调用点，使兼容行为能够分别验证。
- 只改善约 1,500 个不同 INFO 及以上调用点的措辞，有助于文件阅读，但前端仍需用正则重建业务含义。
- 将 runtime.log 改成 JSON Lines 更便于结构化搜索，却要求更换既有查看器和诊断时间线解析器。业务前缀可以保留这些文本使用方。

## 验证

以下测量和测试结果来自 2026-11-01 至 2026-11-04 的原实施记录，属于历史证据，不是本轮重新回放的结果：

- 初始传输测试覆盖实时交付、历史、无间隙订阅、带令牌转发、本地日志读取例外和两种前端载荷。队列消费者、截图及归档测试在文本改为结构化记录后通过。
- 回放本机 2026-10-22 至 2026-11-01 的 169 个小时级文件，`get_scene` 的 INFO 从 35,000 降至 17,797（49.2%），全部场景 INFO 从 35,385 降至 18,182（48.6%），全部 INFO 从 79,932 降至 62,729（21.5%）。静默期取 30 至 300 秒时，`get_scene` 降幅为 48.7% 至 49.4%；剩余切换中有 2,592 次发生在基建场景 205 和 201 之间。维护者于 2026-11-01 接受实测降幅，不再为提案中的 50% 目标改变行为。原先“仅此一项使全部 INFO 减半”的估计不成立。
- 漏单分析器未修改。持续的 `Scene 9998` 仍每 60 秒产生一条 INFO，但按一秒滑动的两分钟窗口中，原来包含这类 INFO 的有 3.46% 不再包含。这些窗口里的等待场景日志只出现在第一分钟，且窗口开始前不足一分钟已有相同场景报告。
- 九个线索流程内部标识改为 DEBUG，其 1,705 条日志占该流程 2,167 条 INFO 的 78.7%，约占该次回放 79,188 条 INFO 的 2.2%。连同场景筛选，INFO 降至 60,414 条（23.7%）。定向线索测试在修复前失败，修复后通过。
- 职业筛选遥测减少原有 10,286 条实时 INFO，定向测试通过 27 项。截图遥测减少原有 1,910 条 INFO，两项定向测试通过。归档告警限频由 30 秒改为 600 秒，将中位间隔为 30.3 秒的 1,196 条回放告警减少到 65 条，定向测试通过。
- 驻员中文叙述及房间、干员结构化字段替换列表字面量；2,170 条换班播报中有 44 个空列表改为 DEBUG。两项选人测试在改动前失败、改动后通过，队列交付测试验证了字段。该中间阶段前端尚未读取字段，最终渲染器已经使用。
- 本地作战和角色信息日志重分级后，15 份文件的 233 项测试通过。回放中没有这两个模块的记录，因此没有测量它们的数量降幅。代理失败、放弃和未知场景仍可能继续后续关卡，消息不再错误宣称整次作战已结束。随后调整的调度日志共 32 处，纠正了原先 19 处的漏计；14 项新测试在修复前失败、修复后通过，回归批次通过 657 项。
- 分组派生的验证批次通过 58 项测试、133 项子测试，其中分组测试为 15 项。后续任务预告的后端验证覆盖名称、副表边界、停止、快照和认证队列查询；六份前端文件通过 330 项，生产构建通过。离线浏览器检查五个排队任务和包含八个设施、27 个位置的预告，在浅色、深色和窄布局中未发现横向溢出或头像加载失败。未观察真实设备。

2026-11-07 至 11-08 评审通过传输、历史保留、认证、业务日志及前端定向测试。[`log_history_tests.py`](../../../../arknights_mower/tests/log_history_tests.py) 和 [`log_stream_tests.py`](../../../../arknights_mower/tests/log_stream_tests.py) 覆盖历史及交付，[`log_display_payload_tests.py`](../../../../arknights_mower/tests/log_display_payload_tests.py) 检查显示快照。[`LogOutput.test.js`](../../../../ui/src/components/LogOutput.test.js) 与 [`mower.test.js`](../../../../ui/src/stores/mower.test.js) 覆盖源文字复制、分组、进度、滚动和重连。队列顺序回归在修复前失败，限制为仅合并相邻同一时刻的刷新任务后通过。

本轮未新增浏览器或设备运行，也未重复历史日志数量回放。未修改的上游 MAA 每日刷新测试夹具需要 `time.tzset`，无法在 Windows 上运行，不能计为通过。历史浏览器及构建结果仅描述当时的源码版本。

## 后果

结构化快照使已支持的业务关联不再依赖从文字猜测，但旧文本回退仍是兼容成本。不支持或无效的元数据必须保留可读文字。新增分组需要与维护其说明的子系统协调，缺少分组仍是合法输入。

有容量上限的实时窗口可能丢弃旧明细或整次操作。复制还原的是仍保留的源记录，不能恢复已淘汰内容；runtime.log 在原有保留策略下仍是更完整的诊断来源。减少 INFO 提高可读性，同时接受上述漏单分析窗口损失。

大型调度器中的消息调整仍须检查真实业务调用路径，显示改善不能改变调度选择、失败处理或恢复。完整接口规则留在子系统说明，决策理由保留在本记录，无需为每个日志调用点或界面调整另建记录。
