# 排班干员持有与练度检查

在正常排班或救急排班编辑中点击「验证排班」时，会检查主表、副表中的主班、所有绑组的替班，以及副表换人任务中的干员。空位、`Current` 和 `Free` 不参与检查。

检查使用森空岛干员缓存，并按以下情况弹出 warning：

- 排班干员未出现在持有名单中。
- 除孑以外的排班干员尚未完整解锁基建技能。解锁要求来自基建技能目录，包含精英阶段和等级。
- 会客室主班、替班或换人任务中的四至六星干员尚未精二。
- 训练室第二个位置的训练位干员基础技能不足七级、所有技能均已专三，或无法确认技能数据。协助位不参与这两项训练技能检查。

这些 warning 沿用原有校验横幅，提示“可能会导致 Mower 无法正常运行”，不会自动消失，需点击 × 关闭；不记录、不阻断校验或启动、不发送通知。成功、排班结构错误、校验未完成和校验请求失败的结果横幅也需手动关闭。启动或运行时的检查不弹出这些横幅。排班结构错误仍按原有规则处理。完整规则见[排班名单警告契约](../docs/subsystems/base-scheduler.md#schedule-roster-warnings)。

发现上述情况时，保存的排班校验和启动校验会尝试同步一次；同步失败仍提示已有缓存中的问题。请在游戏中获取、培养或更换相关干员，再到「养成规划」页面手动点击「刷新」，同步后重新验证排班。缓存损坏或练度字段缺失时也使用这一入口；缺少资源信息时更新资源包，资源更新不能代替练度同步。

尚无干员名单，或仅做过仓库扫描、缓存只有物品信息时，会跳过这些检查；跳过不表示已经满足运行条件。收益演算的缓存练度模式只读已有名单，不触发同步，名单问题同样只弹 warning；全员满练和手动练度模式沿用演算输入，不读取森空岛名单。
