# 宿舍干员绑组换班

本页行为仅在 Mower 设置中开启「测试宿舍逻辑」后生效；开关默认关闭。

在排班编辑器中，为宿舍常驻干员填写与工作干员相同的组。如果该宿舍干员的替换名单中包含一名同组主班，这个名字只作为“将固定位置转换为动态 `Free`”的开关，不再表示由该干员固定接住宿舍位置。

| 组状态 | 宿舍固定位置 |
| --- | --- |
| 上班 | 宿舍常驻干员在原位 |
| 下班 | 转为普通动态 `Free`，由统一休息排序选择任意合适干员 |
| 回班 | 宿舍常驻干员恢复原位；原入住者参与全宿舍动态床位重排 |

因此，替换名单中填写的同组干员不会被绑定到该位置，也不会被优先选择。该位置开放后与排班中直接填写的 `Free` 完全相同：可以安排主班、候补、普通替班或空闲干员；入住者休息满后可以被「宿舍不养闲人」替换。

同组工作成员仍需各自的普通岗位替班。整组下班时，全部工作成员与其他候选一起分配床位；转换出的临时床位只增加容量，不减少需要休息的人数。多个宿舍常驻成员满足条件时，会开放多张普通动态床位。

宿舍常驻成员不参与组内心情排序、床位需求、平均工作心情、用尽或回满计时。普通下班和用尽下班都支持；组内必须至少有一名可轮休的非宿舍干员。

## 回班时的床位关闭

固定宿舍成员回班会关闭对应的临时动态床位。关闭前，系统会收集该床位被挤出的干员和其他仍在宿舍恢复的动态床位入住者，并统一按“休息层级、当前心情、原床位次序”重排：

1. 层级较高者优先保留床位；
2. 同层级中心情更低者优先；
3. 能迁移到其他有效床位的继续休息；
4. 只有剩余容量确实不足时，排序最低者才离开宿舍；如果被淘汰者属于主班，其整组回班并重新计算床位。

这可避免简单恢复固定成员时，把被挤出者直接清退并损失本可继续获得的心情恢复。

## 主副表与宿舍房间顺序

测试逻辑下，动态床位集合取自最终合并后的当前排班。副表可以增加或减少 `Free` 床位；切表时保留仍需恢复的入住者，并按相同规则迁移到新排班的有效床位。新增床位立即参与分配，消失的床位恢复当前排班定义的固定成员。

主表和每张副表分别保存四个宿舍房间的优先顺序，默认是宿舍 1→2→3→4。同一房间内按物理床位顺序排列，不再保存每一张床的全局顺序。升级时，旧床位顺序按每个房间第一次出现的位置折叠为房间顺序；床位数量变化不会再触发“宿舍优先级和当前宿舍不匹配”。关闭测试逻辑后，继续使用 Mower 设置中的稳定版全局床位顺序。

## 单回与纠错

临时动态位置上的入住者按普通 `Free` 处理，不算固定宿管。单回确认会选择房间中第一个实际动态入住位置，并暂时撤下其他动态入住者以建立入驻顺序；固定宿舍成员本人在位时仍算宿管。

重启或部分执行失败后，纠错根据非宿舍成员的实际休息状态决定组状态。组在休息时保留临时床位上的现有休息者；空位保持 `Free`，不会把替换名单中的同组姓名固定塞入。组回班时恢复宿舍常驻成员。

「宿舍干员绑组换班」与「宿舍休息候补干员」是两项不同功能：前者控制固定宿舍位置何时转成动态床位，后者控制主班工作成员在缺床时能否随组撤下待命。候补规则详见 [宿舍休息排序与床位接管](dorm-resting-priority.md)。
