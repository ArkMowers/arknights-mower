# 宿舍休息候补干员

在排班设置的「宿舍休息候补干员」中显式填写需要允许无床待命的干员。

> 测试设置：仅对主班排班中已绑组的干员生效，休息优先级低于「宿舍低优先级干员」。整组下班时，有床则休息，无床则撤下待命，随组回班；待命期间不恢复心情。仅建议在同组存在心情消耗极高的干员时填写，其他情况请使用原有休息优先级。

主班指岗位上的主力干员，不是替班名单中的普通替班；是否绑组及所在岗位以当前生效的主表、副表为准。宿舍常驻、未绑组和普通替班干员填写此项不生效；用尽、回满、加工干员保留相应恢复要求，零心情工作干员绑组后仍随组上下班，但不入住宿舍，不参与候补分床。

休息优先级为：**高优 > 宿舍低优先级干员 > 宿舍休息候补干员**。零心情工作干员不申请床位，不属于休息队列。候补与原低优是独立配置；同一符合条件的干员同时填入两项时，以显式候补配置生效。

此功能补充 #942，不回退其重复分床、普通替班互踢保护及高优接管普通替班床位的修复。旧排班没有候补字段时默认空名单，不自动迁移原低优名单。原低优仍需床位、不能接管正在休息的普通替班，不会因升级而自动变成无床待命。

## 深海组示例

保留歌蕾蒂娅为高优，将其余六名工作成员填写到「宿舍休息候补干员」。达到下班条件且整组替班可用时：

| 剩余床位情况                             | 下班结果                                               |
| ---------------------------------------- | ------------------------------------------------------ |
| 一个空位，其余由普通替班占用             | 高优和显式候补可接管普通替班床位；原低优的保护规则不变 |
| 一个空位，其余由其他尚未休息完的主力占用 | 歌蕾蒂娅入宿舍，六名候补撤下待命，其他主力继续休息     |
| 存在部分可用床位                         | 必需休息成员先分床，再分给候补，其余候补待命           |
| 没有能分给必需休息成员的床位             | 不生成整组下班安排，不留下部分分配                     |

只有组内存在需要恢复心情、能实际入宿舍的高优主力时，候补才允许无床待命。没有这样的高优成员、全组均为低优或候补，或高优已满心情时，仍要求完整分床。整组替班不足时仍不下班。

待命期间不恢复心情。歌蕾蒂娅按现有休息计时规则回班时，待命成员随组返回原岗位；提前回班、急救规则仍适用，不保证一定等到满心情。其他干员回班腾出床位后，待命成员不会自动补入宿舍。

## 纠错与保存

纠错通过实际阵容识别候补待命：本人已离岗、原岗位有配置内的有效替班、同组高优主力正在轮休床位休息。满足时不因离岗或心情记录陈旧而叫回，也不将待命成员计入平均工作心情或在岗耗尽时间预测。重启后可从读取到的阵容恢复识别，不需要额外状态文件。

原岗位缺人或没有有效替班时仍执行现有纠错；能补替班则补替班，不能补时保留原有异常恢复流程，不屏蔽真实错位或已经失去组内休息依据的离岗。

配置字段为 `resting_standby`，默认空字符串，使用逗号分隔的干员名单。主表及副表均支持编辑、导入、保存和一键替换干员；副表名单按现有配置合并规则生效。未选择候补时不启用新的待命或床位接管行为。
