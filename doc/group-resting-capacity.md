# 宿舍休息候补干员

在排班设置的「宿舍休息候补干员」中显式填写需要允许无床待命的干员。

> 测试设置：对符合条件的主班生效，休息优先级低于「宿舍低优先级干员」。有床则休息；无床时进入待命，宿舍出现可用动态床位后立即补入休息；是否绑组不改变原有上班时间计算。待命期间不恢复心情。候补低于当前急救线后，本轮升级为低优主班并必须取得床位；即使休息中越过急救线也保持低优，直到实际回班。

主班指岗位上的主力干员，不是替班名单中的普通替班；是否绑组及所在岗位以当前生效的主表、副表为准。宿舍常驻和普通替班干员填写此项不生效；用尽、回满干员保留相应恢复要求，零心情工作干员绑组后仍随组上下班，但不入住宿舍，不参与候补分床。

休息优先级为：**高优 > 宿舍低优先级干员 > 宿舍休息候补干员**。零心情工作干员不申请床位，不属于休息队列。候补与原低优是独立配置；同一符合条件的干员同时填入两项时，以显式候补配置生效。

此功能补充 #942，保留整组完整分床及同级休息者互踢保护。旧排班没有候补字段时默认空名单，不自动迁移原低优名单。原低优仍需床位，不会自动变成无床待命；按统一接管规则，低优主班及以上可以接管严格低于自己层级的床位，详见 [宿舍休息排序与床位接管](dorm-resting-priority.md)。

## 深海组示例

保留歌蕾蒂娅为高优，将其余六名工作成员填写到「宿舍休息候补干员」。达到下班条件且整组替班可用时：

| 剩余床位情况                           | 下班结果                                               |
| -------------------------------------- | ------------------------------------------------------ |
| 一个空位，其余由普通替班占用           | 高优、低优主班和显式候补可接管普通替班床位             |
| 一个空位，其余由候补无法接管的主力占用 | 歌蕾蒂娅先使用空位，六名候补撤下待命，其他主力继续休息 |
| 存在部分可用床位                       | 必需休息成员先分床，再分给候补，其余候补待命           |
| 没有能分给必需休息成员的床位           | 不生成整组下班安排，不留下部分分配                     |

无床待命必须已有需要恢复心情、能实际入宿舍的高优主力提供待命依据。绑组候补使用组内高优主力；未绑组候补可使用当前任一高优恢复者。宿舍出现空位后，候补优先补入动态床位，不等待下一批宿舍人员回班。没有这样的高优恢复者、全组均为低优或候补，或高优已满心情时，仍要求取得床位。整组替班不足时仍不下班。

待命期间不恢复心情。歌蕾蒂娅按现有休息计时规则回班时，仍按原有组内回班规则处理；提前回班、急救规则仍适用，不保证一定等到满心情。其他干员回班腾出床位后，待命成员会按候补优先级自动补入宿舍。

## 纠错与保存

纠错通过实际阵容识别候补待命：本人已离岗、原岗位有配置内的有效替班，并且存在可提供待命依据的高优主力正在宿舍恢复；绑组候补要求该恢复者同组，未绑组候补可使用任一恢复者。满足时不因离岗或心情记录陈旧而叫回，也不将待命成员计入平均工作心情或在岗耗尽时间预测。宿舍出现可用动态床位时，候补补床任务独立生成，不改写原有回班任务的时间。重启后可从读取到的阵容恢复识别，不需要额外状态文件。

原岗位缺人或没有有效替班时仍执行现有纠错；能补替班则补替班，不能补时保留原有异常恢复流程，不屏蔽真实错位或已经失去组内休息依据的离岗。

配置字段为 `resting_standby`，默认空字符串，使用逗号分隔的干员名单。主表及副表均支持编辑、导入、保存和一键替换干员；副表名单按现有配置合并规则生效。未选择候补时不启用无床待命；统一排序及主班接管规则独立生效。
