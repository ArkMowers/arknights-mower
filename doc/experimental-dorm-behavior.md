# 新旧宿舍逻辑完整对照

本文描述 PR #1110 同步 alpha `78e5af35` 后的行为。“新模式”指开启「测试宿舍逻辑」，“旧模式”指关闭。开关默认关闭。表中的模式差异包括此前已有的实验功能，不全部是本 PR 新增。

## 两种模式都生效的修复

关闭测试开关会恢复旧宿舍算法，但不会撤销下列公共修复。

| 项目 | 修复前的问题 | 当前行为 |
| --- | --- | --- |
| 下班候选顺序 | 后续版本混入宿舍层级，可能让心情更充足的组先占替班 | 恢复原公式：按「当前心情－个人心情下限」从小到大尝试。优先名单只影响宿舍分床，不决定先下班 |
| 普通工作替班 | 只按配置顺序尝试，可能先用已低于急救线的替班 | 只读缓存，把已知低于个人急救线者后移；其余保留填写顺序。全部偏低时仍可使用，未知心情不额外读屏 |
| 用尽组争用替班 | 替班被其他休息组占用时，用尽组可能无法休息 | 先给占用方换其他替班；没有可用方案再叫回占用方整组。替班、床位均验证成功才执行；仍不足时不先做半套安排 |
| 用尽组缺床 | 腾床和解决替班冲突可能脱节 | 替班落实后按原心情降序尝试整组回班腾床。保留用尽回满、专精及延期切产物保护；不能无条件抢走所有资源 |
| 令夕上限 | 可能等整组回班而继续恢复，或达到上限后再次入宿 | 感知模式令上限 12；烟火模式夕上限 12。达到或超过上限即安排单独离宿，等待同组回班；不受“不养闲人”、整组回满和普通任务合并影响。关闭模式或改为均衡时清除旧限制 |
| 半组状态与重启纠错 | 逐人保护可能留下半组上班、半组休息；默认心情 24 被误认为已回满 | 按整组恢复一致状态；完整休息组优先补替班，任一岗位无替班则整组回班。没有采样时间的默认 24 不算实测满心情；有效待命、实测满心情离宿者及零心情工作例外保留 |
| 空床占位符 | 关闭“不养闲人”后，读取心情可能因 `Free` 报错 | 跳过 `Free`、`Current`、空名称及无效名称；查不到干员时返回无宿舍。来自主分支 #1126 |
| 切产物确认 | 补队列后直接回设施列表时，可能误报等待确认框超时 | 接受“出现确认框”或“已回设施列表”两种结果；都没出现才报错。来自主分支 #1127 |

例如：心情 8、下限 12 的余量为 −4，先于心情 1、下限 0 的干员尝试下班。排在前面不等于必定下班，仍须满足心情阈值、用尽条件、替班和必需床位要求；失败继续尝试后续候选。

个人急救线沿用现有设置：个人下限＋（个人上限－个人下限）×排班心情阈值×全局急救阈值。

## 自定义心情上下限（仅测试宿舍逻辑）

开启测试宿舍逻辑后，排班页支持全体默认和指定干员上下限，仅对当前生效排班的主班、替班生效；未排班者不受影响。优先级为指定干员设置 → 令夕模式 → 全体设置 → 其他自动规则。未单独设置时，令夕模式优先于全体设置，自动设置本人及同组上下限。

- 范围为 `0 ≤ 下限 < 上限 ≤ 24`，支持小数；主副表均可保存。副表未设置则继承，生效副表的同项设置以后者为准，退出后恢复；个人设置始终优先于全体设置。
- 下班阈值＝下限＋（上限－下限）×排班心情阈值；急救线再对该区间比例乘全局急救阈值。下班先后仍按当前心情减个人下限。
- 回满、耗尽预测及恢复倒计时复用原上下限逻辑；有手动设置者到上限即离宿、不再入宿，不受“不养闲人”开关影响。固定宿管保留岗位。
- 切表或修改上限时换算已有恢复倒计时，旧上限释放任务失效；未知恢复数据重新读取。整组都到上限离宿后仍按原整组流程回班。

关闭开关后保留自定义配置，但不参与调度，恢复原令夕等自动规则。

详见 [心情上下限配置](mood-limits.md)。

## 开关开启与关闭的区别

| 项目 | 旧模式：关闭 | 新模式：开启 |
| --- | --- | --- |
| 宿舍优先名单 | 名单内按填写顺序优先分床，其后沿用旧高低优分类 | 显式名单 → 普通主班 → 低优主班 → 候补 → 普通替班 → 其他空闲；同级按当前绝对心情从低到高，未知心情最后，同分保留原序 |
| 先给谁分床 | 旧组内高低优选床顺序 | 先保障必须有床者，再给可待命候补分床；先用空床，接管时先选可接管者中层级最低、同级心情最高者 |
| 恢复中的占位者 | 按旧高低优与加工身份判断；满足待命条件且未低于急救线的候补可给正常高优主班让床 | 显式高优、普通主班、低优主班可接管普通替班和空闲者；候补分床可接管普通替班；候补或普通替班接管空闲者时，有有效缓存须不高于 22，无有效缓存默认允许。已入住的候补及以上不因别人优先级高而被踢出，同级恢复者不互踢 |
| 普通床位重排 | 按旧全局顺序重新映射床位 | 日常保留已入住者的位置；心情变化或仅调整宿舍顺序，不反复搬床 |
| 新入住者竞争单回 | 沿用旧全局重排 | 先取得床位，再比较单回目标。新入住者层级更高，或同级心情更低，才交换；旧目标继续竞争后续宿舍单回，最后落到腾出的普通床位。所有已获床者继续休息 |
| 单回目标离开 | 游戏自然接续 | 同样由游戏在本宿舍自然接续，不专门清房重排；游戏不读取 Mower 的优先名单 |
| 宿舍顺序与副表 | 使用设置中的全局床位顺序 | 主表、副表可分别设置房间顺序，同房按物理床位排序；副表留空继承，显式设置才覆盖。旧顺序迁移到缺少独立设置的排班，原全局值保留 |
| 宿舍常驻成员随组休息 | 旧固定宿舍替班处理 | 替班中显式填写 `Free` 才把固定位临时开放为动态床；具体姓名仍是固定替班，不再把同组主班当特殊固定恢复床。具体替班按有效心情选择 |
| 临时床的使用 | 无新的显式临时 `Free` 机制 | 临时床与普通 `Free` 相同，可分床、补床；宿舍成员不计入组内工作心情、床位需求、用尽和回满计时，工作成员仍各自需要替班 |
| 临时床关闭或副表缩容 | 沿用旧床位处理 | 尽量保留有效原床位，只迁移失去床位等必要人员；容量不足按层级、心情决定谁留下，已有单回目标的缩容豁免保留；淘汰主班时整组回班 |
| 候补范围 | 仅符合条件的绑组主班 | 扩展到未绑组主班。绑组须有同组正常优先级主班休息，未绑组须有其他正常优先级主班休息，才能无床待命 |
| 候补待命与急救 | 原随组待命规则 | 有床休息，无床待命；待命不恢复心情。低于个人急救线后，本轮升为低优主班，必须取得床位；实际回岗才解除 |
| 候补补床与回班 | 已随组待命的候补可由 Free 选人及不养闲人补床，仍随组回班 | 有可用床位就补，不因已排未来回班而跳过。生成补床计划不改变回班时间，执行后按实读恢复时间重算；绑组随组回班，未绑组按现有下一批回班安排，不保证回满 |
| 不养闲人 | 旧算法增加候补补床及回满候补替换；空姓名释放任务按实际槽位补齐身份，再做位置校验 | 按统一层级、心情替换已恢复完成者或填空床，支持待命候补；没有合适候选不单为腾床搬人。根据实际占位者判断，避免字典顺序影响结果，避免重复预订 |
| 黑名单、零心情工作 | 黑名单用于空闲补床排除，零心情工作沿用原规则 | 黑名单和零心情工作不参与动态分床、补床；固定宿舍岗位不受黑名单影响。零心情工作者仍随组上下班，不申请床位；普通干员心情为 0 仍可休息 |
| 加工干员 | 保留自动加工中的“低优先休息”设置 | 加工身份本身不降级，按当前排班中的主班／候补／替班身份排序，未排班者属于普通空闲；不强行打断加工或专精 |
| 副表触发 | 按配置的进入、退出阶段检查 | 每轮在缓存内反复推演到条件稳定，不再逐阶段切入切出；循环或计算错误则保留原状态，界面隐藏阶段选项 |
| 副表生成安排 | 沿用旧切表纠偏 | 合并自定义任务、岗位差异和必要宿舍迁移；退出时恢复其改过的位置，无关岗位和宿舍不跟着重排 |
| 下班与入宿任务 | 旧任务流程 | 工作替换与本轮宿舍安排合并进下班任务，减少任务之间“已离岗、未入宿”的状态；实际点击仍逐房执行 |
| 回班与恢复计时 | 保留原回班公式和旧调度流程 | 先在副本中推演已确定的迁移，再排回班；计时跟入住者移动，相关回班在迁移后，无关回班不延迟。执行后用实测重建，计划阶段不提前改真实床位 |
| 同刻任务与执行失败 | 原流程 | 回班和释放保留各自任务类型；跳过失效床位，避免时间溢出。进驻确认已提交但读取失败时，重新核对阵容并补读倒计时；部分属于公共路径修复 |
| 跑单资格 | 旧资格判断及宿舍满员前置条件 | 仅实际／目标产物允许且配置跑单替班的贸易站参与；卖玉房不跑单，及时清除失效任务；动态空床不再阻挡读跑单时间 |
| 跑单延期 | 旧保护延期流程 | 延期后可补一次空余宿舍；纯宿舍任务不整批跟随跑单延期，重复宿舍安排合并为最终入住并保留必要计时 |
| 副表切换后继续规划 | 原唤醒流程 | 重建回班队列后仍安排普通规划唤醒，避免漏掉跑单；原 15 分钟删除／强制刷新规则不变 |
| 换班涉及切产物 | 旧切产物流程 | 先推演目标产物，切换确认成功后再换相关人员；未完成时保留原班，只延期相关安排，其他独立任务可继续 |
| 制造进度与无人机 | 旧葛朗台及缓冲流程 | 结合当前一份进度、生产效率、损耗容限和单次无人机上限计算。可设置切出源石碎片不用无人机；不足时默认预计重试，只有显式允许才取消进度直接切换。上限 0 表示不限制 |
| 等待及资源预留 | 旧等待方式 | 依预计完成时间重试并复核，在取消旧计划确认页等待完成时点和缓冲；延期切产物保留相关人员、床位和任务，避免其他换班抢走 |
| 界面描述 | 显示旧规则 | 随开关显示对应短说明；实验专用切产物选项关闭时不可用；宿舍替班可选 `Free`，编辑锁继续生效 |

## 必须一起理解的边界

- 宿舍优先级只管分床、单回和缩容取舍，不让某组提前下班。普通补床在工作组换班规划之后处理。
- 新入住者先要有床，不能仅凭高优把恢复中的主班或候补踢出去。只比较新入住者引起的单回变化；已有入住者普通迁移不算新入住。已被任务预留的房间不参加此次单回交换。
- 例：四个单回已有 1 名普通主班和 3 名低优。高优新入住者可取得最前单回；普通主班新入住者可超过低优，同级只在心情更低时超过；低优新入住者只能超过心情更高的低优；候补、替班、空闲者不能超过这四人。前提均是已取得床位。
- 候补必须显式填写；旧低优名单不会自动转为候补。固定宿舍成员、普通替班、用尽、回满及零心情工作干员不适用无床待命。没有有效休息主力提供回班依据时，候补仍须有床。
- 整组替班齐备、下班阈值、用尽、回满、原急救及非用尽提前回班公式保留；菲亚梅塔的目标顺序和充能逻辑不改，充能名单不算普通替班名单。训练室保护保留。
- **尚未修复的独立边界：普通跑单延期任务仍未统一使用延期切产物的人员／床位预留机制。此前日志中的旧宿舍安排覆盖用尽回满床位风险，不能算作此次冲突处理已修复；引入版本尚未判定。**
- 令夕“到上限离宿”由定时任务和实读心情触发，并不保证网络或识别故障时能零延迟点击。
