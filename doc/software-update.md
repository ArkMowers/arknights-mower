# 软件更新与实例恢复

入口：**Mower 设置 → 页面底部的软件更新**。与资源更新使用相同的卡片表单，直接查看版本、选择渠道、检查更新或拖入安装包；宽屏左右并排，窄屏上下排列。支持 Windows、macOS 和 Linux。

## 更新渠道

| 渠道 | 更新目标 | 适用部署 |
| --- | --- | --- |
| 正式版 | 主仓库的正式 GitHub Release | 源码、Release 独立包 |
| 公测版 | 主仓库的预发布 Release，例如 `v4.1.6-alpha.3` | 源码、Release 独立包 |
| 开发版（仅源码部署） | `alpha` 分支的最新提交 | 源码 |

正式版适合希望减少变动的日常使用者。公测版提前提供修复和新功能，可能不稳定。开发版比公测版更新频繁，需要自行排查源码运行问题。GitHub 的 `-alpha.N` 标签在界面中归入“公测版”；“开发版”指分支提交，并非同一个更新目标。

版本按语义版本号比较，正式版检查不会误选预发布版本。Release 更新不允许直接降级，以免旧程序读取新配置。开发版按提交判断是否需要更新。

## 源码部署

使用安装目录内 `.venv` 或 `venv` 的 Python 启动 `manager.py` 或 `webview_ui.py`。需要 Git、Node.js/npm，并且 `origin` 指向 `ArkMowers/arknights-mower`。仅当目标提交的 `.gitattributes` 使用 LFS 时才要求 Git LFS；普通 Git 仓库不依赖它。macOS 桌面启动会补充 Homebrew/MacPorts 的常见工具目录，更新命令和恢复实例沿用检测到的 PATH。支持普通 Git 检出和 Git worktree。下文以 `.venv` 为例；原先使用 `venv` 的安装仍使用原目录名。

正式版、公测版从对应 Release 的 tag 获取提交；开发版从 `alpha` 获取提交。更新程序会核对检查时的提交，远端变化时要求重新检查。

源码更新流程：

1. 检查工作区无未提交修改或未跟踪文件，获取目标提交，按目标需要获取 LFS 内容。
2. 保存同一安装目录下正在运行的实例、端口和任务状态，请求各实例正常退出。
3. 保留原 `.venv`、`ui/node_modules` 和 `ui/dist`，将源码切换到目标提交。
4. 创建新的 `.venv`，执行 `python -m pip install -r requirements.in`。
5. 有锁文件时执行 `npm ci`，否则 `npm install`，再执行 `npm run build`。
6. 恢复原实例和端口，等待网页服务就绪，再恢复更新前正在运行的任务。

为保留本地分支指针，目标提交使用 detached HEAD 检出，不执行 `switch -f`、`reset --hard` 或 `git clean`。这不会删除原有分支或未推送提交。后续更新仍按所选渠道进行。

工作区检查遵循 `.gitignore`，忽略的运行数据和构建目录不会阻止更新。前端生成的 `auto-imports.d.ts`、`components.d.ts` 及 `.playwright-cli/` 不纳入版本控制，生产构建不重写组件声明。`package-lock.json` 继续跟踪以固定依赖，源码部署建议使用 `npm ci`；已有本地改动会在页面列出，需先备份或提交，再清理并点击“检查更新”刷新检测。不会把已跟踪源码的本地修改当作缓存直接覆盖。

代理统一在 **Mower 设置 → 网络与下载代理** 中配置，详见下节；软件更新使用这套共享设置，不需要给三个实例分别填写。

源码与 Release 独立包均提供“更新后后台静默重启”选项，在线更新与上传安装共用该选项。开启后不创建启动画面和网页窗口。macOS 遵循“隐藏菜单栏图标”设置，隐藏时不创建托盘进程；后台启动也不会为不存在的启动画面或托盘创建多进程队列。其他平台在后台模式保留托盘入口。窗口子进程关闭后会被回收。关闭静默选项则正常打开窗口。

macOS 源码部署的主进程、托盘及启动画面辅助进程使用 accessory/UIElement 类型，避免出现多余的 Python Dock 图标；此行为不受静默重启开关控制。正常启动时仍创建独立的网页窗口进程，该窗口进程不调用隐藏 Dock 的逻辑。Release 独立包仅在后台模式下隐藏主进程和托盘进程的 Dock 图标。

macOS 设置页用“隐藏菜单栏图标”控制原有的 `webview.tray` 开关（反向显示），无需额外配置。重启后不创建托盘进程；关闭网页窗口后当前实例继续运行，可以用浏览器访问原来的地址。此选项按服务端系统显示，从 Windows 浏览器访问 macOS Mower 时也可设置。

## 自动检查与自动更新

软件更新卡片提供“自动检查更新”和“自动更新”，默认均关闭。打开 Mower 时检查所选渠道；开启自动更新会同时开启检查，发现新版本后按所选静默重启方式安装并恢复运行实例。关闭检查也会关闭自动更新，与资源更新的开关联动一致。

这些设置按安装目录共享。多个实例同时启动时在一分钟内只发起一次自动检查；更新或进程操作进行期间不发起自动更新。软件更新、失败恢复和网页按钮触发的重启不再次自动更新，避免失败后循环重启。自动检查结果和失败原因会显示在软件更新卡片，源码改动、依赖及目标兼容性检查与手动安装相同。

## 当前实例的重启与结束

设置页最底部提供独立的“进程操作”卡片。两个按钮只作用于当前实例，其他实例和多开管理器保持运行，也不依赖 Git、Node.js 或软件更新是否可用。

“重启 Mower 进程”先保存页面配置并请求当前任务正常停止，再使用原 Python/独立包入口、命令行参数、工作目录、实例名称、数据目录和端口恢复当前实例，并恢复原运行状态。通过 manager 启动的实例保留 manager 传入的参数，不额外启动其他实例。“结束 Mower 进程”正常退出当前实例，网页连接随后断开。

退出最多等待 90 秒，不按进程名强制关闭 Python 或其他实例。重启时页面会等待原端口重新连接。操作状态与日志保存在 `updates/<安装目录标识>/control/<操作编号>/`，与软件更新日志分开。

## 网络与下载代理

位于设置页下方、软件更新与资源更新卡片上方。

- **全局网络代理**：用于全局网络连接，例如 `http://127.0.0.1:7897`。填写后覆盖大小写的 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`，并覆盖旧的外部域名绕过规则。留空沿用进程最初的启动环境；回环地址保持直连。此设置仅作用于 Mower 进程和它启动的子进程，不修改操作系统代理设置。
- **GitHub 下载代理站点**：例如 `https://ghfast.top/`，可自行替换为支持“代理站点/原始下载 URL”格式的站点，也可保留自定义路径前缀。用于 Mower 和 MAA 的 GitHub 安装包、资源包、热更包及原始文件（包括资源版本清单和 MAA Python 的按需下载）；清空后直接访问原始下载 URL。MAA 的官方下载 API 和 Mirror酱地址保留原始地址，通过全局网络代理连接。文件代理覆盖 `github.com`、`raw.githubusercontent.com`、`codeload.github.com` 和 `gist.githubusercontent.com`。GitHub API、源码 Git/Git LFS 不走文件加速站点，使用上面的全局网络代理。

两项可同时启用：先把 GitHub 文件 URL 拼接到下载代理站点，再通过全局网络代理连接该站点。下载站点不会代替原有的安装检查和在线 Release SHA-256 校验；手动上传 Release 仍然离线安装，无需校验文件。

输入停顿或离开输入框时自动保存，两项代理用于后续连接。其他实例自动同步代理环境变量；各网络客户端沿用自身读取环境变量的机制，不修改或替换 AI 客户端及其传输层。设置保存在共享的 `@app/config/network.json`，不随实例的 `conf.yml` 自动保存而被覆盖。已启动的独立软件更新任务保留提交时的代理快照；新的更新任务使用最新设置。

“测试连接”只检查 GitHub 资源包下载接口是否可达：按保存的设置拼接下载代理 URL，经全局网络代理发送 HTTP HEAD 请求并跟随重定向，显示连接结果和耗时。不下载包正文，也不解析 JSON；测试成功仅表示该下载地址的 HTTP 请求成功，不代表文件内容、下载速度或 HTTP Range 支持已经验证。

设置页按钮会先等待 `/network/settings` 保存当前输入成功，再调用 `/network/test`；保存失败时不发起测试。`/network/test` 仅测试已保存配置，不接收或保存代理输入。其他调用方也应遵循先保存、再测试的顺序。软件更新检查同样使用这套已保存配置。

## Release 独立包

在线更新按程序正在运行的系统和架构选择完整安装包，核对 GitHub 提供的 SHA-256 后安装。Release 独立包在线更新和手动上传安装均可选择后台静默重启；关闭选项时正常打开窗口。

| 平台 | 安装包 |
| --- | --- |
| Windows x64 | `arknights-mower_<版本>_windows_x64.zip` |
| Linux x64 / arm64 | `arknights-mower_<版本>_linux_<架构>.tar.gz` |
| macOS Intel / Apple Silicon | `arknights-mower_<版本>_macos_<架构>.dmg` |

macOS 必须先把 `mower.app` 移出 DMG，在可写位置运行。安装程序只读挂载 DMG、检查包内容并复制 `.app`，不修改 Gatekeeper 设置。旧式 macOS ZIP 和早期 RAR 包请自行安装。

Windows/Linux 只替换程序拥有的可执行文件和 `_internal`，保留原地的实例配置、数据库、MAA 和其他用户目录。macOS 替换 `.app`，用户数据仍在 Application Support 或用户指定的数据目录。

共享资源位于持久的 `@app/resources`，不会覆盖 internal。程序更新后按版本与声明的兼容性整包选择内置或外部资源，详见[共享资源存储与实例加载](resource-storage.md)。

### macOS 签名与系统信任

当前发布流水线只有 PyInstaller ad-hoc 签名，没有 Developer ID 签名和 Apple notarization。DMG 的镜像校验、`.app` 签名完整性、Gatekeeper 的开发者信任是不同检查：镜像或下载摘要正确，不代表系统一定允许程序启动。

更新器只读挂载 DMG，保留符号链接、权限等复制完整 `.app`，在最终待安装副本上执行 `codesign --verify --deep --strict`。检查失败时不会停止旧实例或替换程序。资源更新写在 `.app` 外，避免修改受签名保护的内容。

即使签名完整性通过，浏览器下载文件的隔离属性、系统信任策略或缺少公证仍可能导致 Gatekeeper 拦截。程序下载与浏览器下载可能带有不同的隔离属性，不能据此保证自动更新永远不被拦截。后台静默重启选项也不能免除系统允许操作。遇到拦截，需要确认包来源后通过系统“隐私与安全性”按提示处理；更新器不删除隔离属性、不禁用 Gatekeeper，也不会自行重新签名。

正式解决首次安装和更新的信任体验，需要发布方使用 Developer ID 签名、启用 Hardened Runtime、完成公证并附加公证票据。现有本地测试验证了 ad-hoc 签名复制后仍有效、修改包内资源后检查失败；未验证 Developer ID、公证或所有 macOS 版本上的 Gatekeeper 行为。

## 手动上传安装

在软件更新卡片的“手动应用”中选择官方安装包，保留原始文件名，点击“安装并重启”即可离线安装。手动上传无需校验文件，不进行 SHA-256 校验，也不联网获取校验值。平台不匹配、版本不高于当前版本或包结构不完整时不会停止实例或替换程序。

此入口适用于 Release 独立包部署。源码部署应选择在线更新中的正式版、公测版或开发版，不允许把二进制包覆盖进 Git 工作区；GitHub 的“Source code”压缩包也不是独立程序安装包。原来的热更包/资源包上传入口继续负责相应的数据包。

也可将更新包拖入主界面的任意页面：资源包、热更包 ZIP 会打开安装确认框；软件安装包会转到软件更新卡片并自动选中文件，点击“安装并重启”后才提交安装。一次仅接受一个文件。

软件 ZIP 请保留官方 `arknights-mower_…` 文件名，只有此前缀的 ZIP 进入软件安装流程；其他 ZIP 交由热更/资源包按内容识别，旧版 `mower.zip` 不支持自动软件安装。DMG 和 tar.gz 按软件包处理。

全页拖放只处理未被现有组件接管的更新包，不拦截内部排序、图片、JSON、文字拖放，也不接管现有上传区、可编辑区域和可拖拽项目。资源更新保留原有局部拖放区；Release 部署的软件更新卡片也提供“点击或拖入 Release 安装包”，可用于不支持全页文件拖放的桌面 WebView。

## 多实例、失败恢复与首次启用

一次更新覆盖同一安装目录，多个实例同时点击也只会接受一个任务。更新只恢复更新前已启动的实例；不会额外启动 `instances.json` 中原本未开启的实例。静默重启时不重新弹出多开管理器，三个实例由更新程序直接恢复；关闭静默选项则恢复原先打开的管理器。

实例有 90 秒时间正常退出；如果任务或 MAA 更新未能及时结束，则取消安装。不会按进程名关闭其他 Python、ADB 或模拟器。安装或启动失败时，更新进程尝试恢复原代码、虚拟环境和前端，并重新启动原实例。若新进程无法退出，则保留备份并报告需要人工恢复，不在仍被使用的运行环境上强行回滚。

首次启用需要先安装包含本功能的代码，并重新启动全部实例，使其注册到同一安装目录。更新目标也须包含实例恢复功能；目前的 `v4.1.6-alpha.3` 发布早于本功能。缺少恢复模块的源码或独立包会在关闭实例之前被拒绝。需要等待此功能合入后续 Release，才能完成正式发布版本之间的自动更新。

直接运行 Flask、Docker 或由其他服务管理器托管的部署继续使用原部署工具更新，避免与外部进程管理策略冲突。

更新状态、日志和源码环境备份保存在安装目录之外：

- macOS：`~/Library/Caches/arknights-mower/updates/<安装目录标识>/`
- Windows：`%LOCALAPPDATA%/arknights-mower/updates/<安装目录标识>/`
- Linux：`${XDG_CACHE_HOME:-~/.cache}/arknights-mower/updates/<安装目录标识>/`

每次任务位于 `jobs/<任务编号>/`，含 `job.json`、`recovery.json`、`update.log` 和 `restart.log`；源码备份也在该目录。独立包备份位于安装目录旁的 `.backup-<任务编号>` 目录。更新卡片显示日志路径。确认新版本工作正常后可以自行清理旧任务、运行环境副本和备份，以释放磁盘空间。
