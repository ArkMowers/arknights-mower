# 每个计划的专精协助方案

选择自动协助且有 BOX 时，按已同步的森空岛干员练度和当前资源，为尚未完成的专精阶段生成协助方案，并与计划原子保存。计划列表中的「协助方案」可以查看、修改各级初始协助者和后段接班者。开始执行前可以修改全部阶段；训练中允许修改后续阶段，已经开始的阶段锁定。保存时对计划状态、原方案和执行快照做并发校验。

未同步 BOX（或文件损坏、无干员数据）时，新增计划自动使用原职业路线并提示确认协助者配置，不要求使用森空岛。手动添加任务也可显式选择「使用职业路线」，跳过自动协助规划。已有 BOX 时，未拥有/未精二、资源规则缺失和无可用协助者等校验错误仍会阻止自动建计划，不静默降级。职业路线计划没有逐计划协助方案，直接在通用专精路线预览中设置教官。

## 排班约束

- 主排班与全部备用排班中的主力、replacement 都计入检查，不判断备用排班是否生效。
- 出现在任何非训练室设施（包括宿舍、活动室）的干员均从协助者名单中排除；训练室栏不排除。Free、Current 和空值不代表干员。
- 被训练干员出现在非训练室排班时，添加计划仅弹出警告，仍允许添加、编辑协助方案和执行训练。原有「空闲／非空闲」筛选保留，所有设施（含训练室）的主/备用排班主力与替换占用仍计为非空闲，不再作为被训练干员的准入限制。
- 阿斯卡纶、烛煌或斩业星熊出现在上述任意排班的 **central 主力或 replacement** 中，就自动启用中枢 +5%。多名同时出现仍为 +5%；出现在其他房间不会触发。页面开关只展示推导结果。
- 自选协助者保存时检查拥有情况、不能自己训练自己和排班冲突，允许选择无专精加速技能的干员。仅实际改过的阶段标记为自选。

## 计算来源与范围

根据游戏 building_data / character_table 独立解释规则，没有移植 riic.autos 的程序代码。

- [游戏基建技能数据](https://github.com/ArknightsAssets/ArknightsGamedata/blob/master/cn/gamedata/excel/building_data.json)
- [游戏干员数据](https://github.com/ArknightsAssets/ArknightsGamedata/blob/master/cn/gamedata/excel/character_table.json)
- [PRTS 训练室](https://prts.wiki/w/训练室) 与 [控制中枢](https://prts.wiki/w/控制中枢)

资源生成时由 `mastery_rules.compile_training_data` 编译职业、分支、专精阶段条件、技能升级替代及减半技能，写入 `skill_data.json.training`（version=1）。运行时按精英阶段和等级选各升级链的最高已解锁版本，同组升级不叠加。

基础训练量依次为 8、16、24 小时。有协助者时速率为 `1 + 0.05 + 技能加速/100 + 中枢加速/100`；空协助位没有 0.05。

自动选人排除依赖资源转换、基建内阵营人数的动态加速技能，包括余、乌尔比安，以及可能瞬间完成训练的武道技能。手动选择此类干员时允许保存，但动态收益不计入时间预测；所有换人仍以实际倒计时检查，无法保证下一阶段获得减半。

最多三级的动态规划比较连续训练总耗时，耗时相同时优先减少换人。普通教官保留各级最快的代表，另保留减半教官；只在创建计划时求解。最终目标级不为下一级安排减半接班者。首级不凭空继承减半；下一阶段只有在实际协助者、训练位和上一阶段工作记录吻合，且实际训练已超过五小时，才估算继承减半。等待收取的时间不计入五小时。

## 通用专精路线预览

「通用专精路线预览」中，默认路线只使用已同步拥有、已解锁训练室技能且没有非训练室排班冲突的干员；不以是否精二作为统一筛选条件，按各技能实际解锁条件判断。主／备用排班、中枢和动态技能排除规则与上文一致。生成连续三级路线时考虑减半，没有可用减半教官就不设置减半换人。缺少练度时提示同步，不回填全游戏固定路线。

此页面仅按职业预览通用路线，不计分支专属加成。添加具体干员的训练计划时，会按其职业和分支独立计算，符合条件的分支加成协助者也参与计算，因此实际路线可能与预览不同。路线行保留编辑控件，不再显示右侧的增删按钮。

旁边的「各职业最优协助者」沿用原 `DEFAULT_ROUTES` 的专一、专二、专三教官和速度，作为全游戏培养参考，拥有情况与排班不改变推荐名单。未拥有标记「未拥有」，已拥有但尚未解锁表中加速技能的标记「未解锁」，缺练度或资源资料时显示「练度未知」。

职业通用默认路线及推荐表都不假设目标分支，不计分支专属额外加速，保留基础职业加速；具体干员的逐计划方案仍可按该干员真实分支计算。

手动下拉保留全部干员，职业路线保存不增加拥有或训练技能解锁限制。已保存的手动路线优先显示；「计算最优」先同步森空岛干员数据，成功后重新请求个人推荐，一次替换全部八个职业的草稿。同步失败时保留现有草稿并提示原因，不使用旧 BOX 继续计算；计算期间防止重复提交或提前保存。「保存并关闭」会保存未编辑过的个人默认路线，直接关闭不写入配置。推荐表不会覆盖个人路线。

「计算最优」旁的问号在悬停时提示「先同步干员数据，再按照最新 BOX 计算最优默认专精路线，应用于全部职业」。各设置页共用的帮助组件直接监听原生指针／鼠标进入与离开事件，也支持键盘聚焦；提示挂在页面顶层，避免被滚动容器裁剪。职业切换栏为选中背景提供定位参照，弹窗内容滚动时背景与职业文字同步移动。

## 执行与换人

1. 技能选择页（219）读出档位后返回，等待场景确认为训练室主页面（217），再复用原有 `_read_slots_checked` 读取槽位；过渡场景先等待。核对阶段、槽位、排班约束和上一阶段减半记录，保存本级执行方案。此时不改协助位。
2. 若上一阶段已获得下次训练减半效果，保留原协助者至本级训练开始、减半生效，再安排本级初始协助者。安排后确认实际槽位，重读倒计时，以截图安排后续任务。
3. 后段减半换人按实际倒计时和当前速度计算，至少留 5 小时加缓冲（缓冲最少 1 分钟）。首选因排班等原因不可用时，按可用减半教官重新计算接班时机；换人后再次核对槽位和实际倒计时。
4. 剩余时间不满足减半条件时保留原人；槽位确认或换人失败时停止本级自动换人并告警。通知按计划和等级去重，删除计划时清理对应记录。
5. 恢复逻辑读取本计划的执行快照，不再将替补减半教官误判成旧职业路线中的陌生人。执行快照与可编辑的计划方案分别保存。

本版本不包含新增的专精心情识别、心情消耗计算、开训前心情检查或按心情替补与告警；协助者能否持续工作需用户自行保证。这部分后续单独实现。

`enable_mastery` 与现有训练室保护规则继续生效。`assistant_follows_schedule=True` 时不执行自动换协助者。旧计划与职业路线计划仍用原职业路线。自动协助模式有 BOX 但资源包缺少 training v1 时明确提示更新资源，不静默使用不完整规则；显式职业路线模式不要求训练规则。

## 模块与持久化

`mastery_support` 保留规划/预览入口，数据与候选过滤在 `mastery_support_data`，路线求解在 `mastery_optimizer`，方案编辑在 `mastery_support_edits`；共享输入、阶段参数和 JSON 编解码集中在 `mastery_support_types`。执行分为 `mastery_support_runtime`（预检与恢复）、`mastery_support_state`（快照与任务）及 `mastery_support_swap`（校验与换人）。

`GET/PATCH /mastery-plan/supports` 读取/修改逐计划方案，DB 的 `support_plan` 与 `support_runtime` 分离，使用原状态及快照比较防止编辑覆盖正在执行的阶段。`support_swap` 是第九类去重通知，key 为 `{plan_id}:{level}`；读取不到有效等级时仅为告警回退到执行快照等级，两者均无效则使用 `unknown` 并显示「专精阶段未知」，不改变训练室动作判断。删除计划时清理该计划的全部协助通知，包括旧版 `:None` 记录。两种建计划载荷均校验技能序号为整数 0/1/2。

## 性能与验证边界

资源规则由现有资源缓存读取；练度文件按路径、修改时间和大小缓存，更新后自动失效。页面排班范围使用 computed；候选名单只在打开协助方案时读取。不增加选人页扫描，不在调度主循环重新求解。

单元测试覆盖资源规则、路线求解、排班约束、方案保存、阶段校验和换人任务。开训流程测试调用真实预检与槽位读取函数，设备边界模拟技能页返回、UNKNOWN/CONNECTING 过渡及读取失败。完整的实机训练流程及不同客户端画质仍需后续验证。

资源生成器和该功能代码发布后，MowerResource 需要重新出包。此功能不向计算网站发起运行时请求。

验证命令：

```sh

.venv/bin/python -m pytest -q  # 自动发现应用与 scripts 测试，兼容 unittest/pytest
cd ui && npm test && npm run build
```
