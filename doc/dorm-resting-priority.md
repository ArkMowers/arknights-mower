# 宿舍休息排序与床位接管

本页描述 Mower 设置中开启「测试宿舍逻辑」后的行为。该开关位于「宿舍不养闲人」下方并默认关闭；关闭时继续使用旧版全局床位排序、加工干员最低优先设置和原版不养闲人。

上下班与宿舍分床是两件事。下班候选沿用原有 `当前心情 - 心情下限` 升序，开启或关闭测试逻辑均不使用下面的宿舍层级改变候选先后。轮到某位主班后仍检查工作心情阈值、用尽规则、整组替班和可用床位；普通空闲干员的补床在工作组换班规划之后处理。回班仍由恢复时间、整组、回满及原有急救规则计算。

宿舍入住候选和床位分配使用以下层级，由高到低排列：

1. 「干员休息优先级」名单中显式指定的高优干员。
2. 普通主班。
3. 「宿舍低优先级干员」。
4. 「宿舍休息候补干员」。
5. 普通替班，包括训练室协助位。
6. 未写入当前生效排班的其他空闲干员，包括加工干员。

普通替班以当前生效主表、副表的替班名单识别，菲亚梅塔的充能名单不作为普通替班名单。零心情工作配置和宿舍黑名单属于候选排除条件，不是最低层级；实际心情为 0 的普通干员仍可休息。宿舍常驻成员本人不参与动态床位竞争；绑组宿舍位置在组下班后会转换为普通动态 `Free`，其实际入住者按本页规则参与竞争。

宿舍分配时，每一级按有效的**当前绝对心情**从小到大排列，未知心情排在同级最后，相同心情保留原顺序。显式高优名单内部也比较心情，不再用填写顺序区分先后。这不是工作组下班顺序，不能让仍有心情的优先名单成员先占用红脸组需要的替班。工作心情阈值、用尽下班、心情下限和菲亚梅塔充能的判定仍由各自规则处理，排序不会强行中断加工或专精。

## 接管规则

| 申请者                       | 可接管的正在休息者     | 申请者心情门槛              |
| ---------------------------- | ---------------------- | --------------------------- |
| 指定高优、普通主班、低优主班 | 普通替班、未排班空闲者 | 无额外门槛                  |
| 分床中的宿舍休息候补         | 普通替班               | 沿用候补下班条件            |
| 宿舍休息候补、普通替班       | 未排班空闲干员         | 不高于 22，且有有效心情数据 |
| 未排班空闲干员               | 不接管仍在恢复的其他人 | —                           |

候补及以上层级一旦实际入住动态床位，不能被其他休息候选人踢出；更高层级只会影响候选排序和宿舍床位重排。同级仍在恢复的干员也不互踢。普通分床先用空位，再接管允许接管的层级最低、同级心情最高的普通替班或空闲占位者；本轮已预留但尚未执行的床位不会重复分配。整组分床先完整预留，失败时不留下部分分配。

候补当前心情低于急救线（排班心情阈值 × Mower 全局急救阈值）时，本轮休息周期临时升级为低优主班：不能无床待命，并按低优主班参与分床。入住后即使心情恢复越过急救线也不降级，实际回到原工作位后才恢复候补身份。

“无额外门槛”指接管权限，不取消工作下班阈值、整组替班齐备等前置条件。

测试宿舍逻辑开启时，待命候补会在可用动态床位出现后自动补床；生成补床任务时不改写原有回班时间，执行后根据实际读取的恢复时间重新计算回班。候补的适用范围与限制见 [宿舍休息候补干员](group-resting-capacity.md)。

## 新入住者与单回位

工作组下班和不养闲人补床共用单回位分配：先确保新入住者已有床位，再按宿舍配置顺序比较每房首个动态位。新入住者的宿舍层级更高，或同级但当前心情更低时，与该单回目标交换床位；同级同心情不交换。原目标继续按顺序竞争后面的单回位，最后被替换者使用新入住者腾出的床位，所有已获床位的干员继续休息。

例如宿舍 1 的单回目标 A 是普通主班，宿舍 2 的单回目标 B 是低优主班，新入住者 C 在显式高优名单中，最初分到宿舍 2 的普通床位。重排后 C 获得宿舍 1 单回，A 获得宿舍 2 单回，B 移到 C 原获分配的普通床位，不会被踢回工作岗位。

分配完成后沿用已有的单回进驻流程：先确认新目标的入驻顺序，再恢复完整宿舍阵容，补读恢复倒计时并重建派生回班。生成计划不会提前修改真实位置或单回标记。其他任务已预留资源的房间不参与本轮单回交换；副表关闭或固定成员占用的位置也不参与。

没有新入住者时，不因已有入住者的心情顺序变化反复搬床。已有入住者的普通迁移不视为新入住；新入住者已取得较前宿舍的单回位时，不再为后面宿舍搬动。上下班候选仍沿用心情余量排序，以上规则只决定宿舍内如何恢复。

## 动态床位与房间顺序

“宿舍优先级排序”属于排班配置，主表和每张副表分别保存宿舍 1、2、3、4 的房间顺序，默认 1→2→3→4。同一房间内按物理床位顺序排列。副表生效时使用该副表的顺序；多张副表同时生效时，排在后面的生效副表覆盖前面的顺序；退出副表后恢复主表顺序。

开启测试逻辑并重新载入配置时，Mower 设置中的旧全局床位顺序会复制到尚无独立字段的排班，并按每个房间首次出现的位置折叠为房间顺序；缺失房间按 1→4 补齐。全局值仍保留，关闭测试逻辑后可继续使用。动态床位集合来自最终合并后的当前排班，因此副表可以增加或减少 `Free`，不会再因床位数量变化要求手工补齐排序。

固定宿舍成员回班或副表减少床位时，所有仍在恢复的动态床位入住者会重新经历一次层级和心情排序。能迁移者继续休息，容量不足时才让排序最低者离开，避免只因原床位关闭而损失恢复时间。

## 加工干员

测试逻辑开启时，加工名单、加工配置和手动备份不改变宿舍休息层级。加工干员仍按当前生效排班中的身份定级：主班、低优主班、候补或普通替班保留对应身份；未写入排班的加工干员自然属于第 6 级空闲干员。测试逻辑关闭时，自动加工页面恢复显示稳定版「低优先休息」设置。

## 宿舍不养闲人

开启后读取动态 `Free` 床位的恢复倒计时。存在可用的未满心情候选时，按上述层级和心情顺序替换已经满心情或倒计时结束的占位者，也可以填补空动态床位。候补及以上的入住保护只覆盖尚未休息完成的阶段；休息完成后仍沿用“不养闲人”的原有腾床逻辑。固定宿舍岗位不清除。

当前床位的干员状态决定是否可以释放，不再受干员字典最后一个对象或插入顺序影响。候选排除黑名单、零心情工作、在岗、未知心情及任务已预订的人员；已预订的床位不重复排任务。没有适合的候选时不为了腾床反复安排满心情干员。执行时机仍受现有任务队列及任务合并间隔影响。
