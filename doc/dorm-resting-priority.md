# 宿舍休息排序与床位接管

本页描述 Mower 设置中开启「测试宿舍逻辑」后的行为。该开关位于「宿舍不养闲人」下方并默认关闭；关闭时继续使用 alpha 稳定版的全局床位排序、四级休息排序、加工干员最低优先设置和原版不养闲人。

休息候选和宿舍床位重排共用以下层级，由高到低排列：

1. 「干员休息优先级」名单中显式指定的高优干员。
2. 普通主班。
3. 「宿舍低优先级干员」。
4. 「宿舍休息候补干员」。
5. 普通替班，包括训练室协助位。
6. 未写入当前生效排班的其他空闲干员，包括加工干员。

普通替班以当前生效主表、副表的替班名单识别，菲亚梅塔的充能名单不作为普通替班名单。零心情工作配置和宿舍黑名单属于候选排除条件，不是最低层级；实际心情为 0 的普通干员仍可休息。宿舍常驻和固定岗位上的宿舍替班不参与动态床位竞争。

每一级按有效的**当前绝对心情**从小到大排列，未知心情排在同级最后，相同心情保留原顺序。显式高优名单内部也比较心情，不再用填写顺序区分先后。工作心情阈值、用尽下班、心情下限和菲亚梅塔充能的判定仍由各自规则处理，排序不会强行中断加工或专精。

## 接管规则

| 申请者                       | 可接管的正在休息者     | 申请者心情门槛              |
| ---------------------------- | ---------------------- | --------------------------- |
| 指定高优、普通主班、低优主班 | 普通替班、未排班空闲者 | 无额外门槛                  |
| 随组分床的宿舍休息候补       | 普通替班               | 沿用随组下班条件            |
| 宿舍休息候补、普通替班       | 未排班空闲干员         | 不高于 22，且有有效心情数据 |
| 未排班空闲干员               | 不接管仍在恢复的其他人 | —                           |

候补及以上层级一旦实际入住动态床位，不能被其他休息候选人踢出；更高层级只会影响候选排序和宿舍床位重排。同级仍在恢复的干员也不互踢。普通分床先用空位，再接管允许接管的层级最低、同级心情最高的普通替班或空闲占位者；本轮已预留但尚未执行的床位不会重复分配。整组分床先完整预留，失败时不留下部分分配。

“无额外门槛”指接管权限，不取消工作下班阈值、整组替班齐备等前置条件。

待命不会自动补床。候补的适用范围与限制见 [宿舍休息候补干员](group-resting-capacity.md)。

## 动态床位顺序

“宿舍优先级排序”属于排班配置，主表和每张副表分别保存一份完整顺序。副表生效时使用该副表的顺序；多张副表同时生效时，排在后面的生效副表覆盖前面的顺序；退出副表后恢复主表顺序。某张表留空表示该表使用默认床位顺序，不继承其他表。

开启测试逻辑并重新载入配置时，Mower 设置中的全局顺序会复制到主表及所有尚无独立字段的副表；全局值仍保留，关闭测试逻辑后可继续使用。动态床位集合变化后，手动顺序必须与当前所有动态床位完全一致，否则排班验证会提示清除或修正顺序。

## 加工干员

测试逻辑开启时，加工名单、加工配置和手动备份不改变宿舍休息层级。加工干员仍按当前生效排班中的身份定级：主班、低优主班、候补或普通替班保留对应身份；未写入排班的加工干员自然属于第 6 级空闲干员。测试逻辑关闭时，自动加工页面恢复显示稳定版「低优先休息」设置。

## 宿舍不养闲人

开启后读取动态 `Free` 床位的恢复倒计时。存在可用的未满心情候选时，按上述层级和心情顺序替换已经满心情或倒计时结束的占位者，也可以填补空动态床位。候补及以上的入住保护只覆盖尚未休息完成的阶段；休息完成后仍沿用“不养闲人”的原有腾床逻辑。固定宿舍岗位不清除。

当前床位的干员状态决定是否可以释放，不再受干员字典最后一个对象或插入顺序影响。候选排除黑名单、零心情工作、在岗、未知心情及任务已预订的人员；已预订的床位不重复排任务。没有适合的候选时不为了腾床反复安排满心情干员。执行时机仍受现有任务队列及任务合并间隔影响。
