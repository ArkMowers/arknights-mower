# 宿舍休息排序与床位接管

休息候选和宿舍床位重排共用以下层级，由高到低排列：

1. 「干员休息优先级」名单中显式指定的高优干员。
2. 普通主班。
3. 「宿舍低优先级干员」。
4. 「宿舍休息候补干员」。
5. 普通替班，包括训练室协助位。
6. 未写入当前生效排班的其他空闲干员，包括加工干员。

普通替班以当前生效主表、副表的替班名单识别，菲亚梅塔的充能名单不作为普通替班名单。零心情工作配置和宿舍黑名单属于候选排除条件，不是最低层级；实际心情为 0 的普通干员仍可休息。宿舍常驻和固定岗位上的宿舍替班不参与动态床位竞争。

每一级按有效的**当前绝对心情**从小到大排列，未知心情排在同级最后，相同心情保留原顺序。显式高优名单内部也比较心情，不再用填写顺序区分先后。工作心情阈值、用尽下班、心情下限和菲亚梅塔充能的判定仍由各自规则处理，排序不会强行中断加工或专精。

## 接管规则

| 申请者                       | 可接管的正在休息者                   | 申请者心情门槛              |
| ---------------------------- | ------------------------------------ | --------------------------- |
| 指定高优、普通主班、低优主班 | 严格低于自己的层级                   | 无额外门槛                  |
| 随组分床的宿舍休息候补       | 普通替班                             | 沿用随组下班条件            |
| 宿舍休息候补、普通替班       | 未排班空闲干员及被加工开关降级的干员 | 不高于 22，且有有效心情数据 |
| 未排班空闲干员               | 不接管仍在恢复的其他人员             | —                           |

同级仍在恢复的干员不互踢。先用空位或已完成休息的床位，再接管层级最低、同级心情最高的占位者；本轮已预留但尚未执行的床位不会重复分配。整组分床先完整预留，失败时不留下部分分配。

“无额外门槛”指接管权限，不取消工作下班阈值、整组替班齐备等前置条件。

候补失去床位后，如果同组高优仍在恢复，则撤下待命，保留原有整组回班任务。必须有床的主班失去床位时，显式安排本人及绑组成员提前回班，并撤销对应的旧回班、释放床位任务，避免之后清掉新占位者。无组成员只恢复本人；主班床位被接管可能使其所在组提前结束休息。

待命不会自动补床。候补的适用范围与限制见 [宿舍休息候补干员](group-resting-capacity.md)。

## 加工低优开关

保留 `workshop_low_priority_rest` 开关。开启时，加工名单、加工配置和手动备份中的干员额外降到第 6 级，即使其被配置为主班或普通替班；显式指定高优名单仍优先，黑名单及零心情工作配置仍排除。关闭后按排班身份定级，未写入排班的加工干员仍属于第 6 级。

## 宿舍不养闲人

开启后读取动态 `Free` 床位的恢复倒计时。存在可用的未满心情候选时，按上述层级和心情顺序替换已经恢复完成的普通占位者，也可以填补空动态床位。主班通过自己的轮休回班任务腾床，固定宿舍岗位不清除。

当前床位的干员状态决定是否可以释放，不再受干员字典最后一个对象或插入顺序影响。候选排除黑名单、零心情工作、在岗、未知心情及任务已预订的人员；已预订的床位不重复排任务。没有适合的候选时不为了腾床反复安排满心情干员。执行时机仍受现有任务队列及任务合并间隔影响。
