# 加工站干员设置

打开设置时读取已同步的 BOX，按干员实际精英阶段、等级及技能升级链筛选已解锁的加工站技能。尚未改过的出厂名单自动替换为个人名单；已有自选名单保留。「恢复默认」改为「一键设置」，旁边可填写副产品概率加成下限，默认 80%，以 `workshop_min_bonus` 保存到用户配置。点击后填入所有达到该下限的可用干员。门槛高于 80% 时，仍保留已解锁 80% 加成的蚀清用于 T4，技巧概要按 80% 门槛筛选；低于 80% 时技巧概要仍沿用用户填写的门槛。这些例外继续要求持有、技能解锁和排班允许，其他材料干员仍使用填写的门槛，不影响实际合成按用户配置执行。设置保持多选。点击一键设置时先调用现有森空岛干员同步接口，等待新 BOX 写入后再读取加工站候选；同步失败、未配置账号、未匹配到所选服务器或缺少资源规则时提示原因并保留现有名单，不使用旧 BOX 继续覆盖。仅打开设置仍读取已有 BOX。

BOX 有效性在同步写入和一键设置名单读取两处统一校验：缺少 `data.characters`、空数组、错误的数据类型或无效干员记录均提示重新同步，不清空原名单，也不以空 BOX 覆盖之前的文件。有效且非空的 BOX 没有符合条件的加工干员时，仍可正常返回并应用空候选。缓存按路径、修改时间和文件大小复用，校验不增加游戏读取或网络请求。

针对每种配方计算固定副产品概率加成，保留全部达到所设下限的干员，不只保留最高者。材料系列、指定材料及配方原始消耗条件分别匹配；通用加成与已解锁的条件加成相加，同组技能升级不重复叠加。材料分工与概率下限分别判断，不因尚未解锁的后续专属技能额外要求 80%；例如门槛为 75% 时未精英化或精一缇缇可填入 T5，门槛为 50% 时未精英化休谟斯可填入非 T5（仅 T3），均只计当前技能的实际加成。宿舍、情报储备等动态加成不预设已满足。心情消耗减免不计入概率；对于缇缇这种同时具有 80% 通用加成和指定配方减耗的干员，按减耗适用范围安排分工。设置内可展开「值得培养的干员」，按全游戏干员技能完成培养后的效果展示，不受持有、当前解锁进度、排班、所选名单或一键设置下限影响。展示九色鹿、蚀清，以及材料加成至少 90% 或技巧概要加成至少 80% 的干员，特殊材料适用相同门槛。培养参考不应用执行时的跨分类互斥或专属材料独占，分别列出每个干员适用的范围；休谟斯的页面说明概括为「仅合成 T3 材料」。未同步或 BOX 无效时仍可通过独立只读接口查看培养推荐，不提供可应用的默认名单。有效 BOX 下仅对未持有的推荐干员标注「未持有」；已持有但技能未解锁或被排班占用的干员不加标识，BOX 缺失或无效时不猜测持有状态。80% 材料干员仍可按一键设置阈值填入，只是不出现在这份展示名单中。

当前资源中的固定特殊加成如下；一键设置仍需满足持有、技能解锁和排班条件。百分比均为副产品概率加成，而非最终出货概率。

| 干员 | 解锁阶段 | 匹配范围 | 加成 |
| --- | --- | --- | --- |
| 贾维 | 精二 | 装置系列 | 90% |
| 奥斯塔 | 精二 | 聚酸酯系列 | 90% |
| 泥岩、谬因 | 精二 | 源岩系列 | 90% |
| 熔泉 | 精二 | 异铁系列 | 90% |
| 号角 | 精二 | 仅炽合金块 | 100% |
| 维荻 | 精一 | 酮凝集系列（含酮阵列） | 80% |
| 特克诺 | 精二 | 晶体系列 | 80% |
| 折桠 | 精二 | 仅异铁组 | 90% |
| 休谟斯 | 精一 | 原始心情消耗为 2 的精英材料 | 50% + 40% = 90% |
| 缇缇 | 精二 | T5，原始消耗为 8 的配方减为 4 | 80% |

休谟斯匹配全新装置、酮凝集组、异铁组、聚酸酯组、糖组、固源岩组；原始消耗为 1、4、8 的配方和技巧概要不在其自动分工内。范围判断使用配方原始消耗，不使用被技能减免后的消耗。

年的高概率加成保留给 T5：一键设置、培养参考和生成合成配置时，只将年用于 T5 材料。非 T5 材料从其他可用干员中比较加成；没有其他候选时留空，不让年回填。旧名单即使在非 T5 或技巧概要分类选择了年，自动生成配置时也会跳过这些分配。

一键设置中，80% 加成干员允许跨分类：空爆可同时填入非 T5 和 T5，凯尔希·思衡托可填入三类，特克诺可同时负责晶体电路与晶体电子单元。材料条件仍要匹配，所以缇缇只分配 T5。其他干员继续按 T5、技巧概要、非 T5 的顺序分配到一个分类；每个分类均可填写多位干员。

九色鹿、蚀清的精英材料合成仅限 T4，莱伊排除 T4；T4 以配方原始消耗为 4 判断，不受减耗技能影响。这些范围同时约束自动名单、配置生成、已有配置的任务派发和实际加工入口，旧的错误分类选择和已排队任务也不能绕过。读取时过滤副本，不改写用户保存的库存上下限。

一键设置名单、生成的配置及实际任务派发中，九色鹿第一、蚀清第二，其余按副产品概率加成降序排列。同加成时优先有已解锁宿舍技能的干员，无论宿舍技能是自回还是帮助他人；仍未解锁的技能不参与优先级。当前 80% 材料干员中优先蜜莓，T5 其次为缇缇；80% 技巧概要干员中子月、赫拉格优先于无宿舍技能的干员。宿舍优先级不超过更高概率加成。现有加工站心情门槛不变，优先干员不满足原有使用条件时可由后续候选执行。派发会重新排序已有配置，不要求用户重建名单才能生效。

队列中相邻且已到执行时间的「加工材料」任务会连续执行：一位干员加工结束后直接切换下一位，整批结束时统一恢复加工站原驻员和借调干员的原位置，同宿舍多位干员一起归位。每次交接都会重新检查队列、配置版本和心情；遇到其他类型任务、带排班操作的任务或尚未到执行时间的任务时结束本批，并遵守专精换人保护。宿舍释放触发的加工仍单独处理。加工站原本无人时，沿用原有行为，以首位实际入驻的加工干员作为最终留驻干员。

排班排除仅用于一键设置：主排班及全部备用排班中的主力和替换干员，只要出现在宿舍、加工站以外的任何设施就跳过，包括训练室、中枢和活动室。仅在宿舍或加工站出现时允许填入；同时在其他设施出现时仍跳过。手动下拉保留全部干员；自动合成配置及实际派发使用用户设定的名单，不因排班占用再次删除干员。培养推荐也不受排班影响。

一键设置九色鹿只需持有，不要求精二，仍受同样的排班过滤。推荐条目仅显示名字，界面保留原有垫刀材料提示。实际使用沿用已有垫刀流程，碳素、碳素组、家具零件_碳素组只分配给九色鹿。

生成合成配置时按所选干员对每种材料的加成分配任务，达到所设下限的干员和匹配的专属干员均保留，手动选择的较低加成干员沿用并列最高的分配方式，九色鹿、蚀清作为 T4 优先候选保留。专属干员只分配符合其条件的材料；没有其他候选、全员对某材料均为零加成或缺少 BOX／外置资源规则时，也不会把无关材料分配给已知专属干员。用户可手动增删任意干员。多个分类选择同一干员时合并其任务，避免执行器只读取第一条配置而漏掉其他分类。

若某材料的专属概率加成达到该材料候选中的最高值，则普通候选仅保留对应专属干员，同种材料的多个专属干员可共同保留，并按加成排序。九色鹿、蚀清是明确的 T4 优先例外，仍可先于对应材料专属干员使用；其他通用干员继续排除。例如异铁组可分配给熔泉、折桠、休谟斯，不再分配给通用干员。若通用干员加成更高，则保留其优先权：年 100% 仍优先于特克诺 80% 合成晶体电子单元。缇缇只有减耗条件，不能因此独占 T5；蜜莓 80% 在她之前。专属干员未选入、未拥有或技能未解锁时，不触发材料独占。

除原有 T4、T5、技巧概要配置外，额外为已拥有、已解锁的所选专属干员补入对应低阶材料，避免折桠、休谟斯选入后没有任务。仅核算下一待专精技能的低阶材料直接需求及缺少 T4 的配方需求，按配方实际数量累计并扣除已有 T4，库存上限为所需数量。补入的低阶任务不分配给通用干员或九色鹿；缺少 BOX／规则时不新增低阶任务。其他材料库存上下限保持原计算。

添加训练计划时，若被训练干员出现在三个加工分类的已选名单或已启用的合成配置中，提示专精可能影响合成，仍允许添加。单项添加、批量添加、计划草稿和专精确认弹窗共用此检查。仅作为推荐展示、尚未选中的干员不触发警告；已停用且未在分类名单中选择的配置也不触发。占用名单使用响应式集合，与空闲／非空闲过滤共用，变更选人后自动更新。

规则由 `workshop_rules.compile_workshop_data` 在资源生成时写入 `skill_data.json.workshop`（version=1）。宿舍技能以 `kind=dormitory` 保留在原技能升级链中，按 BOX 精英阶段和等级解锁；不将只有宿舍技能的干员加入加工站候选。兼容字段 `recipe_ingredients` 直接从游戏基建表保存 39 种精英材料配方的原料数量；计划需求优先使用该字段，旧资源回退到已有 `composite`，不依赖第三方配方表是否随生成环境提供。推荐仅在打开设置、一键设置或生成加工配置时读取缓存数据；一键设置额外同步一次森空岛数据，加载期间禁用按钮以避免重复请求。实际加工入口仅增加材料范围过滤，不增加游戏扫描或专精心情识别。

自动合成配置按钮与仓库扫描后的更新统一读取 DB 计划，按优先级、计划 ID 的队列顺序，跳过 BOX 已专三的条目。没有正在训练的技能时仅准备队首技能的完整剩余材料链；仅在计划状态为 training 且倒计时未到期时，允许提前准备紧接着的一个 idle 技能，不汇总更后面的技能。安排中、待收取、倒计时缺失或过期都不开放提前准备。保留现有整条材料链齐备才自动开训的判断；未改为逐档补料续训。前端草稿选择为空或尚未刷新不再导致回退为全材料囤货；没有待专精计划或关闭自动专精时保留手动合成配置。

按钮生成加工任务时取消首个任务的两分钟等待和干员之间的十分钟间隔，首个任务立即排队，后续最短间隔两秒。后端根据最新任务队列避开已有任务的两秒窗口，覆盖原有小于 1.5 秒视为同时间的冲突判定；新增加工任务会唤醒调度器；等待返回后重新排序并选择任务，实际派发前再次确认任务仍在队列且已到期，避免提前执行睡前选中的换班任务。空闲时由仓库库存触发的加工任务使用同一时间分配函数。任务仍串行执行，前一任务完成后可紧接后续已到时间的任务，沿用现有跑单避让。

提前准备时预留当前训练技能后续等级的材料；已开始的这一档已支付，不重复预留。相同成品的库存先扣除预留数量再计算下一技能的缺口。现有执行器使用批量加工，因此涉及预留原料的配方先跳过，待当前技能不再占用这些材料后再生成，避免一次批量加工消耗掉续练材料；缺少当前技能材料数据时不提前加工。

维护入口与 API 契约同步列在 [专精约束文档](mastery-constraints.md) 的模块地图、推荐/自动排程及 HTTP API 清单中。加工站回归按 BOX、规则、排班、推荐、分配、材料、优先级和执行范围分文件；`pytest.ini` 自动发现这些测试及同步、备料测试，不需要在 CI 手工维护文件列表。

## 加工数量与库存

所有干员复用九色鹿原有的限次加号操作，不再直接点击最大数量。每批次数同时受成品库存上限、单次产出数量和各原料库存下限约束；九色鹿额外受因果垫刀次数约束。默认龙门币充足，不据此限制次数或更新龙门币库存。一次加工多件的芯片、家具零件按实际产出数量计算，家具零件的各条配方共用真实家具零件库存。

加工次数按默认 1 次加上加号点击次数计算，确认加工完成后按配方原子更新共享库存并扣除对应原料。不识别或计算副产物，留给下一次仓库扫描校准；因此同名副产物可能使实际库存略高于设置上限。批量同时受现有心情值限制，精英材料的基础消耗为 T2＝1、T3＝2、T4＝4、T5＝8，按已解锁技能应用固定心情减免、恒定消耗和额外消耗。未计入依赖副产物或宿舍状态的返还／减免，心情预算保守处理，不新增心情或次数识别。入驻前及原有入驻读取后，已知心情不足 1 点的干员立即跳过；候选配方同时按剩余心情与技能修正后的单次消耗过滤，无可负担配方时结束，不逐个打开配方扫描。每批完成后先扣除心情再筛选材料，后续干员读取更新后的库存，已达上限的材料不再加工。未能确认加工完成时不猜测产量，暂停相关材料的加工并告警，重新读取仓库后恢复。

已加工材料的更新持久化到库存数据库；反复读取仓库页面或旧森空岛缓存不会覆盖本轮计数。只有更新的游戏内仓库扫描才重新校准这些材料，读取同一份扫描结果时也不会回退到旧缓存。

`workshop_formula.json` 新增 `costs`、`output_name`、`output_count`，由现有资源生成脚本从游戏基建表提取。`skill_data.json.workshop.mood_operators` 独立保存心情技能升级链，不影响推荐名单。旧资源缺少字段时回退到内置数据，未知配方跳过；BOX 不完整时不假定减免技能已解锁。数量检查只读本地库存，沿用原有加工完成场景判断，不在每批后执行全仓扫描。

## 自动备份与恢复

「无缝合成材料设置」始终展示可编辑的手动表单，实际运行的自动配方不显示在表单中。首次读取时，用已有手动备份、旧版 `workshop_preset.json` 或当前手动配置初始化（空列表也有效）；旧预设只迁移一次，迁移本身不接管或覆盖当前运行配置。用户可随时增删、修改表单；未接管时编辑同步用于日常加工，自动专精接管期间只保存手动表单，结束后恢复用户最后保存的版本。重复扫描和自动生成不会覆盖手动表单。页面移除保存和还原按钮，标题及导航改为「自动专精」。

仓库扫描确认整个训练队列的剩余材料已齐备后，自动恢复手动表单；全部计划结束、删除最后一个计划或关闭自动专精时也恢复。生成或开始加工任务前也核对已同步 BOX：只收尾明确已达目标的 idle 计划，包括重复条目；正在安排、训练、待收取的计划不据此收尾，缺失或无效的技能等级不作完成依据。已无待执行计划时恢复手动表单并使旧自动加工任务失效；恢复后的手动加工仍按用户配置运行。核对复用本地 BOX 缓存，不额外发起网络读取。只有实际接管过才恢复，旧预设存在不等于正在接管。暂时不能提前准备下一技能、缺少 BOX／技能材料数据、原料不足或加工干员心情不足，均不算材料准备完成。多个技能使用相同材料时累计核算；进行中且倒计时有效的训练已支付当前档材料，只核算后续档。合成进度以仓库数据确认为准，不因某一条加工任务返回就提前恢复。

旧预设无法解析、编码损坏、结构不合法或暂时不可读时，保留旧文件和当前运行配置，不初始化备份、不标记迁移完成。`GET/POST /conf` 正常处理其他设置，只返回加工设置范围内的 `workshop_preset_warning`。表单暂时展示现有手动配置，自动接管暂停；用户修复旧文件后可重新迁移，或通过实际编辑手动表单结束迁移并采用新方案。普通自动保存不视为用户主动替换坏预设；修复后导入的表单会更新手动版本，防止旧页面回写覆盖它。已有独立手动表单时不再读取旧文件。

手动表单持续保存于 `workshop_manual_backup`，`workshop_auto_active` 独立记录接管状态；兼容旧版非空／空备份代表正在接管的配置。`workshop_manual_revision` 只随用户编辑变化，`workshop_generation` 随运行配置或接管状态变化，自动生成条目标为 `source=mastery`。这些状态与配置一起原子保存。`GET /conf` 返回独立 `workshop_manual_settings`，前端以此编辑，并在 `POST /conf` 中携带 `workshop_manual_settings_revision`；旧页面冲突时保留服务端表单，响应返回最新表单和冲突标志。自动接管或恢复不会让未提交的手动编辑失效；前端串行发送最新草稿及已确认的版本，不用较早响应覆盖后续编辑。旧 `/workshop-preset` 保留只读兼容。

自动任务携带生成时的运行版本。所有加工入口在取得配方快照时都会绑定当前运行版本，包括宿舍释放转加工及无队列任务的直接调用；过期的排队任务不能通过重新取快照更新版本。执行开始时在配置锁内取得深拷贝快照，库存同步后、加工循环和实际提交加工前再次校验版本；最后一次校验与加工按钮提交使用同一把锁，其余读屏和导航不持锁。执行途中关闭自动专精、删除最后一个计划或恢复配置时，旧任务不能转而加工手动配方。

## 加工干员的宿舍优先级

「加工站干员设置」的一键设置右侧提供「低优先休息」开关，以 `workshop_low_priority_rest` 保存，默认开启以兼容已有配置。开关统一控制床位分配、休息顺序和实际选人；关闭后这些路径恢复原有宿舍优先级，不改变加工名单或合成配置。

三个加工分类、加工配置及接管期间的手动备份中的干员，宿舍恢复顺序低于普通替换干员，只使用其他需要休息者安排后的剩余床位。它们正在使用的床位可由普通主力和需要休息的替班干员接管，但普通替班干员心情大于 22 时不能踢出正在休息的加工干员。加工干员之间不互踢，也不会踢出正在休息的普通替换干员。规则随加工名单变更立即生效，不增加心情识别或网络读取。

「加工站干员设置」内的「九色鹿垫刀素材设置」独立保存为 `workshop_deer_fodder`。默认将碳素、碳素组、家具零件_碳素组合并在一个条目中，共用子材料库存下限 0、成品库存上限 9999；可新增多组素材并分别设限。清空列表表示不添加垫刀素材，不回退默认值。自动专精生成配置及旧默认配置生成器共用此设置，备份和恢复手动加工配置不会覆盖它。候选来自加工配方中的基建材料；未知／已移除的配方和精英暴击材料不会作为垫刀素材插入。
