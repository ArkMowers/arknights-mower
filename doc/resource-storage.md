# 共享资源存储与实例加载

完整资源包安装到共享的 `@app/resources`。软件自带资源保留在 internal，作为内置基线。源码部署的运行期资源目录已加入 Git 忽略规则；macOS 资源写在用户数据目录，不改动已签名的 `.app`。

| 部署方式 | 默认持久目录 |
| --- | --- |
| 源码 | 仓库根目录下的 `resources/` |
| Windows / Linux 独立包 | 程序目录下的 `resources/` |
| macOS 独立包 | `~/Library/Application Support/arknights_mower/resources/` |
| 指定 `MOWER_DATA_DIR` | 该目录下的 `resources/` |

这些路径显式使用 `space=""`，同一数据根目录的多开实例共享一份文件。首次启动会检查原共享 `tmp/resource` 和当前实例旧资源目录，将可用资源复制到持久目录，并保留旧目录供旧程序恢复使用。已有持久索引时不会重复迁移。

## 安装与任务边界

安装程序先在 `.staging-<进程号>` 解压完整资源包，确认版本清单、声明的兼容范围、必需文件及路径。验证完成后，将文件发布到不可变的 `packages/<包摘要>/`，最后原子更新 `index.json`。安装和索引更新使用跨进程文件锁。

每个实例固定使用一个完整版本，包括 JSON、识别模型和网页图片。发布新版本不会覆盖旧版本文件，也不需要在实例之间复制资源。正在执行的任务继续使用原版本：

- 调度器在下一轮任务开始前和任务间休眠时主动检查，刷新本进程的缓存。
- 停止任务的实例由后台检查器加载新版本。
- 任务启动与后台刷新共用进程锁，后台线程不会凭 `sleeping` 状态在任务运行中切换缓存。
- 加载失败时恢复原资源和缓存，并从共享索引撤回失败版本。

旧版本目录暂时保留，供其他仍在执行任务的实例读取，也用于软件回滚后的版本选择。安装失败产生的未引用目录同样不会参与选择；需要释放空间时，应在全部实例退出后清理无用版本。轻量热更包与远端版本查询缓存继续使用各自现有路径。

## 软件更新后的整包选择

每次启动或资源索引改变后，在内置资源和索引中的完整外部包之间选择有效版本：

1. 外部包必须包含当前资源格式要求的全部数据、模型和图片目录。
2. `schema_version` 缺省为 `1`；不支持的格式版本不会加载。
3. 可选的 `mower_version` 使用版本范围，例如 `">=4.1.6a1,<5"`。不满足范围的外部包不会加载；缺省时按现有资源格式处理。
4. 先比较 `res_version` 日期。同日且内容哈希不同时，仅当双方都有可比较的 `last_updated` 才判断先后；哈希本身不能用于排序。无法确认外部包更新时保留内置资源。
5. 选中外部版本后，受资源包管理的文件全部从该版本读取，不逐文件混用内置资源；程序自身的其他文件仍从 internal 读取。

因此，新版软件自带资源更新时，旧外部资源不会继续覆盖它。兼容的较新外部资源可以保留并继续使用。完整程序更新只替换软件文件：Windows/Linux 保留 `resources/`，macOS 替换 `.app` 时用户数据目录也不会被覆盖。

兼容范围是资源发布方提供的声明，不能替代对未来程序版本的实际兼容测试。资源生成流程尚未声明版本范围时，客户端不会自行猜测范围。

## macOS 签名

资源安装不写入 `.app/Contents`，因此不会因更新资源而改变程序的代码签名。DMG 软件更新则完整复制新 `.app`，并在停止旧实例之前执行签名完整性检查。Developer ID 信任与 Apple 公证是另外的要求，详见[软件更新说明](software-update.md#macos-签名与系统信任)。
