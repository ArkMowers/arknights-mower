# 配置导出与导入

入口位于 **Mower 设置 → 数据与维护 → 档案备份与恢复**，在「进程操作」板块上方。

点击「导出档案」会等待页面已有保存任务完成，再下载 ZIP 压缩包。压缩包直接包含当前实例的
`config/` 文件夹及配置原文件（包括注释），例如 `conf.yml`、`plan.json`、`rescue_plan.json`、`weekly_plans.yml`。
`plan.json` 包含主排班和所有备用排班；`state.json` 不导出。
`rescue_plan.json` 包含独立的救急主表和副表；导入旧备份时，程序自动迁移 `conf.yml` 中的救急排班。
`growth_plan.json` 保存养成目标，`workshop_preset.json` 保存旧版加工预设，均位于实例 `config/`。
启动时会从原 `tmp/` 路径迁移；新旧文件同时存在时，以 `config/` 为准。
ZIP 同时包含当前实例 `tmp/` 中的持久化数据：

- `data.db`：数据库中的全部数据表，包括专精计划、专精路线和历史记录。
- `cultivate.json`：库存及干员养成数据。
- `depotresult.csv`、`depotmerged.csv`：仓库识别结果与合并历史。
- `report.csv`、`skland.csv`：基建报表与森空岛记录。

不存在的数据文件不导出。数据库使用一致性快照，包含 WAL 中已提交的数据，
不直接复制正在使用的数据库文件或其辅助文件。

资源包、资源版本信息、更新文件、日志、其他 tmp 文件、实例外的共享设置、保全作业及浏览器偏好不在备份内。
不再支持旧版完整配置 JSON 备份。单独的排班 JSON 和排班图片仍可通过排班页面导入；
排班页面也可从 ZIP 中只读取 `config/plan.json`。

导入步骤：

1. 停止 Mower，等待更新任务结束。
2. 点击「导入档案」，选择包含 `config/` 文件夹的 ZIP（最大 16 MB，配置和数据解压后的合计大小也不得超过 16 MB）。
   必须包含 `conf.yml` 和有效的 `plan.json`；同时支持包含 `tmp/` 数据文件的新备份和仅含配置的旧 ZIP。
3. 确认覆盖当前配置。服务端先校验，再把现有配置备份到当前实例数据目录下的
   `config-backups/before-import-时间-标识.zip`，恢复备份同样包含现有 tmp 数据，
   随后恢复配置及备份内的数据文件；文件写入或数据库恢复失败会回滚。
4. 成功后自动刷新页面加载新配置，无需重启 Mower，此次刷新不会自动启动任务。
   刷新后的设置页显示成功提示及恢复备份路径；若刷新失败，可点击「重试刷新页面」。

提交前，页面暂停配置、正常排班和已加载的救急排班的自动保存，并等待已有保存完成。
导入成功后，当前档案的名称保持不变，配置版本更新；其他已打开的页面也需重新加载后才能保存。
若导入请求超时或响应丢失，页面继续暂停保存，并提供重新加载按钮，避免旧页面覆盖已导入的数据。

导入时保留当前运行进程中加载的管理页面端口、访问令牌、托盘设置，
以及本机的 `network.json`、`gui.yml`、`state.json`，即使 ZIP 包含这些文件也不会替换。
即使运行期间手动替换了磁盘上的 `conf.yml`，上述三项仍以运行中的值为准，确保当前管理入口不变。
网络访问、窗口尺寸、心情曲线偏好、日志布局和更新日志确认状态因此保持本机值；刷新保持原 URL。
旧 ZIP 的 `tmp/growth_plan.json` 和 `tmp/workshop_preset.json` 会导入实例 `config/`，
同包内已有 `config/` 版本时优先使用该版本；两处都没有时保留本机对应配置。
其余 `config/` 文件按备份恢复，备份中没有的本机文件会移除。旧调度缓存会清空，
下次启动按导入后的排班生成任务。备份内的 tmp 数据文件覆盖本机同名文件，
未包含的 tmp 数据文件保持不变；仅含配置的旧 ZIP 不覆盖现有数据表。
导入后清空数据库中的 `saved_state`，不沿用旧调度状态。
其他实例及未列入备份范围的数据不受影响。

如需撤销导入，可再次导入自动生成的恢复 ZIP。恢复备份同样不包含 `state.json`。
迁移到其他电脑后，请检查 MAA、ADB 和模拟器路径。
备份会保留账号、密码、访问令牌和 API 密钥，请妥善保管，不要公开分享。

设置页的「重启 Mower 进程」会暂停自动保存并等待已有保存完成，不再额外写入页面中的整份旧配置。
提交后保持暂停直到页面重新加载；明确被拒绝时恢复自动保存。若响应丢失、超时或重启失败，
保持暂停并提供刷新按钮，重新读取服务端配置后再编辑，避免旧页面继续覆盖配置。旧路径配置迁移失败时会明确报错并停止启动，
不会生成默认文件遮蔽原配置；请按错误中的路径检查权限或文件占用后重试。

配置目录本身及其内部、tmp 目录和列入备份的数据文件均不支持符号链接；
导出、导入前生成恢复备份时都会检查。
遇到这类本机目录问题会明确提示处理本机链接，不会把它报告成上传的 ZIP 损坏。
ZIP 最多包含 1024 个配置和数据条目（另可包含 `config/` 与 `tmp/` 根目录条目），路径必须兼容 Windows，
不接受设备名、大小写歧义、文件与目录冲突或目录穿越路径。排班主表名称仅支持 `plan1`。
损坏的 ZIP 或无法解码的排班图片会返回导入失败提示，并保持原配置。
