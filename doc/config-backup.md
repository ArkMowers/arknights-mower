# 配置导出与导入

入口位于 **全部设置 → 数据与维护 → 完整备份与恢复**。

点击「导出完整备份」会等待页面已有保存任务完成，再下载 ZIP 压缩包。压缩包包含当前实例的
`config/` 文件夹，例如 `conf.yml`、`plan.json`、`rescue_plan.json`、`weekly_plans.yml`。
导出省略账号、密码、访问令牌、API 密钥，以及本机的凭据文件和加密密钥。
`plan.json` 包含主排班和所有备用排班；`state.json` 不导出。
`rescue_plan.json` 包含独立的救急主表和副表；导入旧备份时，程序自动迁移 `conf.yml` 中的救急排班。
`growth_plan.json` 保存养成目标，`workshop_preset.json` 保存旧版加工预设，均位于实例 `config/`。
启动时会从原 `tmp/` 路径迁移；新旧文件同时存在时，以 `config/` 为准。
ZIP 同时包含当前实例 `tmp/` 中的持久化数据：

- `data.db`：数据库中的全部数据表，包括专精计划、专精路线和历史记录。
- `cultivate.json`：库存及干员养成数据。
- `depotresult.csv`、`depotmerged.csv`：仓库识别结果与合并历史。
- `report.csv`、`skland.csv`：基建报表与森空岛记录。

不存在的数据文件不导出。数据库使用一致性快照，包含 WAL 中已提交的数据，
不直接复制正在使用的数据库文件或其辅助文件。

资源包、资源版本信息、更新文件、日志、其他 tmp 文件、实例外的共享设置、保全作业及浏览器偏好不在备份内。
不再支持旧版完整配置 JSON 备份。单独的排班 JSON 和排班图片仍可通过排班页面导入；
排班页面也可从 ZIP 中只读取 `config/plan.json`。

导入步骤：

1. 停止 Mower，等待更新任务结束。
2. 点击「恢复当前配置」，选择包含 `config/` 文件夹的 ZIP。备份大小默认上限为 16 MiB，ZIP 和解压后的配置与数据合计大小都须在上限内。
   必须包含 `conf.yml` 和有效的 `plan.json`；同时支持包含 `tmp/` 数据文件的新备份和仅含配置的旧 ZIP。
3. 确认覆盖当前配置。服务端先校验，再把现有配置备份到当前实例数据目录下的
   `config-backups/before-import-时间-标识.zip`，恢复备份同样包含现有 tmp 数据，
   随后恢复配置及备份内的数据文件；文件写入或数据库恢复失败会回滚。
4. 成功后自动刷新页面加载新配置，无需重启 Mower，此次刷新不会自动启动任务。
   刷新后的设置页显示成功提示及恢复备份路径；若刷新失败，可点击「重试刷新页面」。

备份提示数据库超过上限时，可在 **运行日志 → 数据库管理** 查看数据库大小与空闲页大小。
先停止任务，再点击「整理数据库」，程序检查完整性并回收删除记录留下的空间，完成后显示整理前后的大小。
整理保留现有记录；失败时请按提示检查数据库占用、磁盘空间和目录权限后重试。
如需保留的数据仍超过上限，可在同一窗口调整「备份大小上限（MiB）」并保存，范围为 1 至 1024 MiB。
此设置同时用于完整备份、恢复前备份和档案导入导出；调大上限会增加内存占用。
设置仅用于当前实例，切换档案或恢复备份时保留。

提交前，页面暂停配置、正常排班和已加载的救急排班的自动保存，并等待已有保存完成。
导入成功后，当前档案的名称保持不变，配置版本更新；其他已打开的页面也需重新加载后才能保存。
若导入请求超时或响应丢失，页面继续暂停保存，并提供重新加载按钮，避免旧页面覆盖已导入的数据。

导入时保留当前运行进程中加载的管理页面端口、访问令牌、托盘设置，
以及本机的 `network.json`、`gui.yml`、`state.json`，即使 ZIP 包含这些文件也不会替换。
即使运行期间手动替换了磁盘上的 `conf.yml`，上述三项仍以运行中的值为准，确保当前管理入口不变。
网络访问、窗口尺寸、心情曲线偏好、日志布局和更新日志确认状态因此保持本机值；刷新保持原 URL。
旧 ZIP 的 `tmp/growth_plan.json` 和 `tmp/workshop_preset.json` 会导入实例 `config/`，
同包内已有 `config/` 版本时优先使用该版本；两处都没有时保留本机对应配置。
其余 `config/` 文件按备份恢复，备份中没有的本机文件会移除。旧调度缓存会清空，
下次启动按导入后的排班生成任务。备份内的 tmp 数据文件覆盖本机同名文件，
未包含的 tmp 数据文件保持不变；仅含配置的旧 ZIP 不覆盖现有数据表。
导入后清空数据库中的 `saved_state`，不沿用旧调度状态。
其他实例及未列入备份范围的数据不受影响。

如需撤销配置和数据的导入，可再次导入自动生成的恢复 ZIP。恢复备份省略 `state.json` 和凭据。
恢复脱敏后的完整备份会保留本机凭据。迁移到其他电脑后，可重新填写凭据或导入单独的口令凭据备份，
并检查 MAA、ADB 和模拟器路径。
从旧版导出的备份仍可能包含凭据，请妥善保管。

账号、密码和令牌仍在原设置页查看、修改和清空，保存时由后端加密。
程序升级后会直接迁移已有配置中的凭据，确认密文能读回后再移除原文，无需用户先创建环境变量文件。
本功能首次将已有明文凭据迁入加密存储，采用 X25519 与 ML-KEM-768 混合封装及对称加密。
程序首次初始化固定私钥，此后的保存复用该私钥，每次加密仍产生不同密文。读取本身不改文件，
保存无关设置不一定改写凭据，写入失败会恢复原文件。私钥保存在系统凭据服务或单独的受保护文件中。
加密文件和解密所需的密钥属于持久数据，不能当作缓存删除。密钥丢失或密文损坏时，
程序会报错并保留原文件，不会在正常读写时生成新密钥覆盖旧数据，也不会把访问令牌当成空值。
桌面程序启动失败时会打开凭据恢复页面，列出无法读取的凭据；确认重置后，程序保留排班、其他配置和数据，
将无法读取的旧密文另存，并准备可用的私钥。关闭恢复页面、重新启动 Mower 后，在原设置页重新填写凭据即可。
仍然能读取的凭据和可用私钥会保留。系统密钥服务被锁定时需先解锁；部署者指定的私钥文件不会被程序替换。
同一系统用户的多个实例可能共用私钥；原私钥丢失后，其他受影响实例也需要分别恢复凭据，排班不受影响。
如果需要找回旧凭据，仍需恢复原私钥及其系统保护，或使用此前做好的口令凭据备份。
普通配置 ZIP 不包含私钥，也不能恢复已丢失的私钥。
各平台的保存位置与保护方式见[配置备份子系统说明](../docs/subsystems/config-backup.md#configuration-credential-storage)。

### 可选的口令凭据备份

无需保管私钥也能迁移凭据：在 **完整备份与恢复 → 凭据备份与迁移（可选）** 中，
点击「导出凭据备份」，输入并确认至少 12 个字符的口令，再点击「加密并下载」。
文件扩展名为 `.mower-credentials`。请使用较长且不重复使用的口令，并把文件和口令分开保管；
程序不保存口令，忘记后无法解密。原私钥已经丢失时，不能再导出原来的凭据。

在新机器先恢复普通配置 ZIP，再停止 Mower 的任务，点击「导入凭据备份」，选择文件并输入原口令。
点击「解密并查看内容」后，页面只显示凭据类别、数量和将清空的项目数量，不显示凭据原文。
确认后，凭据会用新机器自动保管的私钥重新加密保存，页面刷新且不会自动开始任务。
其他已打开的旧页面需要重新加载后才能保存，避免旧值覆盖导入结果。
文件最大 4 MiB。口令错误、文件损坏或当前任务未停止时会拒绝导入。

凭据备份包含当前档案的邮箱、森空岛、AI、MAA、一图流凭据及共享 GitHub Token、备用 AI Key，
不包含其他档案、私钥、排班或普通设置。多个档案需分别导出；目标机的访问 Token 保持原样。
包内没有的凭据保留，明确为空的值会清空对应项。共享凭据变更会影响共用它们的其他实例。
更换一图流 Token 会清除原 Token 的同步记录，以便下次向新授权账号同步，其他设置保留。
导入前可另外导出现有凭据备份，以便自行恢复原值。

密钥丢失导致程序无法启动时，先在恢复入口重置不可读凭据，再正常启动并导入已有的口令凭据备份。
源码与无桌面环境可执行 `python -m arknights_mower.utils.credential_recovery` 打开独立恢复服务；
桌面启动器也支持 `--credential-recovery`，有桌面环境时会打开恢复窗口。
`python -m` 默认在终端显示临时入口，桌面启动器可加 `--headless` 强制使用终端方式。
恢复服务默认仅监听本机；多实例可加 `--instance` 并传入该实例的数据目录。
Docker 的停止服务与恢复启动方式见 [Docker 部署指南](../docs/cookbook/docker-deploy.md)。

设置页的「重启 Mower 进程」会暂停自动保存并等待已有保存完成，不再额外写入页面中的整份旧配置。
提交后保持暂停直到页面重新加载；明确被拒绝时恢复自动保存。若响应丢失、超时或重启失败，
保持暂停并提供刷新按钮，重新读取服务端配置后再编辑，避免旧页面继续覆盖配置。旧路径配置迁移失败时会明确报错并停止启动，
不会生成默认文件遮蔽原配置；请按错误中的路径检查权限或文件占用后重试。

配置目录本身及其内部、tmp 目录和列入备份的数据文件均不支持符号链接；
导出、导入前生成恢复备份时都会检查。
遇到这类本机目录问题会明确提示处理本机链接，不会把它报告成上传的 ZIP 损坏。
ZIP 最多包含 1024 个配置和数据条目（另可包含 `config/` 与 `tmp/` 根目录条目），路径必须兼容 Windows，
不接受设备名、大小写歧义、文件与目录冲突或目录穿越路径。排班主表名称仅支持 `plan1`。
损坏的 ZIP 或无法解码的排班图片会返回导入失败提示，并保持原配置。
