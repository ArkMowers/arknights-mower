# 低帧率适配

在「Mower 设置」中可开启或关闭「低帧率适配」。Android 默认开启，Windows、macOS、Linux 默认关闭。已有配置未包含此项时按运行平台补齐；手动选择后会保存，不会被平台默认值覆盖。

开启后，基建选人、排序和翻页会等待画面稳定，逐个重新定位目标，适合帧率低或画面反馈延迟的设备。该模式会增加等待和截图次数。关闭后使用单帧批量选人及原有快速翻页路径，流畅设备可保持关闭。

两种模式的无惯性滑动默认使用 #1050 的快速参数：主方向每 100px 用时 20ms，侧向偏移 100px。低帧率模式的基建和训练室翻页先保留两列重叠进行快速滑动；等待后确认整页仍未推进，才进行一次单列慢速复核。复核主方向每 100px 用时至少 80ms，且不少于 400ms；页面仍在移动或无法识别时交给原有恢复流程，不立即补滑。下一次翻页恢复快速参数，不记录设备级慢速状态。普通模式不新增截图或等待。

全局 `swipe_noinertia` 接口支持 `retry=True`，供其他场景在确认手势未生效后复用慢速参数；接口自身不判断成功、不自动重试。当前自动回退仅接入低帧率模式的基建和训练室翻页。400ms 是待实机验证的重试下限，不影响首次快速滑动；截图失败、到达列表末尾、惯性回弹与拖动不足不能统一视为需要延长拖动。

两种模式都会校验最终名单和顺序。搜索时，空白或尺寸异常的名字区域保留卡片位置、按未识别处理，无关卡片不会阻止选择已识别的目标；待确认名单中的空名字、缺人或顺序错误仍不能通过校验。没有翻页且目标卡片名字匹配时，不再重复切换职业筛选；但名字相同不能证明卡片已选中，多人名单仍按原流程清空重选，再刷新排序并校验。普通模式重选沿用零间隔批量点击。

两种模式切换职业时都会先确认 ALL 生效，再恢复目标职业，避免把切换前的高亮当成完成。ALL 已高亮时省略重复点击及对应等待，真正切换职业时仍确认生效；列表复位仍先切换到其他职业再恢复。普通模式收到反馈即继续，仅反馈迟到时短间隔轮询；侧栏开关等待上次点击完成，不重复点击切换。

配置键为 `low_frame_rate_mode`，布尔值。Android 默认值以宿主的 `MOWER_ANDROID=1` 或 Android 运行平台识别；从电脑浏览器访问手机上的 Mower 不影响默认值。开关不修改跑单前置延时、葛朗台缓冲或截图间隔。

稳定观察仍需要独立的新截图。取帧耗时计入原有 0.5 秒采样间隔：取帧达到 0.5 秒时不再额外等待，取帧较快时补足间隔；名字识别耗时不抵扣这段等待，避免慢识别后紧接着读取另一张尚未更新的画面。连接遮罩会清空连续稳定证据，失败和停止信号沿用现有处理。低帧率模式已确认排序变化并稳定后，不再追加一次固定动画等待。

确认选人、进房和订单导航按画面反馈推进。确认点击后不再叠加默认等待和额外等待；按钮仍清晰可见时先观察下一帧再重试，淡出残影不重复点击。真实训练及二次确认仍处理，持续未生效交回原恢复流程。进入订单页时先收起进驻面板，再打开订单入口并确认相应的加速按钮；进房和打开详情也先等已发出的点击反馈，保留次数上限及最终房间检查。Free 搜索需要 ALL 时直接切换，不先恢复原职业再切回 ALL。

每个房间的换班耗时统计仅写入后台 DEBUG 日志，不推送到前端运行日志。除了截图、识别、等待和点击，还单列 `enter_room`、`room_detail`、`confirm` 和 `order_navigation` 阶段；各阶段总耗时包含内部操作，不能直接相加。`confirm` 包含用户配置要求的跑单等待，分析时需要区分主动等待与页面处理时间。

固定等待的减少不等于整轮耗时的实测改善；截图链路、游戏反馈和网络仍会影响运行速度。
